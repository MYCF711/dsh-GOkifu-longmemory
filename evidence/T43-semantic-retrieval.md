# T43 · 语义联想检索试点（embedding 模型当联想器）

> 日期：2026-11-09 · 只读实验（**不改 src**）· 脚本 `tmp/embedding-download.py` / `tmp/embedding-experiment.py` · 原始结果 `tmp/embedding-out/results.json`
> 数据：`evidence/a2b-holdout.json`（118 题 / 403 对可匹配的 5 行渲染 × claim）· 模型：`sentence-transformers/paraphrase-multilingual-MiniLM-L12-v2`（多语言，384 维，~120 MB）

## 0 · 一句话结论

**语义检索没有比现有机械检索准。** 按 A2b 的 strict 标注：余弦相似度的 AUC **0.839**，现有的关键词重合（`overlap`）AUC **0.850**——基本打平、略输；按「从全库找 related 记忆」的口径：embedding top-5 命中率 **0.33**（全库）/ **0.57**（同 scope），而现在的 walk 是 **0.67**——明显更差。**不建议现在接入**（不替换 `hasRelevantClaim`，也不加兜底）。唯一有苗头的窄切片：机械 `overlap=0` 的 313 对里，余弦 AUC 0.751（`bigram<2` 的 191 对里 0.923），但只涉及 18 个 strict 正例（≈0.15/题），要单独做「渲染集」实验才值得接。

**结论（成本）**：CPU 能接受**离线建索引**（全库一次 14–23 s），但 **12 s 级冷加载 + ~1 GB RAM** 放进 `agent/pre-step` 热路径不划算；只能做后台/离线索引 + 每轮查询 ~6 ms。

## 2 · 实验设计（真实数据）

- 取 `evidence/a2b-holdout.json` 的 **118 题**；每题取 walk 实际渲染的 5 行 claim ⇒ 可匹配到 store 文本的 **403 对**（任务, claim）。
- 标签用 holdout 自己的两个口径：
  - `strict`（78 个正例）：`related` 且与信号有 ≥2 判别词或 ≥1 硬实体重合——**A2b 的严格命中口径**；
  - `related`（158 个正例）：claim.support 含该题的 episode。
- 两个预测器：
  - **语义**：`cos(model.encode(task), model.encode(claim))`；
  - **机械**：holdout 行里已有的 `overlap`（判别词重合数）与 `bigram`（二元组重合）。
- 另做**全库检索对照**（E2）：related 集 = support 含该题 episode 的 claim；比较 walk 的 top-5 与 embedding 全库 top-5 的 P@5/R@5/hit@5。

## 3 · E1：403 对上的判别力（A2b strict 标注）

| 预测器 | AUC（strict） |
|---|---|
| **语义余弦** | **0.8386** |
| 机械 `overlap`（现状） | **0.8503** |
| 机械 `bigram` | 0.7810 |

- 余弦在最佳阈值（0.6135）下：**P 0.797 / R 0.603 / F1 0.686**。
- 正例均余弦 0.617 vs 负例 0.292（能分开，但没那么干净）。
- 对 `related` 标签：余弦 AUC **0.4986（≈随机）**——因为 `related` 是「support 含该局」，语义相似度**根本看不到**这个信息（它不知道哪条 claim 来自哪一局）。这本身就是语义检索的边界：**它不是"证据归属"的判据**。
- 切片（机械盲区）：
  | 切片 | 对数 | strict 正例 | 余弦 AUC |
  |---|---|---|---|
  | `overlap == 0`（机械完全没重合） | 313 | 18 | **0.751** |
  | `bigram < 2` | 191 | 11 | **0.923** |

## 4 · E2：全库检索对照（related = support 含该局）

| 检索方式 | P@5 | R@5 | hit@5 |
|---|---|---|---|
| **现状：walk 渲染** | **0.400** | **0.300** | **0.670**（= holdout relatedRate 0.6695 ✓） |
| embedding 全库 top-5 | 0.097 | 0.130 | **0.331** |
| embedding 同 scope top-5 | 0.263 | 0.288 | **0.568** |

- 语义 top-5 明显更差：它找的是"语义最像"的 claim（往往是同主题的**另一条**失败教训），而不是"这条任务真正相关/同局出现过"的 claim。
- 这直接回答任务书的关键问法：**A2b 严格 46.6% 这个口径用语义替换检索不会提高**（同一批 5 行内重排也改不了 hit@5；换检索则 hit@5 从 0.670 掉到 0.331/0.568）。

## 5 · 结论与建议

**不接入。** 理由（按证据）：

1. **判别力打平略输**：AUC 0.839（语义）vs 0.850（现有 overlap）——现有机械打分已经把这批 label 分得更好；而且这个 label 本身就由 token 重合定义（对机械有主场优势），语义连"打平"都算不上赢。
2. **检索面明显更差**：全库 top-5 的 related 命中 0.331（同 scope 0.568）vs walk 0.670。
3. **对 `related` 口径完全无效**（AUC≈0.5）：语义不认识"证据归属"（support 在哪一局），而这正是本项目 related/strict 定义的一半。
4. **成本不便宜**：12 s 冷加载 + ~1 GB RSS + 6–10 ms/条编码，进不了 `agent/pre-step` 热路径；只能离线建索引。
5. **边界**：AGENTS §2.1 明写本项目「不做向量检索」；本次只是用户拍板的**试点**。试点结论是负的，边界不需要改。

**如果将来还想试**（不在本刀范围，需另立任务）：
- 只做「机械 `overlap=0` 且 walk 无命中」的**兜底召回**（切片 AUC 0.751/0.923，但只有 18 个正例，先要扩大样本到 ≥50 正例再判）；
- 或者把 embedding 当**重排器**（只在同一候选集内排序），而不是检索器——本实验 E2 说明"当检索器"不行；
- 换 BGE-M3 前先算：2.3 GB + 更慢的 CPU 编码（约 3–5×），且本实验里语义的失败点是**口径错位**（证据归属/同局），不是模型太小 —— 换大模型不会解决。

## 7 · 限制（不许当结论用）

1. **标签是机械的**：A2b 的 strict/related 由 token 重合与 support 归属定义 ⇒ 无法证明"语义更符合人类相关性"；本实验只能说明**在项目自己的口径下**语义不占优。
2. **单一模型**：MiniLM 多语言 384 维；未测 BGE-M3（体积超预算）。语义的失败形态（找"主题相近但不同局"的 claim）换更大模型也大概率存在。
3. **E2 的 label 偏向 walk**：related = support 含该局，而 walk 就是沿着 support/links 走的；embedding 没有这个结构信息。这是"结构性劣势"，但也正是现状的**有效机制**。
4. **未做端到端注入实验**：本刀只测检索/判别，不测"注入后模型是否少踩坑"（那是 ablation 的口径）。
5. 样本：118 题 / 403 对 / 78 strict 正例；切片只有 11–18 个正例，**不足以支撑"兜底会有用"的结论**。
