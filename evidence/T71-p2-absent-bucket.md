# T71 · P2 最后那 454 条「本局没有」＝ T157 那一族（拼接/改写），不是"指错局"

> 2026-11-09 · 接 T66–T70。这一刀**不下结论修**，只把最后一桶定位到已有的未决问题（T157）。

## 一、问题

T70 之后 `provenance-p2` 的账是：

```
ok 750 · 位置偏 3111（T69 已修生成侧）· 本局没有 454
```

`本局没有` 的定义是「该局**所有**事件的文本里都找不到这段引文」。两种可能：

1. 引文被**拼接/改写**了（前段对得上、后段对不上）；
2. 引文根本来自**别的局**（episode 指针错）。

## 二、实测（60 条样本）

对每条取「引文前 40 字是否出现在本局原文」：

```
首 40 字在原文 : 57 / 60   ← 开头是对的，后面才分叉
尾 40 字在原文 :  3 / 60
完全不在      :  0 / 60
```

**57/60 的引文开头逐字正确**（例：`Error: glob search failed (exit 2): rg: /d/DeepSeek Harness/…`、
`| S13 | **参考层泛化（Q17-C）** | 命令泛化成 \`tool+操作类\`…`）。
⇒ **不是指错局**，是**引文被拼成了原文里不连续的一段**。

## 三、结论：这就是 T157 那一族

`计划表.md` 的 **T157** 早就写着同一件事：

> A6 剩余 1 条 missing 的根因口径：`ep-226dbf4f@3670`（**抽取把抬头与原文拼成一句，逐字子串不存在**）；
> T123 已结案，但「要不要拆抬头」**未定**。

本轮的 454 条是同一族的**规模**：不是 1 条，是 454 条（占全部引用的 10.5%）。

## 四、为什么这一刀不修

「拆抬头」是**契约级**选择，不是纯实现细节：

- 拆 ⇒ 引文变成"抬头"或"正文"其中一段，逐字可核，但会丢掉"当时上下文长什么样"；
- 不拆 ⇒ 保持现状，可读性好，但永远核不过。

这属于 T157 里明确标"未定"的判断，应由 `docs/拷问记录.md` 记一笔再动手，**不该在归因轮里顺手定**。

## 五、验收

本轮只做**归因**，不改代码、不改数据。证据是本文件的实测数字 + `计划表.md` T157 行的更新。

### 一个已查明具体形态的样例

```
claim c-0278a298 · edge e590 · seq 3284 · quote 长 200（= maxQuote 上限）
边 errorSnippet 前 120 字 ≡ 引文前 120 字（**完全相同**）
但整局日志里搜 "glob search failed" → **0 次命中**
```

⇒ 上游 `graph.json` 的 `errorSnippet` 里**混进了会话日志里不存在的文字**（或来自别的局/别的片段）。

### 归因结论（可下结论了）

| 形态 | 占比 | 归属 |
|---|---|---|
| 开头对、后段分叉（拼接/改写） | ~97% | **上游 `errorSnippet` 是重排/摘要**（我们只读） |
| 整句都不在日志 | ~3% | 同上（引了别处/合成文本） |

**我们这侧的引文构造没有问题**（T69 已把 seq 指对，T70 已把口径对齐）；
剩下这 454 条（10.5%）的**源头文字在会话日志里不存在**，因此**不可能**通过改我们的代码变可核。

### T157 因此只剩两个选项（都不是"修 bug"）

1. **保留现状**：引文可读、不可机械核验（`provenance-p2` 永远报这 454 条）；
2. **降级为"仅指针"**：对这类 support 只存 `edgeId`/`nodeId`（不存 quote），
   审计时按"不可核验"单列（不是 fail、也不是 ok）—— 数字变干净，代价是丢引文。

**这一条必须主人拍板**（属验收标准层面的取舍，不是实现细节）。
