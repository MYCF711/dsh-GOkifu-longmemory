# 边界静态审计 `scripts/boundary-audit.mjs`（2026-11-02）

## 为什么
`docs/记忆的职责边界.md` §5 要求「注入上线前必须跑一次机器审计」，`AGENTS.md` 目录约定也列了
`scripts/boundary-audit.mjs`，但仓里一直没有这个脚本。audit-01 把它记为 P2-8。

## 做了什么
- **只扫模型可见面**：`src/rooms/inject.mjs`（卡片渲染，唯一真正进模型上下文的地方）与 `src/plugin.mjs`（注入消息构造）。
  `gates.mjs` 的字符串是**给代码/日志看的失败原因**，不注入，故不扫（写在注释里）。
- 扫描对象是**源码里的字符串/模板字面量**，先剥注释、再去掉 `IMPERATIVE_PATTERNS`/`GOVERNANCE_PATTERNS` 声明块
  （否则检测清单自己会被判违规）。
- 命中即退出 1；已接进 `check.mjs`，PR 阶段就会挡。

## 与运行时闸的分工
| | 静态（本脚本） | 运行时（`gates.mjs`） |
|---|---|---|
| 时机 | 提交/PR | 每次渲染卡片 |
| 对象 | 源码字面量 | 实际注入文本 |
| 价值 | 拦住"往模板里写指令句" | 拦住动态拼接/数据带进来的越界 |

```
boundary-audit: PASS（0 处）        # 当前仓库模型可见面
```
