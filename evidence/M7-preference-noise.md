# 偏好类注入的噪声测量（2026-11-03）

## 怎么发现的
用 `replay-live` 看真实卡片时，看到这样几行被注入：

```
- [candidate] 你持续去各个网站平台学习相关知识，产品不要闲着。 (ep-8cc34e32, 2026-11-02, seq 6975)
- [observed]  开启superagent模式，做好定时任务，写好goal…不要粉色大象。 (ep-8cc34e32, 2026-11-01, seq 1613)
```

它们是**用户原话**（preference 类），带 provenance、逐字引用——按契约是合法的。
但注进去的是**祈使句**，这与边界成文法里"注入只能是事实"的**精神**有张力。

## 测量（本机库，2026-11-03）
| 指标 | 数值 |
|---|---|
| claim 总数 | 322 |
| 其中 `preference` | **110** |
| `preference` 里含祈使/指令词（不要/务必/记得/必须/请/下一步/建议/你应当…） | **40（36.4%）** |
| `antipattern` 里含同类词 | 4 / 186（2.2%） |
| `fact` 里含同类词 | 0 / 26 |

样本（含噪声，逐字）：
- `不要吝啬token，呈现最好的产品，可并发的任务全部交给团队成员或子代理。`
- `理由：不写不要吝啬token就会为了节省token节省轮次…`（**理由句被当成偏好**）
- `- **不要直接写** home\profiles\*cordis.patch.yml…`（**文档里的加粗语法被抽进来了**）
- `我记得好像有个手机版本的DSH是用GO写的，你看看参照一下`（**闲聊，不足以成为长期偏好**）

## 判断
1. 这不是 bug：`preference` 就是为"用户约束"设计的类别，逐字引用 + 带源是正确做法；
2. 但它带来三个真实问题：
   - **祈使句入上下文**（与边界成文法 §2.1 的字面要求冲突）；
   - **噪声**：理由句、闲聊、文档标记被当作偏好；
   - **重复**：40 条里大量是同一批"不要吝啬 token"的复述。
3. 收紧需要**产品裁定**：是"偏好就该逐字复述"，还是"只保留可机械核验的硬约束（hard）"？

## 建议（待主人裁定，Q19）
| 选项 | 做法 | 代价 |
|---|---|---|
| A（维持） | 偏好照旧注入，只在标记上区分 | 祈使句仍在上下文；噪声 36% |
| B（收紧到硬约束） | 只保留 `hard` 类（工具/边界/禁止项），丢弃理由句与闲聊 | 可能丢掉有价值的软偏好 |
| C（保留但降级） | 偏好只出现在**指针**（"本卷有 N 条偏好，见 cli facts"），不逐字展开 | 模型看不到具体内容，价值下降 |
