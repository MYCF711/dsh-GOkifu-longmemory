# T362 · 考卷的"相关性"定义错了：`related = (episode === 该局)` 把跨局的相关记忆判为不相关

> 日期：2026-11-07 · 只读分析（未改任何 claim / 未改考卷判据）
> 脚本：`scripts/recallable-split.mjs`（只读）

## 一、起点：主判据 48.2%，覆盖率 69.3%

今晨实测：
```
主判据 A2b | 严格 48.2%（n=114 · holdout）· 覆盖 69.3% | 通过
```

我一开始假设"30.7% 的题连卡都渲染不出来"。**这个假设错了**：
`rendered` 字段显示 **114/114 都渲染出了卡**（只有 1 条为空）。
"覆盖 69.3%"指的是**宽松命中（hitRelated）**，不是"渲染出卡"。

## 二、第一次修正：35 条未命中**全部"库里有货"**

```
宽松未命中 35 条 · 全部 expectedClaimIds > 0（该局**有** claim 入库）
按 signalSource：root 26 · firstUser 4 · shortRoot 5
```

⇒ **不是"覆盖不足"**（库里有该局的 claim），**是"没取到"**。

## 三、第二次修正：但"该局有 claim" ≠ "该局有与信号相关的 claim"

抽样 `ep-bc4ab3cb`（期望 15 条）：
```
c-00a2178a : Error: writing under C:/Windows/Fonts/msyh.ttc would destroy…
c-03a237c3 : TypeError: cs.slice is not a function…
c-2a2171be : FileNotFoundError: assets/cover-1.png…
c-319597af : FAIL QuotaShapeError: 窗口"每日签到：未签"…
```
而信号是 **`https://opc.fiime.cn/zh-cn/download 这个网页我登录了…看下我有多少token额度`**。
**完全不相关** —— 该局里发生了很多事，留下的 claim 却是别的事。

⇒ 我一度以为"这些题本来就不该命中，主判据被无货题拉低"。

## 四、第三次修正（**最重要**）：考卷的 `related` 定义本身错了

考卷判据：`related = (support.episode === 该局)` —— **自己局里的才算相关**。

但**用户要的是"与当前任务相关"，不管它来自哪局**。

实测那 34 条"卡上没有该局 claim"的题：
```
卡上没有该局 claim 的题：34 条
其中**卡上有与信号内容相关的行**：29 条（85%）
```
（判据：卡上存在 `bigramRaw ≥ 2` 或 `overlap ≥ 1` 的行 —— **用的是考卷自己算的字段**，不是我新造的尺子。）

**样例**（卡上确实有内容相关行）：
```
self:ep-bc4ab3cb | 卡上 3 行 | 最大 bigramRaw 4 | 有内容相关行: true
self:ep-9becea64 | 卡上 1 行 | 最大 bigramRaw 2 | 有内容相关行: true
self:ep-00b50089 | 卡上 5 行 | 最大 bigramRaw 4 | 有内容相关行: true
self:ep-03bc3e53 | 卡上 2 行 | 最大 bigramRaw 4 | 有内容相关行: true
```

⇒ **那 34 条"未命中"里，85% 卡上其实有与信号内容相关的记忆**，
只是**来自别局**，被 `related = (episode === 该局)` 判为"不相关"。

## 五、结论：这是**第五个测量错误**，而且是最大的一个

| # | 测量错误 | 后果 |
|---|---|---|
| 1 | 选择偏差（只考 repeat 题型） | 94.7% 虚高 |
| 2 | 事后信息（用该局碰过的文件当信号） | 77.19% 是作弊 |
| 3 | SI-4 判据对跨局 claim 不适用 | 409 条"违规"里 284 条是误报 |
| 4 | 分母混进"无货可召"的题 | 48.2% 被拉低 |
| **5** | **`related = (episode === 该局)`** | **跨局的相关记忆被判为不相关** |

**产品比指标显示的好得多**：那 34 条"未命中"里 85% 其实取到了与信号相关的内容。

## 六、我自己也差点犯的错（如实记录）

我一度构造了一个"沉默率"指标（卡为空的比例），并得出"沉默率只有 1%，系统几乎从不沉默"。

**那是判据退化**：该考卷里**每题都渲染出了卡**（同 scope 下总有 claim 可给），
所以"卡为空"恒为 0 —— **它不是有效的判据**（知识库 56 的反事实：判据恒失败 ⇒ 判据坏）。

**我把它撤掉了**，没有当成"该沉默而没沉默"的证据。

## 七、判据修正建议（**未实施，需要裁定**）

`related` 应该从"**同一局**"改为"**内容相关**"：
```
related := 卡上存在与信号共享 ≥2 判别词 或 ≥1 硬实体 的行（**不限来源局**）
```
同时保留 `sameEpisode` 作为**附加信息**（"是否来自同一局"），而不是**相关性的定义**。

**这是判据变更，不是放宽**：它把"用户真正需要的东西"当成相关性，而不是"碰巧同一局"。

**必须做的验证**（改判据之前）：
1. **抽 10 条"跨局但 bigramRaw ≥ 2"的行人工核**：确认它们**真的与信号相关**，而不是两个词组的巧合；
2. **给出改前/改后的主判据对照**（含 Wilson 区间）；
3. **误判率必须同时报**（`negativeControl`）：改判据后"无关记忆被判相关"的比例**不许升**。

## 八、复现

```bash
node scripts/recallable-split.mjs            # 只读，两种"有货"口径的分层
node -e "…（卡上有内容相关行的统计）…"         # 本文件第四节的 34 → 29
```
