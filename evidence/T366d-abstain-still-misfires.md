# T366d · 精化后的 abstain **仍会误杀**（实测 1/3）：根因是"中文信号 vs 英文报错"

> 日期：2026-11-07 · 用真实考卷（n=118）+ 逐条人工核
> 结论：**精化适用条件并没有解决误杀** —— 在"判据可靠"的输入上，仍有约 1/3 的拒绝是**误杀**。
> 根因：**"中文信号 vs 英文报错"的语义相关对，词重合为 0**（T242 的老问题在 abstain 上又咬了一口）。

## 一、实测方法

`scripts/abstain-effect.mjs`（只读）：
- 对考卷里**判据可靠**（`hasReliableHandle(signal)`）的题，
  模拟"精化后的 abstain"：卡上**没有** `bigramRaw ≥ 2` 或 `overlap ≥ 1` 的行 ⇒ 会被拒；
- 再逐条核"该局是否有与信号相关的 claim"（**不是** `expectedClaimIds > 0` 就算相关 —— 那个判据已被证明是错的）。

## 二、读数

```
判据可靠的题：59 / 118
会被 abstain 拒掉的：3（卡上无 bigramRaw≥2 / overlap≥1 的行）
```

**3 条被拒的题，逐条核**：

| 题 | 信号 | 该局 claim 讲什么 | 拒掉对不对 |
|---|---|---|---|
| `ep-75e7347e` | **安装失败 @tencent-connect 帮我装一下** | `Error: tool call aborted` · `还要装一个工具，占用5k上下文` | ❌ **误杀**（这些正是该给的） |
| `ep-f46d6330` | Codar科搭.exe 的模型版本 | `不要依赖2api` · `TypeError` · `每日签到窗口` | ✅ **正确**（与信号无关） |
| `ep-1e976ca9` | 继续这个会话的任务 | （通用信号） | ✅ 大概率正确 |

⇒ **至少 1/3 = 33% 是误杀**（`ep-75e7347e`）。

## 三、根因：**"中文信号 vs 英文报错"的语义相关对，词重合为 0**

`ep-75e7347e` 的关键对照：
```
信号："安装失败 @tencent-connect/dsh-qqbot@latest 帮我装一下"
claim："Error: tool call aborted"
```
**它们讲的是同一件事**（安装工具时失败），
但 **"安装失败"（中文）与 "tool call aborted"（英文）没有一个共享的词** ⇒ `bigramRaw < 2` ⇒ **被判为"不相关"**。

**这正是 T242 早就记过的老问题**：**"中文任务 vs 英文报错"** ——
**语义相关，但字面零重合**。判据只看词重合，**必然漏掉这一类**。

## 四、结论：精化适用条件**不能**让 abstain 可开

我本以为"精化适用条件"（只在判据可靠的输入上启用）能解决误杀。
**实测证明不能**：
- 即使在"有硬实体/英文判别词"的输入上，
  **"中文信号 vs 英文报错"的对仍会被误判为不相关** —— **误杀率约 33%**。

**所以 `abstain` 的重开条件必须再加一条**：
> **"词重合判据无法识别中英文语义相关"这一类输入，也**必须**被排除在启用面之外。**

**但那一类输入（中文任务 + 英文报错）恰恰是**最常见**的 —— 排除它们，abstain 就没什么可作用的了。**

**这就是 abstain 不能开启的**实证理由**（不是"感觉不安全"，而是**实测会误杀**）。**

## 五、与前几刀的关系

- **知识库 87（精化适用条件）**：理论上"只在判据可靠的输入上启用"能避免一刀切 —— **本刀实测证明它仍会误杀**；
- **T242（中文 bigram + IDF 过滤）**：早就记录过"中文任务 vs 英文报错"的词重合问题 —— **它在 abstain 上复现了**；
- **abstain 的当前状态**：**仍默认关** —— 而且**这次有了实测的误杀证据**（33%），不是"感觉不安全"。

## 六、复现

```bash
node scripts/abstain-effect.mjs

```

## 七、一句话

**"精化适用条件"解决的是"判据在哪些输入上可靠"，但"中文信号 vs 英文报错"这一类，判据**在任何输入上**都判不出来 —— 因为它们共享的不是词，是意思。**
