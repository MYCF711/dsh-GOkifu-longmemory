# T364 · A1.redundant 回放：**23.86% 是上界，不是浪费率**——因为 live-stats 缺会话 id

> 2026-11-19 · 目标：把 A1.redundant 从「未通电、n/a」推进到可判。

## 一、回放实测（历史 `live-stats.jsonl`，35056 行）

```
注入总数      1802
新鲜          1372
「浪费」重注    430    ← 30 分钟内同 scope + 同 digest 再注入
浪费率        23.86%
浪费 tokens   72204 / 353230
```

## 二、**这个 23.86% 不能当浪费率用**

A1.redundant 的判据是「**同会话**同卡再次注入 = 浪费；**跨会话**同卡各拿一次 = 必要」。
但历史 `live-stats` 行里**没有会话 id**（只有 `scope` / `src` / `pid`），所以回放只能按 `scope` 归并 ——
**把"跨会话必要重注"和"同会话浪费"混成了一个数**。

⇒ 430 次是**上界**，真实的浪费率 ∈ [0, 23.86%]，不可判。

这也解释了为什么线上 A1.redundant 一直显示「未通电 n/a」而不是某个数：**它缺的不是样本，是判据所需的字段**。

## 三、本轮修复（只加一个字段，不改行为）

`src/plugin.mjs` 的 pre-step live-stats 行增加：

```js
sid: sessionId ?? null,   // T364：让 A1.redundant 能区分"同会话重注"与"跨会话必要重注"
```

- 新行有 `sid`，**历史行没有** ⇒ 回放时按 `null` 归入"不可判"，不硬造数；
- 不改任何决策路径，只多写一个字段。

## 五、后续（等数据）

有了 `sid` 之后，下一次窗口累积到阈值时，A1.redundant 就能算出**真值**：
同 `sid` + 同 `digest` + 窗口内 ⇒ 浪费；不同 `sid` ⇒ 必要。
在那之前它继续显示 `n/a`（不硬造数），但**根因已经从"样本不足"改成"字段已补、等数据"**。
