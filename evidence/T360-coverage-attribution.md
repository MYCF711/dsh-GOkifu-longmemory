**结论：覆盖率缺口不是"信号无关"，而是「子代理局不产 claim」。**

这些局本身**有失败信号**（失败 4–11 次不等），但都停在 `depth ≥ 1`，于是：
它们的教训没有归并进父局 ⇒ 不产 claim ⇒ 考卷里抽到这些局就渲染不出卡。

## 二、这条与已知两条待办是同一条因果链

```

        └── T292/T293：子代理局的失败教训有没有真的归并到父局（726 局）

```

原计划里 T360 写的「C1 库无 claim / C2 信号无关」两桶，实测下来 **C1 的主因是子代理局**。

## 五、代码核查（2026-11-19）：**「子代理归并到父局」只写在文档里，代码没有实现**

`AGENTS.md` §4.1 的 episode 契约写着：

```js
agentPreset, delegationDepth, // 只收 depth=0；子代理归并到父局
```

实际代码里能查到的只有：

| 位置 | 内容 |
|---|---|
| `src/rooms/episode.mjs` | 把 `delegationDepth` / `parentSessionId` **原样带出**（注释：`R00 原样带出`） |
| `src/rooms/joseki.mjs` | `rootOnly` 开关（**默认 false**）+ 一处 `.filter(...)`，是"忽略子代理局"的**可选项**，不是归并 |
| `src/rooms/claim.mjs` | 有"归并"字样，但**没有**按 `parentSessionId` 把子代理失败并进父局的逻辑 |

⇒ 子代理局的失败**从未进入父局**，父局的 claim 自然也拿不到这些教训。

这正是覆盖率缺口的机制：不是抽取坏了，是**归并这一步根本没落地**。

## 六、修法（下一刀，按顺序）

1. **先定口径**：子代理局的「失败」与父局的「失败」是不是同一件事？
   建议：**是**——失败事实归父局，但 `support` 里保留 `episodeId` 指向子代理局（可回溯到原始日志）。
2. **机械归并**：`buildEpisode` 之后、`promoteClaim` 之前，把 `parentSessionId` 指向的父局聚成一条"含子局的信号视图"；
   **只做深度 ≤2、同一父局、时间窗包含**这三条机械条件（不做语义猜测）。
3. **幂等**：重放两次结果逐字节相同（沿用现有 append-only + 幂等约定）。
4. **复量**：`node scripts/coverage-audit.mjs`，看无 claim 局里 depth≥1 的占比是否下降。

**不做**：跨父局合并、按语义相似度合并、修改子代理局自身的 claim 归属。
