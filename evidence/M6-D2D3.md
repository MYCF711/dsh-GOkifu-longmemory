## D2 · 同类协议错误合并

`errorKeyOf` 新增类映射（只合并环境/协议类，代码语法错误保留原文）：

| 类 | 匹配 | 合并前 | 合并后 |
|---|---|---|---|
| `fs-read-before-write` | file has not been read / changed since read / no longer exists | 4 + 4 + 2 = 10 条分散 claim | **1 条，15 局支撑** |
| `tool-unavailable` | unknown tool / not found | 2+2 | 1 条 |
| `sandbox-limit` | team member limit / aborted / timed out | 2+2 | **1 条，9 局支撑** |
| `policy-human-turn` | requires a direct human turn | 2 | **1 条，5 局支撑** |
| `web-search-empty` | web_search_tool_result blocks | 3 | **1 条，5 局支撑** |

复算：

```bash
node scripts/archive.mjs --store tmp/d23-store   # 本地复跑
# claims 里搜 file has not been read → support 15
```

## D3 · 跨局重复优先

`compareHits` 顺序改为：档位 → depth → **repeat 降序** → weight → 时间 → id。
`repeat` = `claim.support` 里不同 episode 数；失败命中与 claim 用路径归一后的文本机械匹配。

实测：信号「编辑文件时提示 file has not been read」在本机 store 上命中
`repeat=8` 的 fs 类 claim，排在一次性高权重命中之前。
