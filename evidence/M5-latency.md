# M5 注入延迟实测（R11 walk + R12 inject + R13 gates）

`[本] 2026-11-02 04:45 +08:00` · 语料 `tmp/memory-context`（92 棋谱 / 780 主题 / 125 claim）· 工作树
口径：一次 pre-step 决策里"walk → 卡构建 → 闸门"的墙钟时间（不含宿主导入开销），10 个真实信号 × 5 轮 = 50 次。

## 结果（0.6.2 索引 + 闸门缓存后）

| 指标 | 值 |
|---|---|
| 冷缓存（读 1,281 文件进内存） | **355–667 ms**（一次性，插件 `apply()` 预热） |
| 热 p50 | **3.9–5.3 ms** |
| 热 p90 | 20.9–56.4 ms |
| 热 p95 | 46.3–107.2 ms（随 GC 波动） |
| 热 max | 110–123 ms（偶发 GC 尖峰） |

## 修复链

1. 0.6.1：`createWalkCache` + `buildMemoryCard({cache})` + `apply()` 预热（把 1,281 次文件读移出热路径）
2. 0.6.2：主题精确索引（`topicsByKey`，O(terms) 快路径）+ 闸门记录查找走缓存（不再 `store.get` 逐个读盘）

## 判定

- `方案.md` §8.2 硬指标 ≤50ms/步：**p50 达标（≈4ms）**；p90 多数在 50ms 内；p95 受 GC 影响在 46–107ms 波动，**未稳定达标**。
- 冷路径不进对话：插件加载时预热（356–667ms）。
- 尖峰与 GC 相关（同一轮内 max 偶发 ~100ms），不是磁盘读（已全部缓存）。

## 复现

```bash
node scripts/bench-inject.mjs
```

## 结论

影子模式可用；真注入前若要 p95 <50ms，需要减少每卡分配（行字符串复用/对象池）或接受"每会话首轮一次、p50 4ms"的成本口径。**当前结论：p50 达标，p95 不承诺。**
