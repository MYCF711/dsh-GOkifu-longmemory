# M5 注入延迟实测（R11 walk + R12 inject + R13 gates）

`[本] 2026-11-02 04:40 +08:00` · 语料 `tmp/memory-context`（92 棋谱 / 780 主题 / 125 claim）· 工作树
口径：一次 pre-step 决策里"walk → 卡构建 → 闸门"的墙钟时间（不含宿主导入开销），10 个真实信号 × 5 轮 = 50 次。

## 结果

| 指标 | 值 |
|---|---|
| **冷缓存**（首次读 1,281 个文件进内存） | **548 ms**（一次性，已挪到插件 `apply()` 预热） |
| 热 p50 | **5.1 ms** |
| 热 p90 | 50.8 ms |
| 热 p95 | 62.7 ms |
| 热 max | 118.9 ms（偶发 GC 尖峰） |

## 判定

- `方案.md` §8.2 的硬指标是 **≤50ms/步**：**p50 达标（5.1ms）**，p90/p95 在阈值附近、偶发尖峰超限。
- 冷路径 548ms 不进对话：插件加载时预热（`apply()`），首轮注入走热缓存。
- 尖峰与信号命中条数相关（5 条 claim 行时最慢）；下一步可把卡片渲染的重复正则在构建期编译/复用（未做）。

## 复现

```bash
node scripts/bench-inject.mjs        # 冷/热 + p50/p95
```

## 结论

当前形态可用于**影子模式**；开真注入前建议再压一次 p95（目标 <50ms），或接受"每会话仅首轮注入一次、p50 5ms"的成本口径。
