# T365 · 三种失败分开算：位置偏 / 源头不存在 / 读不到

> 2026-11-09 · 接 T74 的定因。T157 我选了**第 3 个选项**（标注来源、审计单列），
> 因为它既不丢信息、也不让数字撒谎 —— 而且**可逆**。

## 一、改了什么

`provenance-p2` 的判定从两态变三态：

| 判定 | 含义 | 是不是我们的缺陷 |
|---|---|---|
| `ok` | 引文逐字出现在被引 seq 上 | — |
| `quote-not-substring` | 引文**在本局别处**存在（多半 ±2/±4，T69 已修生成侧） | **是**（历史数据） |
| **`unverifiable-source`**（新） | 引文在**本局任何地方都不存在**（T74 定因：上游 `errorSnippet` 是摘要） | **否** |
| `seq-unreadable` | 日志读不到 | fail-closed |

规则是**数据驱动**的，不是靠打标：`quote-not-substring` 且「本局别处也找不到」⇒ 降级为 `unverifiable-source`。
所以历史数据里那些**指错位置**的（真缺陷）不会被一起放过。

## 二、改后读数（真库）

```
claims 2410 · refs 4315 · ok 750 · not-substring 3111
  · 不可核验(源头不存在) 454 · unreadable 0 · 其中：位置偏 3111 · 本局没有 0
```

| 桶 | 条数 | 占比 | 说明 |
|---|---|---|---|
| ok | 750 | 17% | — |
| 位置偏 | 3111 | 72% | T69 已在生成侧修掉，历史不回填 |
| **不可核验（源头不存在）** | **454** | **11%** | 上游摘要，我们修不了（T74） |

## 三、为什么选这个而不是另外两个

- **保留现状**（什么都不做）：数字继续撒谎——把"上游摘要"算成我们的缺陷；
- **降级为仅指针**（删 quote）：能治数字，但**丢信息**，而且不可逆；
- **本方案**：留 quote、单列、可逆。将来若上游改成逐字摘录，把这条判定删掉即可。

## 四、验收

```
node --test test/t365-unverifiable-source.test.mjs → 3/3
  ✔ ① 本局任何地方都没有 ⇒ unverifiable-source（不算 fail，也不冒充 ok）
  ✔ ② 引文在本局别处 ⇒ 仍算 fail（偏移不许被"不可核验"吃掉）
  ✔ ③ 日志读不到 ⇒ unreadable（fail-closed）
node --test "test/*.test.mjs" → 1282 条 / 1276 pass / 0 fail / 6 skip
node scripts/check.mjs        → PASS
```

## 五、边界

- **`unverifiable-source` 不是"通过"**：它明确表示"这条证据不可机械核验"。任何下游判据都不许把它当 ok。
- 454 条仍是 454 条 —— 这一刀改的是**账**，不是数据。要让它们真变可核，只能等上游 `graph.json` 改。
