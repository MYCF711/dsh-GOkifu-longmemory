# 签名索引缓存（2026-11-03）：12× 提速，但**不是**之前那次慢的主因

## 改动
`loadSignatureIndex` 按 `(mtimeMs, size)` 缓存；`writeSignatureIndex` 主动失效。理由：
m5 一次会建几百张卡，每张都 `readFile + JSON.parse` 这个文件（当前 135 KB）。

## 微基准（300 次读取同一文件）
```
无缓存：160 ms / 300 次
有缓存： 13 ms / 300 次
提速： 12.3×
```
折算每次约 **0.5ms → 0.04ms**；对单张卡可忽略。

## 诚实结论
- 这是**廉价清理**，不是性能主因；
- 实测 `m5` 完整跑 **130s**（267 局 / 761 claim / 19 条 A2b + LOO + A4 全套），主要成本在
  **A2 的 LOO 与热路径重复建卡**，不是索引解析；
- 之前那次 18 分钟的后台任务还叠了 `ledger-sync`（再跑一遍 m5）与 `check`，并且当时本机另有 compact 测试在跑；
  **不能**把 18 分钟记到索引头上。
