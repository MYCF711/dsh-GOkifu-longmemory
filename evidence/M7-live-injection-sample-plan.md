# M4 精度抽样：为什么必须现在建（2026-11-04）

## 已观察到的现象（来自本会话真实注入的那张卡）
`<memory-ledger>` 362 局 · 5 条 · 299 tokens，触发文本是「整点巡检…」这类**宽泛指令**，
卡里给的却是 `sandbox-limit / fs-read-before-write / web-search-empty / syntaxerror / runtime-destroy` 五类失败教训。

- 好的一面：A2b 口径下这些确实是"同作用域的历史失败"，可回溯（ep+seq 齐全）；
- 风险面：**触发词宽泛 ⇒ 卡片给的是"泛相关"而非"这条任务相关"**。这类情况若不抽样核对，
  A1（负迁移）在线上可能悄悄升高，而 m5 的 A1 用的是离线留出集，看不到线上。

## 所以本轮加了什么（0.116.0）
配置键 `sampleCards`（默认 **true**）：每次**成功注入**时把卡片正文追加到
`<storeRoot>/card-samples.jsonl`（只写 sidecar、不写会话日志；单文件 8 MB 上限；失败不影响注入）。

字段：`{at, scope, scopeFrom, digest, tokens, section}` —— 与心跳的 `digest` 可直接对上，
所以"某次注入 → 那张卡"可一一核对。

## 抽样后的判定方式（下一步）
1. 随机抽 N 条 `card-samples`，逐条问三个问题（人工，不调模型）：
   - 卡里每条 claim 的 `ep+seq` 在原文里确实是这个意思吗？
   - 这张卡对**触发文本**来说是"相关"还是"泛相关"？
   - 有没有把 A 项目的教训贴到 B 项目的语境（跨作用域）？
2. 记 `泛相关率` 与 `错误引用数`，作为**线上 A1 的代理**（离线 A1 仍按留出集算）；
3. 若泛相关率显著，再谈收敛触发条件（例如要求 ≥2 判别词或明确错误类），这属于行为改动，单独一刀。

## 口径
- 抽样只是**取证**，不改变注入行为；
- 生成的文件在 sidecar（`<storeRoot>`），不进仓库；仓库里只放结论（本文件与后续报告）。
