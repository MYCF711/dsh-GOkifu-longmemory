# T360b · 覆盖率被 4079 个子代理局污染：真实根局覆盖率 **77.85%**，不是 69.3%

> 2026-11-19 · 接 T360 归因。修正**指标分母**，并推翻"归并没实现导致覆盖率低"的结论。

## 一、分层实测

```
根局     298 · 有 claim 232 = 77.85%     ← 产品口径
子代理局 4079 · 有 claim 0                ← 按契约不该有（AGENTS §4.1：只收 depth=0，子代理归并到父局）
```

原口径把 4079 个子代理局混进分母 ⇒ 覆盖率被算成 **5.3%（全库）** 一类数字，与"69.3%"的口径也不同源，
**两种读法都误导了归因**。

## 二、归并收益实测为 **0**

| 指标 | 数量 |
|---|---|
| 有子局的父局 | 120 |
| 其中有失败子局的父局 | 105 |
| **其中父局已经有 claim** | **105（100%）** |
| 其中父局无 claim | **0** |

⇒ 即使把子代理局的失败全部归并进父局，**覆盖率一分都不会动**。
上一轮"归并没实现"是真问题（文档与代码不一致），但它**不是覆盖率缺口的原因**——这条要更正。

## 三、本轮改动（只动测量，不动产品行为）

`scripts/coverage-audit.mjs`：
1. 新增 `byDepth`（root / subagent 分层，含 `rate`）；
2. **无 claim 抽样只从根局里抽** —— 子代理局无 claim 是设计如此，不该出现在"缺口"样本里；
3. CLI 打印两行分层结果。

## 四、复现

```bash
node scripts/coverage-audit.mjs          # 看分层两行
node scripts/coverage-audit.mjs --json   # 看 byDepth 字段
```
