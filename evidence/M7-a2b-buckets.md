# A2b 严格口径分桶：失分集中在哪里（2026-11-03）

## 动机
调研 28（Mem0 / LOCOMO）把评测分成 single-hop / temporal / multi-hop / open-domain 四类。
我们也把 19 条冻结卷按机械规则分桶，看 89.5% 的失分到底在哪。

## 分桶规则（机械，可复算）
优先级从上到下：
1. **temporal**：签名含时间戳或时间词（`2026-11-03` / `N 天` / 今天 / 昨天 / 最近…）；
2. **multi-hop**：`prior.length ≥ 2`（该签名在 ≥2 局出现过）；
3. **open-domain**：`sameScope=false`（先例全在别的工作区）；
4. **singleHop**：其余。

## 结果（2026-11-03 实测，`node scripts/m5-report.mjs`）
| 桶 | 严格命中 / 总数 | hit（含非严格） |
|---|---|---|
| multiHop | **15/15** | 15/15 |
| openDomain | **2/4** | 4/4 |
| singleHop | 0 条 | — |
| temporal | 0 条 | — |

合计 17/19 = **89.5%**，与既有口径一致。

## 结论（可执行）
1. **失分全部集中在 openDomain 桶**（2/4）——不是"普遍召回差"，而是"跨工作区先例的可读性差"；
2. openDomain 的 4 条 hit 全中、但只有 2 条达到"文本含 ≥2 判别词"的严格标准 —— 说明卡片**找到了**这些先例，**只是没把判别词带出来**；
3. 这正好落在 Q18（类级章节是否允许跨工作区）的射程内：如果开 B，优先受益的就是这 2 条；
4. 其余 15 条 multiHop 全中，说明同域多跳路径是稳的——**不要为了 2 条去动全局排序**（此前排序实验 0 变化的教训）。
