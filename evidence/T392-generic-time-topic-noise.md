# T392 · 命中面收窄：闲聊也命中主题（「今天天气不错」→ 主题 `今天`）

> 2026-11-19 · 起于 T391 的追问「为什么非活跃会话会被记忆打扰」。

## 一、实测（生产同一套 `matchTopics` + 真库 topics 6593）

| 信号 | 命中主题数 |
|---|---|
| `zzzqqq nonexistent-topic-xyzzy` | 1 |
| `qwertyuiop asdfghjkl zxcvbnm` | 0 |
| `扫描隐私 头部 没找到`（真实报错） | 3 |
| **`今天天气不错`（闲聊）** | **1** |

命中详情：

```json
今天天气不错 → [{"key":"今天","kind":"term","by":"term","input":"今天"}]
```

**根因**：历史抽取把**通用时间词**收进了 topics 表（`今天` 作为 `term` 主题），而匹配是"逐字命中即算"，
于是任何含「今天」的消息都会建卡、都会注入记忆。这不是延迟问题，是**精度**问题（落在主判据 A2b 那一侧）。

## 二、修复（两处，互补）

1. `src/rooms/topic.mjs` 的 `CJK_STOPWORDS`：补入通用时间/寒暄词
   （`今天` `昨天` `明天` `今晚` `早上` `下午` `晚上` `今年` `去年` `刚才` `最近` `未来` `还行` `不错` …）。
2. `src/rooms/walk.mjs` 的 `matchTopics`：**匹配时**跳过这批键 ——
   这样**历史已抽进 topics 的脏键**也不再命中（不删数据，只不改可见性以外的行为）。

> `walk.mjs` 设计上零 import，所以那张小表在文件内就地重复一份，注释里写明与 `topic.mjs` 同源。

## 三、修复后实测

| 信号 | 修复前 | 修复后 |
|---|---|---|
| `今天天气不错` | 1 | **0** |
| `扫描隐私 头部 没找到`（真实报错） | 3 | **3**（召回未动） |

## 五、边界

- 只挡"通用时间/寒暄词"这一类；其他过宽命中（如短英文 token）未处理，属下一刀。
- 历史 topics 行**没有删除**（只增不改）；它们从此不参与匹配。
