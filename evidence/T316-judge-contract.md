## 1 · 契约（`docs/数据契约.md` 新增「判据契约 v1」）

| 节 | 内容 | 为什么 |
|---|---|---|
| **J1 判别词** | `toLowerCase().split(/[^a-z0-9\u4e00-\u9fff]+/).filter(t => t.length >= 4 && t !== 'path')` | 3 字以下（"的"、"the"）到处重合会灌水；`path` 是占位符 |
| **J2 判别性 bigram** | 中文 2 字滑窗；英文/数字/路径 `split(/[^a-z0-9_./-]+/)` ≥3 字；**IDF：df/N ≤ 0.02** | 中文整段当 token 时 `includes` 几乎不命中（T281）；不过滤时 bigram 误判 4.09% → 0.02 后 2.63%（T286） |
| **J3 硬实体桥** | 6 条模式（Win/POSIX 路径、`class:`、错误码、包名、命令），**≥1 个即算** | 实体是语言中立标识符；实体桥误判 0.93%（T248） |
| **J4 判中** | `related ∧ (判别词≥2 ∨ bigram≥2 ∨ 共享硬实体≥1)`；**`related` 是 ground truth，不许改** | 三条通道是并集，只实现一条会得到不同的数（T314 实证） |
| **J5 可复算** | 必须产出 `at`（钉死）/`claimsCount`/每条 row 完整字段；I1 = `results` sha256 逐字节相同 | T315 已落地 |
| **J6 演进** | 改任何一条都要 CHANGELOG + 前后对照；**禁止为凑数改契约** | T314 教训：对不上才是信息 |
