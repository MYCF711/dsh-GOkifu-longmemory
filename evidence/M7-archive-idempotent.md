# 归档幂等性实测（2026-11-03）

## 问题
`AGENTS.md` §2.3 要求"写盘可崩溃恢复：append-only + 帧校验 + **幂等（重放两次同结果）**"。
这条一直只有单测，没在**真实库**上验证过。

## 做法
对真实库连续跑 `node scripts/archive.mjs`，每次前后记录每个 JSON 文件的**字节数**，按 kind 统计
同 / 变 / 新增。

## 结果（连续三次）

### 第 1 次：大量新增（不是幂等问题）
`claims 322→533`、`episodes 117→167`。
原因：**此前未归档的会话这次补齐了**——审计子代理等会话在写完后才有完整 header，
之前的归档把它们跳过了（"没有可用 header ⇒ 不入馆"）。这是**补课**，不是重放失真。

### 第 2 次：+24 新增、8 个变大
新增的是**两次运行之间新产生的会话**（我们自己的对话仍在写日志）；
变大的 8 个是活跃会话的 episode（`ep-8cc34e32` 等）——它们在持续追加事件。

### 第 3 次：**0 新增，仅 3 个活跃 episode 变大**
```
episodes: same 164 / changed 3 / added 0
claims/topics/links/threads/joseki: 全部 same，0 变化
```

## 结论
- 对**已封存**的数据，归档是幂等的：第 3 次除 3 个活跃会话外，3574+ 个文件字节不变；
- 对**仍在写**的会话，episode 会继续变大——这是"增量入馆"的应有行为，不是幂等性破坏；
- 之前 322→533 的跳变，是补齐了"当时还没有 header"的会话，属于设计内的补课。

## 留下的判据
判断"归档是否失真"用这一条：**同一批已封存会话，重跑后除活跃 episode 外零变化**。
需要时可复跑本文件里的三步法（快照字节数 → archive → 比对）。
