# T56 · 发版时 `node --test` 卡死会无声挂住 25 分钟：加有界超时

> 2026-11-09 · 事故 + 缓解。**不是根治**（根因仍未复现），只把"无限等"变成"最坏 4 分钟点名失败"。

## 一、事故（本机实测三次）

| 时刻 | 触发 | 现象 |
|---|---|---|
| 03:47 | `ledger-sync.mjs` 内部跑全量测试 | 子进程忙等空转，20 分钟无输出，只能杀 |
| 03:59 | `release.mjs` 内部跑全量测试 | 同上，`release.mjs` 一直挂在"数测试条数"那一步 |
| 04:10 | `npm test`（与上面那次并发） | 同上 |

一次实测：卡住的测试隔离进程 **20 秒烧掉 186 秒 CPU**（kernel 500s→686s），不是死锁，是忙等/极慢 I/O。

## 二、一个很可能的原因（有数据支持，但不宣称已证）

最慢的一条测试是 `T213 真库只读` —— 它把**真库**（1654 局 / 2410 claim / **11083 条 link**）交给每个工具真调一次。
T54/T55 之前它要 **103.7 秒**，而且每个工具调用都重建 walk cache、`stats` 还全量解析。

T54（计数走文件名层 + walk cache 惰性）与 T55（walk cache 跨实例共享）之后，同一条测试：

```
T54 之前  tmp/test8.log   T213 = 103718ms
T54 之后  tmp/test9.log   T213 =  49652ms
          tmp/test10.log  T213 =  51237ms
T55 之后  tmp/test11.log  T213 =  41031ms      ← 2.5×
```

也就是说：**"卡死"的最大嫌疑对象已经被顺手砍掉了 2.5 倍**。这不证明它就是根因（其余测试也一起变快了），
但它让"某一条真库测试在 I/O 争用下跑到几分钟"这条路径明显变窄。

## 三、缓解（本轮改的）

`scripts/release.mjs` 数测试条数那一步：

```js
run(process.execPath, ['--test', `--test-timeout=${TEST_TIMEOUT_MS}`, ...tracked]);   // TEST_TIMEOUT_MS = 240_000
```

- 卡住 ⇒ 变成"某个测试超时失败"并**点名**，最坏 4 分钟出结论（原来是无限等）。
- 240 秒 = 2.3× 余量（最慢一条现在 41 秒）。

## 四、验收

```
node --test test/release-ledger.test.mjs → 19/19
  （断言 argv = ['--test', '--test-timeout=240000', 'test/a.test.mjs']；未跟踪的测试仍不许传）
```

## 五、边界（别当已修好）

- **根因没复现、没定位**。02:00–09:00 之间加了 `--test-timeout=180000` 连跑 5 次全绿，一次都没再现。
- **超时器对同步忙等不一定生效**：如果进程卡在同步循环里，Node 的定时器根本没机会跑。
  所以这是"缩小损失"，不是"保证有界"。
- **只改了 `release.mjs`**。`ledger-sync.mjs` / `ledger-check.mjs` 的 `node --test` 调用被
  `test/ledger-tmp-guard.test.mjs` 的正则**逐字符**钉死（要求两边完全同一口径），改它要连带改闸，
  本轮没动 —— 如果要改，应该是三处一起、并把那条正则放宽成"允许同一个超时参数"。

## 六、补记（2026-11-09 10:14）：又复发一次，这次抓到了特征

| 项 | 读数 |
|---|---|
| 启动 | 10:10（`node --test --test-reporter=spec "test/*.test.mjs"`） |
| 日志停止增长 | **10:14:00**，停在 `✔ T325 ④` 那一行 |
| 已完成 | **800 / 1246** 条（约 64%） |
| 隔离子进程 | 内核态 CPU 持续增长（238s → 364s，20 秒采样仍在涨）⇒ **忙等**，不是死锁等 I/O |
| 处置 | 10:30 杀掉；**紧接着重跑**同一条命令 ⇒ **148.5 秒全绿**（1246/1240/0/6） |

特征与之前三次一致：**父进程无输出、某个隔离子进程在烧 CPU、重跑就过**。
注意这次是 `--test-reporter=spec` 下复发的 —— 之前"spec 没复现过"的印象作废。

仍未定位到具体是哪个测试文件：隔离子进程的 argv 里**不带文件名**（只有一堆 node 参数），
日志又是完成序而非派发序，靠现有手段分不出来。下一步如果要挖，应该用
`--test-concurrency=1`（顺序执行，卡住时"最后一行"直接指向下一个文件）。
