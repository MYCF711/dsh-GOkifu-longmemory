# M5 · 定式候选为什么是 0（R03/R08 根因证据）

`[本] 2026-11-02 04:55 +08:00` · 语料 `DSH_HOME`（25 局 root）· 工作树
问题：真实语料 R08 一直 0 候选。此前假设"成功边只收 write 型"。本轮补了 S11（`tool/result` 以 `[exit code: 0]` 结尾也算可验证成功），再量一次。

## 1 · 补 S11 后的成功面

| 指标 | 数值 |
|---|---|
| 有成功信号的局 | **12 / 25** |
| 成功条数（含命令退出码） | **105** |
| 跨 ≥2 局重复的成功签名 | **1 条**（`{"path":"user"}`，工具参数噪声，不是可复用招法） |
| 定式候选（R08，≥2 局同签名序列） | **0** |

## 2 · 结论

1. **不是"我们没把命令成功算进去"**：算进去后成功从 54 → 105，跨局重复仍只有 1 条噪声。
2. 原因是**真实编码会话的命令高度 episode 特异**（路径、参数、文件名每次都不同），精确签名几乎不重复；R08 要求"2–3 招连续窗口 + ≥2 局独立支撑"自然为 0。
3. 要长出定式，必须让签名**泛化**（如按 `tool + 操作类`：`bash:测试`、`edit:配置`）；但泛化会直接放大过拟合风险（把一次偶然成功当通用招法）——这是**方向问题**，需要主人裁定，不能由实现自行放宽。
