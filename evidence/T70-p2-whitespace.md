# T70 · P2 的 3565 拆成「位置偏 3111 / 本局没有 454」，并修掉白色噪音

> 2026-11-09 · 接 T66–T69。这一刀**不改数据**，只把"这个数到底在说啥"钉死。

## 一、发现：34% 的失败只是**空白差异**

`support.quote` 是**单行视图** —— 生成侧 `clipQuote()` 明确把 `\s+` 折成单个空格（卡片只能单行）。
而 `provenance-p2` 的 `normalizeText()` 只处理 CRLF/NBSP/ZWSP，**不折叠连续空白**。

于是拿单行引文去和多行日志做"逐字节子串"比较，等于两套口径互判：

```
实测：3565 条失败里 1223 条（34%）只是差空白（diagnosis.elsewhereCollapsedOnly）
样例：'[notice] A new release of pip is available: 26.2.1 -> 26.2.2 [notice] '
      原文子串? false   · 空白折叠后? true
```

## 二、改法（三处，都在审计侧）

1. `normalizeText()` 增加**连续空白折叠**（并 `.trim()`），写进 `NORMALIZE_RULES`（可被审计）；
2. `indexEvents()` 的**跨段拼接改用单空格**（原来用 `\n` 拼 ⇒ 跨两段的引文永远对不上）；
3. `stats.breakdown = { offset, absent }`，`formatSummary()` 带上"位置偏 / 本局没有"。

## 六、边界

- **`ok` 不变**是预期的：这一刀修的是**归因口径**，不是数据；`位置偏` 那 3111 条要等**新归档**才消失（T69）。
- 空白折叠会不会**放过真错**？会放过"只有空白不同"的引文 —— 那正是引文的定义方式（单行视图）；
  真正的改写/截断仍然判红（T70 ② 断言了这一点）。
