# N9 设计：按签名索引历史失败原文（2026-11-03）

## 要解决的问题
`hit=19/19` 但卡片会给**错类别的教训**：walk 按"类别"召回 claim，无法保证卡片里出现该先例局**这条**失败的原文。
（实例：hostname 解析失败 → 卡片给「文件未读」「web_search 空」两条。）

## 观察到的数据事实
棋谱边（`<sid>/graph.json` + 增量 delta）里，失败边带：
```
{ id:'e748', result:'failure', errorSnippet:'Error: URL hostname "raw.githubusercontent.com" resolves to a non-public IP address',
  evidence:{start:...,end:...}, ts:<epoch ms> }
```
即：**签名 + 原文 + seq 区间 + 时间** 四件套都在。而 claim 的 support 只有"代表行"，覆盖不到同局的其它变体。

## 设计
1. **派生索引**（可重建、只增不改）：`<storeRoot>/signature-index.json`
   `{ version, builtAt, entries: { <归一化签名>: [{episode, edgeId, seq, occurredAt, snippet}] } }`
   由 `scripts/build-sigindex.mjs` 扫描所有 episode 棋谱边生成；实测 93 局 / 28,135 边 / 628 条失败原文 / 172 个签名。
2. **注入侧**（下一步接）：`buildMemoryCard` 先算信号签名 → `lookupSignature` → 命中则追加一条带完整 provenance 的条目
   （`episode + edgeId + seq + occurredAt`），文本用原文 snippet；仍受作用域闸（A5）与十道闸约束。
3. **不替换现有 claim 条目**（N8 教训：替换会误伤），只做**追加**，且每信号最多 2 条。

## 验收口径（下一轮）
- `recallReadable`（卡片含签名 ≥2 判别词）：当前 **17/19**；
- `hit` 保持 19/19；`strict` 不下降（≥17/19）；
- A1 仍 0%、A5 仍 0 越界、A4 p95 不受影响（token 增量需记录）。

## 为什么先只做索引
索引是可独立验收的派生数据：没有它，注入侧无从按签名取原文；有了它，注入改动才是"接一根线"，
而不是又一次大改检索。索引也方便未来复用（CLI/审计/回放）。
