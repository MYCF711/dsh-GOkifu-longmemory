## 0. 三条判据（缺一条都不算成功）

1. **改一个用户可见行为，只需碰一个地方**（改动半径）；
2. **"全绿"只需一条命令**（现在我们是 check + 全量 test + patrol + metrics-guard + ledger-check + tag-audit **五条以上**）；
3. **加一个新能力不需要理解 2,100 行**（新房间 + 登记 + 一条边界用例）。

"减少行数"不是目标，是副产品。

## 2. 六条方法 → 本仓动作

| 方法 | 压缩仓怎么做 | 棋院要做什么 |

## 3. 顺便吸收的上游精髓（代码级，详见对标方案）

| 吸收 | 上游代码级依据 | 落在哪 |
|---|---|---|
| **注入按 slot 幂等覆盖 + 内容 hash** | Letta `rebuild_system_prompt`（注释原话：不该重建，否则 flood recall storage） | 新房间 `inject-slot` |
| **归档按 episode 增量、候选限定端点对** | Graphiti `add_episode` 8 步 + `_pair_search_filter` | `persist.replaceDerived` |

## 5. 不做的

- 不为了"像压缩仓"而重写记忆核心（机械抽取 + 只增不改是我们的红线，与他们的压缩定位不同）；
- 不引入向量库（MemBench：全量注入 10k→100k token 时参与式 0.647→0.489）；
- 不把陪伴层（小屋/桌宠/微信/QQ）搬进来。
