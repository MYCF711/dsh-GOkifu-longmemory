# 对标 Hindsight：基线台账与"更强"的判据

> 2026-11-02 · 本项目硬约束（主人裁定）：「我们也用了这么久的 hindsight 了，**至少要做的比 hindsight 强**。」
> 本文只做三件事：**把基线量出来**（本机部署实测，不引用厂商分数）；**定义"更强"能合法地指什么**（Q2 已裁定）；**给出可跑的擂台协议**。
> 引用标记同 `方案.md`：`[本]` = 本机实测（带时点）；`[外]` = 外部证据。

---

## 0 · 为什么必须写这一页

"比 Hindsight 强"如果停在这句话，它会变成无法验收的口号；拿厂商自报的 LoCoMo / LongMemEval 分数来比，又是**错的口径**——那些是聊天记忆基准，不是 DSH 编码会话，且各家评测模型/预算不同、不可排名 `[外] docs/调研/03-产品对标简报.md §5`。

**唯一合法的比法：同一个域（本机 DSH 编码会话）、同一批留出会话、同一份任务预算，比"记忆带来的净收益与净损害"。**

## 1 · 基线：本机 Hindsight 的真实配置与实测

### 1.1 部署形态（`~/.hindsight/coding-agent.json`，2026-11-02 读取；密钥不录）

| 项 | 值 | 意义 |
|---|---|---|
| `serverMode` / `apiUrl` | `self-hosted` / `http://<LAN_HOST>` | 本机服务，走 HTTP；**记忆不在进程内** |
| `bankId` | **`coding-agent::default-workspace`**（静态） | **所有项目共用一个 bank**（不是 per-repo）——跨项目混流的结构性来源 |
| `autoInject` | `recall` | 首轮注入改走 recall（用户注释：pages 模式实测注入 3,879 字符里**真实记忆 = 0**；recall 平均 **1,666 字符真实记忆**）`[本·配置注释]` |
| `recallOptions` | types `world/observation/experience`、budget `low`、`max_tokens: 2000`、`min_scores.reranker: 0.005` | 用户两轮调参：MRR@8 0.857→0.929、65/103→77/103（+10.7pp）、token 170→400/轮 `[本·配置注释]` |
| `recallRefreshEveryTurns` / `injectTimeoutMs` | 3 / 10,000 ms | 每 3 轮刷新一次注入；超过 10s 放弃 |
| `pages` | 关 `Initiatives`，其余 4 页保留；`pageRefreshEveryTurns: 20` | 知识页每 20 轮刷新（每次一回合 LLM 合成） |
| `observationScopes` | `combined` | 观察按标签组合分作用域 |

### 1.2 实测用量与可靠性（`~/.hindsight/coding-agents-logs/`，2026-11-02 统计）

| 指标 | 数值 | 口径 |
|---|---|---|
| 会话数 / 轮数 / 天数 | **209 个会话 / 13,700 轮 / 33 天** | `usage.jsonl` 全量 |
| 最近一天轮数 | **1,585 轮**（2026-11-01） | 同上 |
| `retain_ok` / `retain_failed` | **3,127 / 252（7.5% 失败）** | `diag.jsonl` |
| `pages_ok` / `pages_failed` | **560 / 69（11.0% 失败）** | 同上 |
| `inject_recall` / `inject_recall_failed` | **703 / 293（29.4% 失败）** | 同上；失败样本为 10,000 ms 超时 |
| 注入延迟（成功） | **p50 4,715 ms / p90 8,329 ms / mean 4,902 ms** | 同上 |
| 每次注入条数 | **p50 8 条 / p90 12 条** | 同上 |
| `inject_empty` | **2,776 次** | 大量轮次注入为空 |

> **任何"更强"的声明都必须同时过这三关，且不能在"收益"上倒退。**

## 2 · "更强"能合法地指什么（六轴，全部可测）

| # | 轴 | Hindsight 基线 | 本项目目标 | 测法 |
|---|---|---|---|---|
| **A1** | **负迁移/错误记忆** | 未量测（论文自认 "blur the line between evidence and inference" `[外]`） | ≤5%（**硬上限**） | 留出会话注入后逐条核验；带 validity/preconditions 的机械判、其余影子+抽样 |
| **A2** | **收益：不重复踩坑** | 未量测（只有检索命中率 MRR 类指标） | **相对无记忆的下降幅度不劣于 Hindsight** | 有/无记忆配对；`repeatFailureRate`（失败动作签名匹配） |
| **A3** | **可靠性** | 注入失败 29.4%、retain 失败 7.5%、pages 失败 11.0% | **0 失败**（失败只降级、不中断；in-process 无网络） | 每次注入必有结果或明确的"空"状态；故障注入测试 |
| **A4** | **延迟/成本** | p50 4.7s / p90 8.3s；写侧 LLM 抽取 + 页合成；读侧 ≤2000 tokens | ≤50ms（本地文件读）；写侧 **0 模型调用**（裁决层除外）；读侧 ≤500 tokens/步 | 计时 + token 计量 + 模型调用计数 |
| **A5** | **作用域隔离** | 单一静态 bank（所有项目混流） | 按工作区隔离，只允许显式祖先 | 跨项目注入泄漏测试 |
| **A6** | **可核/可回溯** | 观察带 proof count + 原文引用，但抽取是 LLM 推断 | 每条 claim → episode → seq/边 → 原件，100% 带 provenance；每条带 `occurredAt` | provenance 覆盖率断言 + 追溯测试 + 时间戳覆盖率 |

> **判据（Q2 已裁定，2026-11-02）**：
> **主判据 = A2 收益**（`repeatFailureRate` 相对无记忆的下降幅度，且不劣于 Hindsight 的同一指标）。
> **A1 负迁移 ≤5% = 硬上限**（只否决，不参与"赢"的计算）；**A3 可靠性 / A5 作用域 / A6 可回溯 = 硬门槛**；**A4 延迟成本 = 硬指标**。
> 为什么稳：① 主判据与产品第一验收面同源；② 堵住"少说少错"（空注入系统不能赢）；③ 可机械测、可复算。六轴全过才允许说"比 Hindsight 强"；若 M5 数据显示收益无法超过 Hindsight，则降为"收益非劣 + 六轴全过"，并记一次改判。

## 3 · 擂台协议（怎么跑出可比较的数）

### 3.1 三个对照臂

```
臂 1  无记忆（baseline）        —— 关掉两个插件，同一留出会话重放
臂 2  本项目记忆               —— 只用 <T 的会话构建记忆，注入 ≥T 的会话
臂 3  Hindsight                —— 用其本地 bank 的 recall（同一首轮提示），或历史日志里已发生的注入
```

### 3.2 语料与切分

- 主数据集：**本机 DSH 编码会话**（当前 86 个会话日志 / 11 张棋谱 `[本] 2026-11-02`；随使用持续增长）。
- 切分：按时间 `<T` 训练、`≥T` 留出；每臂至少 20 个留出会话才报数（不足则只报方向，不报数值）。
- 臂 3 的两个现实约束：① Hindsight 的历史注入已发生，可从日志取（离线）；② 若要重放新提示，需调它的 recall API（只读，不改它的 bank）。

### 3.3 指标（每个带分子/分母/时点）

| 指标 | 定义 | 对应轴 |
|---|---|---|
| `negTransferRate` | 注入条目在留出会话中被证据否定/判不适用的条数 ÷ 注入条目总数 | A1 |
| `repeatFailureRate` | 留出会话中"执行了记忆里已结算失败动作"的次数 ÷ 可避免失败动作总数 | A2 |
| `injectFailureRate` | 注入失败（超时/异常/应有却空）次数 ÷ 注入尝试次数 | A3 |
| `injectLatency` | p50/p90 毫秒 | A4 |
| `injectTokensPerStep` | 真实 token（CJK 加权） | A4 |
| `crossScopeLeakRate` | 注入条目中 scopeKey 不匹配的条数 ÷ 注入条目总数 | A5 |
| `provCoverage` / `timestampCoverage` | 带 provenance / 带 `occurredAt` 的注入行 ÷ 总注入行 | A6 |

### 3.4 什么不能拿来比（写死，防止自欺）

- **不能比厂商自报的 LoCoMo / LongMemEval / BEAM 分数**：域不同、评测模型不同、预算不同；且不可排名 `[外] 03 §5`。
- **不能只比"注入条数/检索命中"**：那是手段不是目的；A2 必须落到"少走弯路"。
- **不能只比延迟**：更慢但更准可能仍更强；快而错是最差的组合（A1 是硬上限）。
- **不能拿训练集内的命中当收益**：那是考同一张卷子（`方案.md` §6.4）。

## 4 · 本项目对"更强"的诚实风险清单

| # | 风险 | 为什么诚实地说它存在 | 缓解 |
|---|---|---|---|
| 1 | **语义召回不如 Hindsight** | 它有多臂检索 + cross-encoder；我们只有 scope + 机械排序 + 文件树 | 记忆树 + `index.md` + 模型自有 read/grep；scope 命中优先；M3 先测"注入覆盖率" |
| 2 | **抽取语义不如 LLM** | 它用 LLM 抽事实/观察；我们机械抽取，可能漏掉"隐含的成功模式" | 机械抽取先做"可核事实"；定式由受限归纳 + 证据门槛 + 多成员裁决；M4 再评估 |
| 3 | **Hindsight 的调优是资产** | 主人两轮调参（MRR 0.857→0.929）不是白做的 | 不比"调参后的它"，比"同预算下的净收益"；参数不隐藏 |
| 4 | **我们有它没有的失败模式** | 关系网维护成本、关联过泛（F8）、伪共识（F9）、时序混淆（F10）、claim 污染 | 十道闸 + 留出评测 + 事后闸；见 `方案.md` §6 |
| 5 | **测量成本** | A/B/配对重放要跑模型 | 先用 Hindsight 历史日志 + 我方影子模式跑"零模型"指标；M5 再上模型配对 |
| 6 | **跨项目连接** | 它按 repo 分 bank（本机是单 bank 混流，靠标签区分） | 我们按"本质信号"连边（共用基础/技术对象/目的），**反代插件们、GOkifu↔记忆系统能自动连上**；`crossProjectHit` 探针 |

## 5 · 结论（v0.7）

1. **基线已量出来**：209 会话 / 13,700 轮；注入 p50 4.7s、29.4% 失败、单 bank 混流；调优后 token 170–400/轮。
2. **"更强"= 六轴全过**：A2 收益为主判据（必须不劣于 Hindsight），A1 负迁移 ≤5% 为硬上限，A3/A5/A6 为硬门槛，A4 为硬指标。
3. **唯一不能做的事**：拿厂商基准分数当"我们更强"的证据。

> 本文件与 `方案.md` §2.4 联动。任何"比 Hindsight 强"的声明，必须引用本文件的指标与擂台协议；否则视为口号。

## 附 · 2026-11-02 机制级对照（来源：本机 hindsight-coding-agent skill 文档）

| 维度 | Hindsight（原文所述） | 我们（本仓实现） |
|---|---|---|
| 存储单元 | 每仓库一个 bank（worktree 共享） | 单 store + `scopeKey` 作用域 |
| 摄入 | commit seed + 代码库 survey + 对话 | **只收会话**（无棋谱不入馆） |
| 合成 | 首条 prompt 触发 LLM reflect | 机械 walk（毫秒级） |
| 知识页 | 5 张固定分类，LLM 周期合成 | 不建知识页；类级章节机械拼接 |
| 失败降级 | reflect→pages→recall→无记忆 | 任何异常→原 decision（fail-open） |
| 纠错 | `Correction:` 文档 | L4 人纠错 → counter/validTo/disputed |
| 延迟 | 秒级 | 毫秒级（本机 p50≈2ms） |

**结论**：我们的优势在「可回溯 + 可核 + 零模型成本 + 毫秒延迟」；
它的优势在「自动摄入代码与提交历史」——这一条我们**刻意不做**（边界成文法）。
要"至少比它强"，把这条差异写清楚比盲目对齐更重要。
