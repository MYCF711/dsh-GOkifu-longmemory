# 多少记忆才够：位置、稀释与"少而准"（2026-11-06 采集）

- 来源：一手论文（已读摘要全文，访问日期 **2026-11-06**）：
  [Lost in the Middle: How Language Models Use Long Contexts](https://arxiv.org/abs/2307.03172)
  （Liu, Lin, Hewitt, Paranjape, Bevilacqua, Petroni, Liang；**TACL 2023** 接收；arXiv v3 2023-11-20）。
- **范围声明**：44 篇讲验收方法论、50 篇是判据总表、61 篇讲负向对照；
  本篇只写**"多少记忆才够"**——位置效应、注意力稀释、卡片大小的判据。三篇不重复页面。

## 一、长上下文"能用" ≠ "会用"：位置决定可用性

- [外] **核心发现**："performance can **degrade significantly when changing the position** of relevant
  information, indicating that current language models **do not robustly make use of information in long input
  contexts**."
  ⇒ 同一份内容，**放在不同位置，效果不同**——"塞进去了"不等于"被用上了"。
- [外] **U 形曲线**："performance is often **highest when relevant information occurs at the beginning or end** of
  the input context, and **significantly degrades when models must access relevant information in the middle** of
  long contexts."
- [外] **长上下文模型也一样**："**even for explicitly long-context models**"——即**窗口变大不解决定位问题**。
- [外] **他们给了评测协议**："provides **new evaluation protocols** for future long-context language models."
  ⇒ "用了多长的上下文"是产品指标，"**在该用的位置用上了**"才是效果指标（44/56 篇同一纪律）。

## 二、"多给记忆"什么时候反而有害

| # | 机制 | 为什么有害 | 可测信号 |
|---|---|---|---|
| **1 位置稀释** | 相关条目落在**中段** | 中段信息被显著忽略（论文的 U 形） | 把同一张卡放头部 vs 中段，命中率差 |
| **2 注意力预算** | 条目越多，每条**平均被读到的概率越低** | 3 条里每条 ~1/3 注意力，30 条里 ~1/30 | 条数与"被引用的条数"是否同比 |
| **3 上下文挤占** | 记忆占位 ⇒ 挤掉**任务本体**（代码/报错原文） | 模型看不到真正要处理的东西 | 命中率 vs 卡片 token 的**边际曲线**转负 |
| **4 噪声命中** | 泛词/弱相关条目进卡 | 引入**伪相关**（53 篇：归因陷阱） | 负向对照命中率上升（61 篇） |
| **5 自相矛盾** | 新旧条目并存且未标 `supersedes` | 模型按位置选，不按新选（60 篇） | 同一问题两次注入给不同答案 |

**共同点**：这五条**都不体现在"卡变大了"**——所以只看 token 数的验收**永远发现不了**。

## 三、"该给多少"怎么判（我们能测什么）

| 可测量 | 怎么算 | 用来回答 |
|---|---|---|
| **卡片 token** | 注入文本长度 | 成本（已测：卡 191 tokens / 3 条） |
| **命中率** | 该用记忆的题里，答案是否正确 | 收益 |
| **被引用条数** | 卡上几条**真的进了回答** | **稀释度**（3 条中 1 条被用 ⇒ 66% 是噪声） |
| **负迁移率** | 有记忆反而更差的题占比 | 硬上限（`docs/对标-Hindsight.md` §2：≤5%） |
| **边际曲线** | 条数 1→3→5→10 的命中率 | **拐点**就是"够"的位置 |

**判据**：**边际收益转负之前的那一条**就是答案。若 3 条→10 条的命中率增量在噪声区间内（61 篇 `|Δ|<MDE`），
那多出的 7 条**只是成本**。

## 四、一张记忆卡要证明"它帮上了"，最少四条

| # | 判据 | 机械检查 |
|---|---|---|
| **C1 被引用** | 卡上至少 1 条**出现在回答/行为里** | 标注哪条被用（出处 ep/seq 可追） |
| **C2 有增量** | 去掉该条 ⇒ 结果**变差**（不是"没了也一样"） | A/B：有它 vs 无它，逐题配对 |
| **C3 不引入负迁移** | 有记忆的题不因为记忆而更差 | 负迁移率 ≤ 5%（硬上限） |
| **C4 位置不敏感** | 该条**放在卡头/卡尾都能被用上** | 交换位置重测（论文的 U 形） |

**C2 是关键**：绝大多数"看起来有用"的卡片过不了它——**去掉也一样**，说明它只是占位。

## 五、对照本仓（棋院）

- 现状：卡 **191 tokens / 3 条**；`AGENTS.md` 的设计是"**不相关时沉默**"（`silent` 率 ~94%）、
  每条 = 日期 + 出处 + 一句话、**不写"下一步"**。
- 用第二节扫一遍：**位置稀释**——我们的卡在**首轮注入**（`pre-step`），天然落在"开头"位置，
  这是**结构上做对的一点**（不需要额外优化）。
- **注意力预算**：3 条是**经验值**，没有边际曲线支撑；按第三节，应测 **1/3/5/10** 四档的命中率，
  取**转负前的那一点**——这比"再多塞几条"值钱得多。
- **被引用条数**是本仓**已有但未消费**的指标（51 篇：指标先有消费者）：如果长期只有 1 条被引用，
  另外 2 条就是**纯成本**。
- **未采纳**：C2（去掉该条是否变差）**从未测过**——这是"3 条够不够"的直接判据，也是最便宜的一刀。

## 结论

判据三句话：**上下文能用 ≠ 会用**（位置决定可用性，中段被显著忽略）；
**"多给"的害处不在 token 成本，而在稀释与噪声**；**卡要证明自己有用，必须过 C2"去掉它结果变差"**。
最后一句：**"多少才够"的答案不在直觉里，在边际曲线上**——把 1/3/5/10 四档跑一遍，
拐点之前的那个数字就是我们的 3（或者不是）。
