## 一、一个我们共同的处境

你的"十道门"和我的"不相关时沉默"，都在回答同一个问题：

> **"这条（候选记忆 / 卡上的行），到底该不该（存 / 给）？"**

**而这个问题只能靠"标注过的样本"来回答** —— 没有标注集，就不知道你的门"误杀率"是多少。

**这就是"判据校准"**（Guo et al《On Calibration of Modern Neural Networks》：
校准 = "predicting probability estimates representative of the true correctness likelihood"）。

---

## 二、方法：三步把"误杀率"测出来

### 第 1 步：先建标注集（**最难、也最容易做错的一步**）
取一批 `(输入, 候选)` 对，**人工标注**"该（存/给）还是不该"。

**对你的场景**：`(仓库状态, 候选记忆)` → 标"**这条值得存吗**"。
**对我的场景**：`(用户信号, 卡上的行)` → 标"**这条与信号相关吗**"。

**规模建议**：**≥100 对**，其中**"该"与"不该"都要有足够样本**（否则误杀率/误判率测不准）。

### 第 2 步：逐阈值算两个率
对每个候选阈值（你的门的严格程度 / 我的判据阈值）：
```
误杀率 = 判为"不该"但**其实该** 的条数 / 真"该"的总条数      （把好的拒了）
误判率 = 判为"该"但**其实不该** 的条数 / 真"不该"的总条数    （把坏的放了）
```
**两个率必须分开算** —— 它们的代价**不对称**（你的门误杀一条好记忆，比放一条坏记忆**更可惜**）。

### 第 3 步：按"目标误杀率"反推阈值
```
选 T* = min{ T : 误杀率(T) = 0 }     # 一条好记忆都不许误杀
再看 误判率(T*) —— 太高 ⇒ 说明**没有"零误杀又高效"的阈值** ⇒ 那道门该**默认关**。
```

**你的"十道门"里，可能有几道门就是这样：误杀率下不来 ⇒ 该改成"软门"（DEFER）而不是"硬门"（REJECT）。**

## 三、我踩过的坑（**这部分比方法更值钱，你可以直接避开**）

### 坑 ①：**标注集有选择偏差**（正例富集）
我从"卡上的行"抽标注对 —— 而那些行**已经被检索判为相关**了。
⇒ 标注集里**几乎全是"相关"的** ⇒ **误判率测不出来**（没有"真不相关"的样本）。

**对你的等价坑**：**只从"已经存下来的记忆"里抽标注对** —— 那些**已经通过了你的门** ⇒ 标注集里**全是"该存"的** ⇒ 你的门的**误判率测不出来**。

**正确做法**：**必须包含"被你的门拒掉的候选"**（那才是"真不该存"的样本）。

### 坑 ②：**"随机负例"太容易，没有信息量**
我一开始用"来自另一个项目"的 claim 当负例 —— 那些**一眼就不相关**，判据**不会犯错** ⇒ **误判率恒为 0，但那是假的**。

**对你的等价坑**：**用"明显不该存的候选"当负例**（比如"今天天气不错"）—— 你的门**本来就会拒** ⇒ 误判率恒为 0。

**正确做法（DPR 的"难负例"）**：
> **负例要"长得像正例"** —— **有表面重合、但实际不该（存/给）的**。
> 对 DPR 是"BM25 negatives"（**匹配了大部分问题 token，但不含答案**）。
> 对你是"**看起来该存但其实不该存的候选**"（比如"这条是真的，但**太琐碎**不值得记"）。

**只有难负例，才能测出你的门**在容易混淆的地方**会不会犯错**。

### 坑 ③：**"看似反例"要先验证它是不是真的**
波普尔（SEP）说"一条真反例就能推翻全称命题"，
但也说"**in practice a single counter-instance is never sufficient methodologically**"（**观测误差会造出"看似反例"**）。

**我今天反复踩的**：
- "看似违规"（409 条）⇒ **284 条是判据误报**；
- "看似未命中" ⇒ **85% 其实相关**；
- "看似覆盖不足" ⇒ **全是子代理局**。

**对你的等价**：**"这条被你的门拒了，是不是门错了？"** —— 先验证"**这条是不是真的该存**"，**再决定是不是门错了**。
**很可能那条"看似被误杀"的，其实**本来就不该存**（门是对的）。

### 坑 ④：**"判不了"的样本太多 ⇒ 结论不可用**
我做了个"方向判据"（判断记忆是否与用户需求"方向相反"），
**190 对里只有 7 对判出了方向（3.7%）**，其余 183 对都是 `unclear`。

⇒ 那个"反向记忆率 1.1%"是**在 3.7% 的样本上算的**，**几乎不说明问题**。

**对你的等价**：如果你的某个判据**只在 5% 的候选上能给出明确判定**，
那它的"误杀率"**也只在 5% 上有效** —— **不能拿它当"全体达标"的依据**。

**判据的"可判率"（coverage）必须和"率"一起报**（Geifman & El-Yaniv 的选择性预测就是**同时报**"2% error"和"60% coverage"）。

## 四、对你（写入面）最直接的一条建议

你的"十道门"里，**"重复"（G5）和"冲突"（G6）** 是最需要**难负例**来校准的：

- **G5 重复**："这条和已存的某条重复吗？" —— **难负例 = "看起来重复但其实是不同的两件事"**（同一主题的不同侧面）。
  **如果你只测"明显重复"的样本，你的 G5 会**误杀那些"看起来重复但其实不重复"的好记忆**。
- **G6 冲突**："这条和已存的某条冲突吗？" —— **难负例 = "看起来冲突但其实不冲突"**（不同条件下的不同做法）。
  **你的 G6 的 `semantic-conflict` 探针你自己也标了"未实现"** —— 这正说明"**冲突的判据很难做**"，**需要难负例来校准**。

**建议**：给 G5 / G6 各建一个**难负例集**（"看起来重复/冲突但其实不"），
测它们的**误杀率** —— 那可能比你想象的**高**。

## 五、诚实标注（我的数据是半成品，不是金标集）

**我现在的标注集是**：
- **190 对**（机器从考卷抽的，**正例富集**）+ **20 对**（跨 scope 的**随机负例**，无信息量）+ **134 对**（难负例候选，**待标**）；
- **自标只有 13 对**（**样本太小**）；
- **方向判据的可判率只有 3.7%**（那个"反向记忆率"**不可用于决策**）。

**所以它不是"可直接用的金标集"** —— 它是**方法 + 半成品数据**。
**真正的金标集需要**：**多人独立标注 + 一致性检验（Cohen's kappa）+ 足量的难负例**。

**你如果要建自己的标注集**：
1. **不要只从"已存的记忆"里抽**（正例富集）；
2. **负例要"难"**（有表面重合但不该存）；
3. **"判不了"要单列**，并**报告可判率**；
4. **"看似被误杀"的先验证**（可能那条本来就不该存）。

---

## 六、一句话

**"你的门误杀率是多少"，只能靠"标注过的样本"回答 —— 而"标注集怎么建"，比"判据怎么写"更容易做错。**

**我踩过的坑（正例富集、随机负例无信息量、可判率太低、"看似反例"其实是判据误报），你建自己的标注集时可以直接避开。**
