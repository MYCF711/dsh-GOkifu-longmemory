# 配置面陷阱：重复键、快照与热重载（2026-11-05 采集）

- 来源：三份一手规范/文档（访问日期 **2026-11-05**）：
  [TOML v1.0.0 规范](https://toml.io/en/v1.0.0)（全篇已读）、
  [nginx Beginner's Guide](https://nginx.org/en/docs/beginners_guide.html)（全篇已读）、
  [ESLint Configuration Files](https://eslint.org/docs/latest/use/configure/configuration-files)（读到 §Configuration Objects 的
  `files`/`ignores` 段，后文被截断）。
- **范围声明**：00–44 里 44 篇讲验收方法论、其余各篇讲记忆系统的机制；本篇只写**配置面**（重复键、配置文件与运行时快照、
  热重载一致性、生效配置的可观测性），不重复任何已写页面。
- [外] **重复键在规范层面就是非法的**（TOML）："**Defining a key multiple times is invalid**"，
  示例给的是 `name = "Tom"` 后面再写 `name = "Pradyun"`。同理"**you cannot define a table more than once.
  Doing so is invalid**"。
- [外] **拼写不同不等于不同的键**（同上）："**bare keys and quoted keys are equivalent**"——
  `spelling = "favorite"` 与 `"spelling" = "favourite"` 是**同一个键**，重复定义即非法（示例标注 "THIS WILL NOT WORK"）。
  这条对"同一插件写了两遍、只是 id 拼法不同"是直接判据。
- [外] **错误必须是解析期（parse-time）的**：文档反复用 "must produce a parse-time error" 描述
  "先定义数组又当表用""给静态数组追加"等冲突，并在数组/表冲突处给出 "INVALID TOML DOC" 示例——
  即**加载阶段就失败**，而不是"最后一条赢"。
- [外] **配置文件的改动默认不生效**（nginx）："**Changes made in the configuration file will not be applied until
  the command to reload configuration is sent to nginx or it is restarted.**"
  也就是说：磁盘上的配置 ≠ 正在运行的配置，二者是**两份东西**。
- [外] **热重载是 fail-closed 的**（nginx）：master 收到 reload 后"**checks the syntax validity of the new
  configuration file**"；成功才起新 worker、让旧 worker 退出；"**Otherwise, the master process rolls back the
  changes and continues to work with the old configuration.**"
- [外] **重载期间两版配置并存**（nginx）：旧 worker "**stop accepting new connections and continue to service
  current requests until all such requests are serviced. After that, the old worker processes exit.**"——
  即在一段时间里，**同一进程组内两套配置同时在服务**。
- [外] **每条配置应当有名字**（ESLint）：flat config 的配置对象支持 `name` 字段，
  "**This is used in error messages and config inspector to help identify which configuration object is being
  used**"；作用域由 `files` / `ignores` / `basePath` 决定，未写 `files` 的对象会应用到任何被其它对象匹配的文件。
  换句话说：**"哪条配置生效"必须是能被指出来的**，而不是靠人脑推。

**没读到 / 不能确认的部分（如实标注）**：① ESLint 页**只读到 `files`/`ignores` 段**，

## 对照本仓（棋院）

今晚的现象：`home/profiles/desktop/cordis.patch.yml` 里 **`dsh-gokifu-longmemory` 出现两次**
（id 分别是 `kifu-longmemory` 与 `dsh-gokifu-longmemory`），其中一条写着 **`disabled: true`**；
而宿主 **pid 10096 是在这份 patch 写入之后才启动的**，却仍在注入（心跳 13350 行、inject=468）。
**配置说禁用、运行时在跑** —— 而且因为"重启后会读哪一条"取决于加载顺序，**下次重启的行为是未知的**。

| 外部规范 | 我们的现状 | 判断 |
|---|---|---|
| 重复键 **parse-time 直接报错**（TOML） | 同一插件两条、id 拼法不同，**没报错** | ⛔ **必须补**：加载期归一见名后冲突即**报错**，不许 last-wins |
| **bare 与 quoted key 等价**（TOML） | `kifu-longmemory` 与 `dsh-gokifu-longmemory` 视为两个插件 | ⛔ **必须补**：短名/全名/带 scope 前缀名要**归一后比较**，否则"同一个插件"能写两遍 |
| 配置改动**不自动生效**（nginx） | 我们默认"改了文件就生效"，且不打印生效版本 | ⛔ **必须补**：区分"磁盘配置"与"生效配置"，并给出可观测证据 |
| 重载 **fail-closed + 回滚**（nginx） | 坏配置可能半应用（写了就生效） | ✅ 可借：校验失败**保持旧配置**并报错，绝不部分应用 |
| 重载**窗口两版并存**（nginx） | 我们没写"重载期间行为"的契约 | ✅ 可借：契约里明确"重载期间的请求可能走旧配置"，别把它当 bug |
| 每条配置**有 name**（ESLint） | 只有 id，且 id 有别名 | ✅ 可借：`name` + **生效配置哈希**一起打印 |

**如果重来，应该怎么设计（机械判据，全部可在加载期跑）**：

1. **唯一性**：同一 `name`（归一后：小写、去 `dsh-gokifu-` 前缀、去空白）**只允许一条**；
   重复 ⇒ **加载失败并打印两条的 id 与行号**（TOML 的 parse-time 语义）。
2. **启用态单一真相**：`disabled` 与 `enabled` **二选一**，同时出现 ⇒ 报错；两者都不写 ⇒ 默认值**写进契约**（例如默认启用），
   并且**只认一个字段**，另一个即使出现也报错而不是被忽略。
3. **生效配置哈希**：启动时打印 `configSha256` + 每条的 `name` + 来源文件；把它写进**心跳**，
   下次启动/巡逻比对，不一致 ⇒ 显式告警（"文件改了但没生效"或"生效的不是磁盘上那份"）。
4. **`--print-effective-config`**：任何时刻能回答"我现在按哪份配置在跑"，而不是靠读文件猜。
5. **重载 fail-closed**：新配置语法/语义校验失败 ⇒ **保留旧配置**并报错退出重载；
   成功则按 nginx 的形状定义"旧 worker 服务完再退"，并把这段窗口写进契约。
6. **漂移检测进验收**：把"配置哈希 == 运行时哈希"做成一条可断言（与 44 篇的"核身份不核数量"同一条纪律——
   这里核的是**配置的身份**，不是"文件存在"这个数量）。

**明确不借的一点**：**不借"重启一定生效"的侥幸**。nginx 的窗口与回滚说明：**生效是有时点的、可回滚的、可并存的状态**，
把它当成"写下去就对了"正是今晚这条问题的根。含混的重启语义只会把问题推到下一次启动才暴露。

## 两条可复用结论

1. **配置的真相只能有一份**：任何"两处都写"的形态（重复 id、`disabled`+`enabled` 并存、短名与全名混用）都会让
   运行时行为取决于**加载顺序**，而加载顺序正是不可复现的根。规范层面的解法只有一条：**归一后判重，冲突即报错**。
2. **"配置说 X、运行时 Y"不是玄学，是缺一条可观测断言**：只要启动时打印生效配置哈希、并把它写进心跳，
   下一次就能立刻发现漂移——**而不是等到行为异常才发现配置从未生效**。

## 结论

无需改机制（我们的热重载本来就走设置 UI 串行 + 回滚）；可落地的是**把配置面收成单点**：
归一判重、`disabled`/`enabled` 二选一、启动打印 `configSha256` 与 `name`、`--print-effective-config`、
重载 fail-closed、把"配置哈希 == 运行时哈希"做成一条验收。
今晚的 13350 行心跳正好证明：**运行时一直在回答"我在跑"，却没人问过"你按哪份配置在跑"**。
