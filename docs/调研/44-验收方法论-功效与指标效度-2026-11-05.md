# 验收是实验：误差棒、聚类与裁判偏差（2026-11-05 采集）

- 来源：两篇一手论文（访问日期 **2026-11-05**）：
  [arXiv:2411.00640](https://arxiv.org/abs/2411.00640) *Adding Error Bars to Evals*（Evan Miller，Anthropic；2024-11-01，14 页；
  [HTML](https://arxiv.org/html/2411.00640v1) 已读 §1–§3）；
  [arXiv:2306.05685](https://arxiv.org/abs/2306.05685) *Judging LLM-as-a-Judge with MT-Bench and Chatbot Arena*
  （Zheng 等 13 人；v4 2023-12-24；NeurIPS 2023 Datasets & Benchmarks；读的是摘要页）。
- **范围声明**：42 篇是"检索 vs 利用"的 3×3 诊断（一个具体评测实验），34/22/33 是各自的基准与失效现象；
  本篇是**评测方法论**（统计功效、聚类、裁判偏差、指标效度），与那四篇的页面不重复。
- [外] **核心命题：评测就是实验**。"Fundamentally, evaluations are experiments; but the literature on evaluations
  has largely ignored the literature from other sciences on experiment analysis and planning."
  做法是把评测题看作从**未见的超总体**（super-population）里抽出的样本——所以分数是**估计值**，
  必须给误差棒，而不是一个光秃秃的数字。
- [外] **两种分析框架**：§2.1 **独立题**（每题互不影响）与 §2.2 **聚类题**（clustered questions）——
  当多道题共享同一段上下文/同一会话时，它们不是独立样本，必须用**聚类标准误**（附录 A 给了推导）。
  这意味着：把同一组的 N 行当成 N 个独立样本，会**低估**方差、高估置信度。
- [外] **方差缩减的技巧与反直觉**：§3 给了三种——重采样（resampling）、next-token 概率、以及
  "**Don't touch the thermostat!**"。最后一条的例子很硬：把采样温度从 T=1 降到 T=0 看似"去掉随机性"，
  但在单 token 二值题里，最小方差反而从 **1/12 升到 1/4**（uniform 被"取整"成 Bernoulli），
  即"**降低温度可能反而把方差放大三倍**"。
- [外] **比较两个系统：配对分析比非配对强**（§4.1 unpaired / §4.2 paired）——配对是逐题（逐组）算差，
  方差小得多；对比"两个独立均值"会浪费掉题目的对应关系。
- [外] **先规划再跑：功效分析**（§5 + 附录 B 的样本量公式、附录 C 的**聚类校正版**样本量公式）——
  即"要检出多大的差异，需要多少题/多少组"应当在开跑前算出来，而不是跑完再说"看起来差不多"。
- [外] **LLM 当裁判的已知偏差**（MT-Bench 摘要）：**位置偏差（position）、冗长偏差（verbosity）、
  自我增强偏差（self-enhancement）**，以及**推理能力有限**；论文还给出缓解办法。
  其结论是"像 GPT-4 这样的强裁判能达到 **over 80%** 与人类偏好一致，**与人类彼此之间的一致率同量级**"——
  但这句话成立的前提是**偏差被测量并缓解**，而不是"裁判说对就对"。
- [外] **它的公开资产规模**：MT-bench 多轮题集、**3K 专家投票**、**30K 带人类偏好的对话**——
  也就是说，"裁判可信"这件事本身是靠**独立的人工标注**校验出来的。

## 对照本仓（棋院）

今晚的坑很具体：**四条验收口径里没有任何一条检查"成员仍在库里"**，所以合并后
**31 行内容丢失 / 14 组**照样全绿——口径测的是"行数"，不是"这一行还是原来那行"。
这正是 Miller 说的"分数是估计值、要先想清楚它在估什么"，也是 MT-Bench 说的"指标会偏"。

| 外部方法论 | 我们的现状 | 判断 |
|---|---|---|
| 聚类题必须用**聚类标准误**（同一上下文下的多题不是独立样本） | 我们的"可折组 ≥10"正是在数**组**；但四条口径里有的在数**行** | ✅ **同向**；今晚的坑就是"把 14 组摊成 31 行"当独立样本 |
| 分数是**超总体估计**，要给误差棒 | 我们已用 **Wilson 下界**（门槛 0.7）而不是点估计 | ✅ **已经对上了**：区间下界比"过 70%"这种单点阈值更抗小样本 |
| **先做功效分析再跑**（要多少组才检出差异） | "≥10 组"是**拍的**，没有算过"要检出 5 个点差异需要多少组" | ⚠ **还差**：应该像附录 C 那样按聚类校正版公式反推组数 |
| **配对分析**比非配对强 | 我们换逻辑前后比的是两个**独立均值** | ⚠ **还差**：同一批组跑 A/B 应逐组配对（同一组前后差值） |
| 方差"旋钮"别乱动（降温度反而升方差） | 验收参数（阈值、条数上限）随手调 | ⚠ 要记：**改口径参数会改变方差**，不同版本的通过率不可直接比 |
| 裁判有**位置/冗长/自我增强**偏差 | 本仓不使用 LLM 裁判，判定全是可机械复算的计数与身份比对 | ✅ **结构上避开了**；但代价是"看起来对"的语义问题我们测不到 |
| 裁判可信靠**独立人工校验**（3K 投票/30K 对话） | 我们的"人工"就是主人纠错与审计 | ⚠ 还差：**没有固定的抽样复核流程**（谁、抽多少、多久一次） |

**今晚的坑 → 对应哪条方法论**：它不是"样本太小"，而是**指标不忠**（unfaithful metric）——
口径声称测"合流没有丢东西"，实际只测了"行数没变少"。这是 Goodhart 的经典形状：
**口径成为优化目标，系统就会学会在一行很长的空壳上"通过"**。

**我们的补救，对照外部方法论**：

| 补救 | 对应 |
|---|---|
| **Wilson 下界 0.7**（不用点估计） | Miller 的"误差棒/区间"；小样本下比点阈值稳 |
| **可折组 ≥10** | Miller 的"聚类"：组是聚类单位，先保证**组数**够，再看组内行 |
| **② 无组时 fail-closed**（没有可折组就判失败，不判通过） | 统计上就是"**不可估计就不声称**"——与我们的注入纪律（无源不入）同源 |
| 新加"**成员仍在库里**"这条不变量 | 从"数数量"升级为"**核身份**"：逐条比对成员 id / 内容哈希，而不只是 count |

**还差什么（要写进下一版验收）**：

1. **反例集覆盖度**：现在只有"内容丢失"一类反例；仍缺——跨作用域泄漏、时间戳被回写、
   合并后成员不可达（42 篇那条）、覆盖后旧条仍被注入。**每类失效都要有一条专门构造的反例**，否则口径再严也只防一种病。
2. **配对而非独立**：改动前后应在**同一批组**上逐组比，报配对差值与区间；独立均值的比较在小样本上会掩盖效果。
3. **功效反推组数**：给定"想检出 5 个点的下界差"，用聚类校正公式算需要多少组/多少行，而不是"≥10 就够"。
4. **口径变更要登记**：阈值、上限、分母任何一项变了，历史通过率就不可比——应像数据契约一样版本化。
5. **抽样复核**：固定"每次验收抽 N 组人工复核"，给裁判（人）留出可被推翻的空间。

## 两条可复用结论

1. **验收必须"先规划、再分析、最后才报单点"**：没有区间的"50% 通过"没有意义；
   区间下界 + 组数下限，才是能扛住小样本的口径。
2. **指标必须核身份，不能只核数量**：数量型口径天然可被"空壳"刷过（31 行丢内容仍然绿）；
   每条口径都要能回答"这条记录**还是原来那条**吗"，而不只是"还有没有一条"。

## 结论

无机制需照搬（我们不用 LLM 裁判、不做向量），可落地的是**把验收当实验来设计**：
区间下界（已有）、组数下限（已有）、**配对比较（缺）**、**功效反推组数（缺）**、**每类失效一条反例（缺）**、
**口径版本化（缺）**。
今晚的 31 行 / 14 组正好证明了一件事：**验收的自欺不需要恶意，只需要把"数量"当成"身份"**。
