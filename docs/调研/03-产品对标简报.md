## 0 · 方法与限制（先说清楚，免得把结论当传言）

**工具状况（必须记录）**：`web_search` 在本机不可用 —— 调用返回 `DeepSeek returned no web_search_tool_result blocks`（搜索端点在 Plugins > Built-in plugin settings > Web search 里配置，不该由我改）；`web_fetch` 对所有目标域名返回 `URL hostname ... resolves to a non-public IP address`（本机 hosts 被 Steam++/S302 段整体指向 `127.0.0.1`，本地反代在 443 上，属 SSRF 防护的正常拒绝）。

**替代手段（等价于「查官方仓库」）**：
1. `curl` 经本机反代直接取 **raw.githubusercontent.com** 的 README/设计文档原文；
2. GitHub REST API（`api.github.com`，官方数据源）核实仓库归属、描述、star、默认分支；
3. `arxiv.org/abs/*` 与 `export.arxiv.org/api/query` 核实论文标题、编号、摘要原文；
4. 官方文档站（`hindsight.vectorize.io`、`docs.openviking.ai`、`docs.mem0.ai`、`docs.letta.com`）抓正文后去 HTML 标签。

**核实纪律**：每个对象的机制描述，至少一条来自其官方仓库或官方文档；每个数字都带出处 URL；官方没说的不补，改为 `[查不到]`。论文里的数字标 `[官方论文]`，产品 README 的自报数字标 `[官方自报]`（**自报 ≠ 独立复现**）。Hindsight 明确写了「其他厂商分数为自报；Hindsight 数据由 Virginia Tech Sanghani Center 与 Washington Post 独立复现」——这条本身值得记。

## 2 · 逐系统核实（每项 7 问）

### 2.1 Hindsight（vectorize-io）

- 仓库：https://github.com/vectorize-io/hindsight （MIT，Python；2026-11-02 经 GitHub API 核实 star 57,572）
- 文档：https://hindsight.vectorize.io/developer/retrieval ｜ https://hindsight.vectorize.io/developer/observations ｜ https://hindsight.vectorize.io/developer/mental-models ｜ https://hindsight.vectorize.io/best-practices
- 论文：https://arxiv.org/abs/2512.12818 （《Hindsight is 20/20: Building Agent Memory that Retains, Recalls, and Reflects》）

| 问题 | 官方说法 |
|---|---|
| Q1 数据模型 | 四类：「世界事实」(world facts)、「经历」(experiences)、「观察」(observations，多记忆合成的有证据信念)、「心智模型」(mental models，对某问题的常驻答案)；另有 knowledge pages（文件夹组织的活文档，可投影成 markdown）。记忆住在 **bank** 里，README 原话「Isolation is strict: no cross-bank leakage」。层级靠 **tags**：`user:`/`session:`/`team:`/`topic:`/`scope:`，以及 `observation_scopes`（combined / per_tag / all_combinations / 自定义组合）`[官方]` |
| Q2 写入路径 | `retain()` 内 **LLM 抽取**关键事实、时间、实体、关系 → 归一化为规范实体、时间序列与索引。写入后**后台自动整合**成 observations：每条带**支持证据的原文引用**与 **proof count**，新证据到达时**「refined rather than overwritten」**。近重复用 `HINDSIGHT_API_CONSOLIDATION_DEDUP_THRESHOLD`（默认 **0.97 余弦**）触发，且**读双方全文**后决定 merge/keep，好让「数字、否定、命名实体、语言」有差异的观察不被误并；只在**同 tag 作用域内**比对 `[官方]` |
| Q3 检索路径 | 四路并行：语义向量、BM25 关键词、图遍历（实体/时间/因果链）、时间窗过滤 → **RRF**（k=60，四路**等权**，只用名次不用原始分）→ **cross-encoder 重排**（先截到 `RERANKER_MAX_CANDIDATES`，默认 300）→ **token 预算装填**（只有正文计费、元数据免费；放不下的整条跳过继续装；全放不下时至少返回 top-1）。预算可固定或自适应 `recall_budget = clamp(max_tokens × ratio, min, max)` `[官方]` |
| Q4 遗忘与整合 | **未见时间衰减/删除机制**（本次抓取的 README + retrieval/observations/mental-models/best-practices 四页均未提及）；整合 = 观察合并 + 心智模型「按作用域」重建（有新知识落地或按计划触发），并保存**每一版历史**。心智模型带 **freshness 信号**：落后时仍展示，但**不再短路检索**，要求 agent 回下层核对 `[官方]` |
| Q5 过拟合/泛化 | 见 §3（重点节） |
| Q6 量化 | AMB 站：LongMemEval **94.6%**、LoCoMo **92%**、PersonaMem 32K 86.6%、BEAM 100K 75% / 1M 73.9% / 10M 64.1%（https://benchmarks.hindsight.vectorize.io/ ）`[官方自报，声称经 VT/WaPo 复现]`；论文：开源 20B 骨干下整体准确率 **39% → 83.6%**（对比同骨干 full-context），换更大骨干到 **91.4% LME**、**89.61% LoCoMo**（对比最强开源前作 75.78%）`[官方论文]` |
| Q7 会话级 vs 长期 | **没有**「单会话压缩产物 → 长期层」的显式二次蒸馏。它的分层是「原始事实 → 观察 → 心智模型」，跨会话但不以会话为单位；会话只是一个 tag `[查不到 会话压缩产物]` |

### 2.2 OpenViking（volcengine）

- 仓库：https://github.com/volcengine/OpenViking （描述「Self-evolving Context Database for AI Agents. Unify Agent Memory, Knowledge RAG and Skills.」；2026-11-02 star 41,296）
- 文档：https://docs.openviking.ai/en/concepts/03-context-layers ｜ https://docs.openviking.ai/en/concepts/08-session ｜ https://docs.openviking.ai/en/concepts/07-retrieval ｜ https://docs.openviking.ai/en/concepts/02-context-types

| 问题 | 官方说法 |
|---|---|
| Q1 数据模型 | **虚拟文件系统** `viking://`：`resources/`（知识）、`user/{id}/memories/`（记忆）、`skills/`、`peers/`。每个目录有 **L0 abstract（默认 256 字符，供向量检索）/ L1 overview（默认 4000 字符，供 rerank 与导航）/ L2 原文（按需读）**。记忆类型固定：profile / preferences / entities / events / identity / soul / cases / trajectories / experiences（可自定义），另有 Beta 的 **Rules**（强制约束，生命周期 active/paused/archived）`[官方]` |
| Q2 写入路径 | `session.commit()` **两阶段**：请求内归档（messages.jsonl + 保留策略）→ 后台 ① LLM 生成结构化摘要写 `.abstract.md`/`.overview.md` ② 抽取长期记忆 ③ 写 **`memory_diff.json`（记忆变更审计日志）** ④ `.done`。抽取**以既有记忆为输入**，允许「merge or edit existing files, create files, or delete them」，并受 **memory schema、写权限、输出校验**约束；被校验拦下的操作进 `skipped_operations` `[官方]` |
| Q3 检索路径 | 官方文档直白：**全局向量检索 + 可选 rerank**；`find()` 直查并可用 `target_uri` 限定子树；`search()` 先做 **意图分析**（LLM 产出 0..n 个 TypedQuery，输入是会话摘要 + 最近 5 条消息 + 当前 query）。文档同时说明：`limit` 对**每个**规划查询生效，合并结果可能超出且**当前不保证跨查询去重**。**未文档化 RRF/多路融合** `[官方]` `[查不到 多路融合]` |
| Q4 遗忘与整合 | 未见衰减/热度模型；整合靠「抽取时的 update/merge/delete」+ 目录摘要重算。`commit` 有保留参数（可只归档部分、留最近消息/轮次）`[官方]` |
| Q5 过拟合/泛化 | 见 §3 |
| Q6 量化 | README 自报（0.3.22，Doubao 2.0 Pro + Doubao-embedding-vision-251215）：LoCoMo 上 OpenClaw 24.20%→**82.08%**、Hermes 33.38%→**82.86%**、Claude Code 57.21%→**80.32%**；输入 token **−34.3~91.0%**，查询延迟 **−58.45~66.10%**；tau2-bench 任务成功率零售 **+6.87pp**、航空 **+11.87pp**（https://blog.openviking.ai/post/openviking-benchmark-results/ ）`[官方自报]` |
| Q7 会话级 vs 长期 | **是，九套里最显式**：一次 commit 就产出「归档 + 单会话摘要（L0/L1）」这一**压缩产物**，再由后台抽取写进长期记忆；另有 `ov compile` 把素材编译成 wiki / 知识图谱 / 报告 `[官方]` |

### 2.3 MemOS（MemTensor）

- 仓库：https://github.com/MemTensor/MemOS ｜ 论文：https://arxiv.org/abs/2507.03724 （《MemOS: A Memory OS for AI System》）
- 本地插件设计文档（关键）：https://github.com/MemTensor/MemOS/blob/main/apps/memos-local-plugin/ARCHITECTURE.md ｜ L1: `core/memory/l1/README.md` ｜ L2: `core/memory/l2/README.md` ｜ L3: `core/memory/l3/README.md`

| 问题 | 官方说法 |
|---|---|
| Q1 数据模型 | 主线是 **MemCube**（可组合记忆立方：跨用户/项目/Agent 隔离、受控共享、动态组合）+ 图结构记忆 + 多模态（文本/图像/工具轨迹/人设）。本地插件给出四层：**L1 = 步级 grounded trace**，元组 `(s_t, a_t, o_t, ρ_t, r_t)`；**L2 = 策略（policy）**；**L3 = 世界模型** `f^(3) = (ℰ, ℐ, C, {f^(2)})`（环境拓扑 / 推断规则 / 禁忌 / 引用它的 L2 集合）；再上是 **Skill 结晶** `[官方]` |
| Q2 写入路径 | 异步 **MemScheduler** 摄取。L2 只由**「已结算、带 reward 的 episode」**触发（`reward.updated` 事件）→ 关联既有策略 → 未匹配的进**候选池**（按 pattern signature 分桶 + TTL）→ 桶内**不同 episode ≥ `minEpisodesForInduction`** 才 LLM 诱导 → 草稿校验后插为 **candidate** → 计算 **gain + status**。L3 更严：只吃 **active 且 gain ≥ θ、support ≥ σ** 的 L2，先聚类，再按 domain tag 做 **cooldown**，最后 `chooseMergeTarget` 决定合并（提置信度）还是新建 `[官方]` |
| Q3 检索路径 | 混合检索 **FTS5 + 向量**；分层召回 **Tier-1（技能）/ Tier-2（trace）/ Tier-3**。更关键的是 **注入时机**：ARCHITECTURE 明写「V7 spec is explicit about **injection timing, not quantity**」，并列出 turn-start / 工具调用 / 子代理启动 / 决策修复 各自允许的 tier；**明确拒绝在 `onToolCall`/`onToolResult` 里偷偷注入**（「never mid-decision」）`[官方]` |
| Q4 遗忘与整合 | 策略有 **candidate/active/retired** 状态、gain 与 support、cooldown、候选池 TTL；世界模型有置信度提升与合并。未见时间衰减公式 `[官方/查不到衰减]` |
| Q5 过拟合/泛化 | 见 §3（这是九套里**唯一把「泛化」写进算法门槛**的） |
| Q6 量化 | README 自报：LoCoMo **88.83**、LongMemEval **89.20**、PersonaMem v2 40.58、HaluMem 80.91、BEAM-10M **56.75**、GDPVal 62.07、LiveCodeBench 64.96、OmniMath 61.00、**SWE-Bench 38.46**、BrowseComp-Plus 23.85；OpenClaw 五任务平均完成率 36.63%→**50.87%**（评测集 https://github.com/MemTensor/OmniMemEval ）`[官方自报]` |
| Q7 会话级 vs 长期 | **是，且是四级**：L1（每步 trace）→ L2（跨任务策略，需多 episode）→ L3（跨任务世界模型）→ Skill。每一级都有独立触发条件与门槛，**单个 episode 永远不产生 L3 行**（L3 README 原话）`[官方]` |

### 2.4 SimpleMem（aiming-lab）

- 仓库：https://github.com/aiming-lab/SimpleMem ｜ 论文：https://arxiv.org/abs/2601.02553 （《SimpleMem: Efficient Lifelong Memory for LLM Agents》，ICML'26）
- 设计文档：https://github.com/aiming-lab/SimpleMem/blob/main/docs/text-memory.md ｜ 多模态篇：https://arxiv.org/abs/2604.01007

| 问题 | 官方说法 |
|---|---|
| Q1 数据模型 | 记忆单元 = **自包含事实**（消解指代 + 绝对时间戳），每个单元三视图索引：**稠密 1024 维 / BM25 稀疏 / 符号元数据（时间、实体、人物）**。无 user/project 层级，只有「当前会话作用域」`[官方]` |
| Q2 写入路径 | 三段流水线：① **语义结构化压缩**（LLM 生成时的隐式语义密度门控，滤冗余）② **在线语义合成（Online Semantic Synthesis）**：**写时**把相关单元合成更高层抽象，去冗余 ③ 检索规划。注意官方强调「unlike traditional systems that rely on asynchronous background maintenance」——**它把整合放在写路径而不是后台** `[官方]` |
| Q3 检索路径 | **意图感知检索规划**：LLM 推断潜在搜索意图，动态决定检索**范围与深度**，组装紧凑上下文；多模态版是 FAISS + BM25 混合 + **金字塔式 token 预算扩张**。`[官方]` |
| Q4 遗忘与整合 | 写时压缩 + 会话内合成就等于整合；**未见**时间衰减、访问频次、归档策略 `[查不到]` |
| Q5 过拟合/泛化 | 见 §3（有一个很值得抄的「Guard + 回滚」） |
| Q6 量化 | 论文/README：LoCoMo 上平均 **F1 +26.4%**，推理期 token 约 **1/30**；EvolveMem 相对最强基线 **+25.7% 相对提升**，且「evolved configurations transfer positively across benchmarks」；Omni-SimpleMem 在 LoCoMo 与 Mem-Gallery 达 SOTA `[官方自报]` |
| Q7 会话级 vs 长期 | **部分**：Online Semantic Synthesis 是**会话内**合成，属于「单会话压缩」，但**没有**再往跨会话长期层的第二级蒸馏 `[官方]` |

### 2.5 mem0

- 仓库：https://github.com/mem0ai/mem0 ｜ 论文：https://arxiv.org/abs/2504.19413 ｜ 文档：https://docs.mem0.ai/core-concepts/memory-types ｜ v3 迁移：https://docs.mem0.ai/migration/oss-v2-to-v3

| 问题 | 官方说法 |
|---|---|
| Q1 数据模型 | 存的是**抽取后的事实**（默认不存原文逐字稿），带元数据、embedding、可选实体关系。作用域是**三个 ID 维度**：`user_id` / `agent_id` / `run_id`（+ metadata）——是隔离维度，**不是层级**；没有任何 session→project→global 的继承关系 `[官方]` |
| Q2 写入路径 | v3（2026-04）**单次 LLM 调用、ADD-only**，官方原话「**no UPDATE/DELETE. Memories accumulate; nothing is overwritten**」；agent 确认的动作也作为一等事实入库；新增实体抽取与链接。图记忆从 OSS 移除，改为平台内置 `[官方]` |
| Q3 检索路径 | **多信号混合**：语义 + BM25 + 实体匹配并行打分后融合，再加**时间推理**（判断问的是当前状态、过去事件还是将来计划）。README 标注检索预算 top_200、单次调用（no agentic loops）`[官方]` |
| Q4 遗忘与整合 | **没有遗忘**；「累积」就是设计。整合只有实体链接与（平台版）图 `[官方]` |
| Q5 过拟合/泛化 | 见 §3（反面教材：ADD-only 消除了「LLM 改写漂移」，但把「陈旧」全推给检索期时间推理） |
| Q6 量化 | 平台版：LoCoMo **92.5**（旧 71.4）、LongMemEval **94.4**（旧 67.8）、BEAM-1M 64.1、BEAM-10M 48.6；分别耗 **7.0K / 6.8K / 6.7K / 6.9K** token，p50 延迟 0.88–1.09s；README 明示「scores reflect Mem0's managed platform… open-source users should expect directionally similar gains but not identical numbers」。OSS 迁移文档口径：LoCoMo 71.4→**91.6**、LongMemEval 67.8→**93.4**，抽取延迟约减半 `[官方自报]` |
| Q7 会话级 vs 长期 | **无**。`run_id` 能圈出一次运行，但没有「会话产物 → 长期层」的蒸馏步骤 `[查不到]` |

### 2.6 Letta / MemGPT

- 仓库：https://github.com/letta-ai/letta （当前源码指向 `letta-ai/letta-code`，旧 V1 服务在 `archive` 分支）
- 文档：https://docs.letta.com/letta-code/memory ｜ https://docs.letta.com/letta-code/memfs ｜ MemGPT 论文：https://arxiv.org/abs/2310.08560

| 问题 | 官方说法 |
|---|---|
| Q1 数据模型 | **MemFS**：git 版本化的记忆文件系统，记忆**按路径寻址**（label 就是路径，如 `persona.md`、`human.md`）。根目录文件**每轮都进系统提示**；带自己 `MEMORY.md` 索引的**子目录默认不进上下文**，靠索引当路标按需读。`skills/` 也在 MemFS 里 `[官方]` |
| Q2 写入路径 | **Agent 自己决定**：文档原话「The agent decides where the lesson belongs and commits the update to MemFS」；也可 `/remember` 显式教。每次编辑都是 git commit（有版本历史与冲突解决）。**dreaming** 用后台子代理复盘最近会话、整合经验；可选「**Agent reviews before applying**」再开一段后台会话复核提案 `[官方]` |
| Q3 检索路径 | **默认没有向量/语义索引**（文档明说），靠文件搜索与读工具；要关键词/语义检索得装 `@letta-ai/memfs-search`（语义需 QMD 索引）。会话历史检索是另一套（`letta messages search`）`[官方]` |
| Q4 遗忘与整合 | dreaming 做整合；`/doctor` **审计「placement, duplication, and system-prompt token usage」**，专门治「记忆层级漂移或膨胀过大」；重组前会**备份整个仓库**再拆文件/去重/重排 `[官方]` |

| Q7 会话级 vs 长期 | dreaming 是**跨会话的后台整合**，但没有「单会话压缩产物」这一中间层 `[查不到]` |

### 2.7 Zep / Graphiti

- 仓库：https://github.com/getzep/graphiti ｜ 论文：https://arxiv.org/abs/2501.13956 （《Zep: A Temporal Knowledge Graph Architecture for Agent Memory》）｜ 产品：https://www.getzep.com

| 问题 | 官方说法 |
|---|---|
| Q1 数据模型 | **context graph**：实体节点（摘要**随时间演化**）+ 事实边（三元组，带**有效期窗口**）+ **episode**（原始数据，一切派生事实的溯源）+ 自定义本体（Pydantic）。README 反复强调「Everything traces back to **episodes** — the raw data that produced it」`[官方]` |
| Q2 写入路径 | 从 episode 增量建图（非批处理重算）；LLM 抽实体/边；**自动事实失效**：信息变化时**旧事实被 invalidate 而不是 delete**，保留时间史；本体可「prescribed（Pydantic 预定义）」或「learned（从数据涌现）」`[官方]` |
| Q3 检索路径 | **混合**：语义 embedding + 关键词 BM25 + 图遍历，README 明说「without reliance on LLM summarization」；Zep 侧宣称 **sub-200ms at scale** `[官方]` |
| Q4 遗忘与整合 | 失效标注 + 实体摘要持续更新 + 社区摘要（对比表提到 communities）；**不删除**，靠时间轴区分「现在为真」与「曾经为真」 `[官方]` |
| Q5 过拟合/泛化 | 见 §3（冲突处理是九套里最机械的） |
| Q6 量化 | 论文：DMR **94.8% vs MemGPT 93.4%**；LongMemEval 准确率最高 **+18.5%**，同时响应延迟 **−90%** `[官方论文]` |
| Q7 会话级 vs 长期 | 有「episode（原始流）→ 派生事实」的蒸馏，但 episode 不等于「会话压缩产物」，**不是**按会话封装的中间层 `[查不到]` |

### 2.8 A-MEM

- 仓库：https://github.com/agiresearch/A-mem ｜ 论文：https://arxiv.org/abs/2502.12110 （《A-MEM: Agentic Memory for LLM Agents》）

| 问题 | 官方说法 |
|---|---|
| Q1 数据模型 | **Zettelkasten 式笔记**：每条记忆生成结构化笔记（**上下文描述、关键词、标签**），互建链接形成知识网络；底层 ChromaDB。**无层级** `[官方]` |

### 2.9 MemoryOS

- 仓库：https://github.com/BAI-LAB/MemoryOS （EMNLP 2025 Oral，描述「memory operating system for personalized AI agents」）｜ 论文：https://arxiv.org/abs/2506.06326 （《Memory OS of AI Agent》）

| 问题 | 官方说法 |
|---|---|
| Q1 数据模型 | 三层存储单元：**短期记忆（QA 对）/ 中期记忆（对话链段 segment）/ 长期个人记忆（用户画像 + 用户知识 + Agent 知识）**。这是九套里**层级最像操作系统**的（短/中/长期） `[官方]` |
| Q2 写入路径 | `Updater`：短期满 → 按**对话链 FIFO** 合并成中期段；中期段累积 **heat**，超阈值 → 分析并抽取画像洞察、用户事实、Agent 知识写入长期。**无置信度、无冲突检测** `[官方]` |
| Q3 检索路径 | `Retriever` 一次性取四类：短期历史 + 中期段 + 用户画像/知识 + Agent 知识库，一起拼进 prompt。**无打分融合、无预算分配**（至少 README 未描述）`[官方]` |
| Q4 遗忘与整合 | **heat = 访问频次 + 交互长度**（README 原话「based on factors like visit frequency and interaction length」），超阈值提升；中期用「分段页」组织。代码默认 `mid_term_heat_threshold=5`，示例配置里出现 13.0 `[官方]` |
| Q5 过拟合/泛化 | 见 §3（**没有**任何过拟合讨论，是「纯晋升型」系统的典型） |
| Q6 量化 | 论文：LoCoMo 上 **F1 +49.11%**、**BLEU +46.18%** `[官方论文]` |
| Q7 会话级 vs 长期 | 三层晋升（短→中→长）是一种蒸馏，但按**对话链/热度**切，不按「会话产物」切 `[官方]` |

## 3 · 重点节：过拟合 / 泛化 —— 九套系统到底防到了什么程度

> 结论先行：**没有任何一套产品用「过拟合」这个词**。它们用的是另一套词：`evidence vs inference`、`stale`、`contradiction`、`drift`、`generalise across tasks`、`negative transfer`。**没有一套做「留出会话评测」**；唯一有「回滚闸」的是 SimpleMem 的 EvolveMem，而且它回滚的是**检索配置**，不是记忆内容。

### 3.1 谁明确讨论了「记忆导致行为僵化/错误泛化」

| 系统 | 是否显式讨论 | 原文/出处要点 |
|---|---|---|
| **Hindsight** | **是（最接近）** | 论文摘要直接点名现有系统的病：「still **blur the line between evidence and inference**」；产品侧配套机制：观察带 **proof count + 原文引用**、新证据「**refined rather than overwritten**」、心智模型带 **freshness 信号**（落后就不再短路检索，要求回下层核对）。best-practices 里明确的反模式：`tags_match="any"` 会**跨用户泄漏**、给「关于用户的一切」建一个心智模型 = **低准确率 + 难作用域 + 难刷新**、「Match scope to how often you expect patterns to change」`[官方]` https://hindsight.vectorize.io/best-practices |
| **MemOS** | **是（唯一写进算法门槛的）** | L2 文档原话「reusable **L2 policies** … that **generalise across tasks**」；L3 文档原话「The L3 pipeline is deliberately **cross-task**. **A single episode never produces an L3 row**; we wait until enough high-quality L2 policies exist to **generalise safely**」。门槛：`minEpisodesForInduction` 个**不同** episode、gain ≥ θ、support ≥ σ、cooldown、候选池 TTL `[官方]` |
| **SimpleMem** | **是（但是检索配置层面）** | EvolveMem 闭式循环 **Evaluate → Diagnose → Propose → Guard → Repeat**，「guarded by **automatic rollback on regression**」，且声称演化出的配置能**跨基准正向迁移** `[官方]` |
| **Zep/Graphiti** | **否（但机制上等价）** | 未讨论僵化；但「**自动事实失效 + 保留时间史**」在机制上就是「不许把旧事实当现在为真」，且明确把 contradiction handling 与 GraphRAG 的「LLM 摘要判断」对立 `[官方]` |
| **Letta** | **否（但有审计工具）** | `/doctor` 专治「记忆层级漂流或膨胀过大」，审计**放置、重复、系统提示 token 占用**；dreaming 可加一道「**agent 复核提案**」 `[官方]` |
| **mem0** | **否（且方向相反）** | 没讨论过拟合；v3 的设计选择是「**什么都不覆盖**」，把「哪条为真」推迟到检索期的时间推理 `[官方]` |
| **OpenViking** | **否** | 有 `memory_policy` 白名单、schema/写权限/输出校验、`skipped_operations`、`memory_diff.json` 审计，但**没有**任何关于「记忆导致僵化」的论述 `[官方]` |
| **A-MEM** | **否** | 「记忆演化」直接改写邻居笔记的上下文表示 `[官方]` |
| **MemoryOS** | **否** | 纯热度晋升，无冲突/无失效/无审计 `[官方]` |

### 3.2 外部学术侧的说法（第三方，可作为「过拟合」的正式定义来源）

- **MCMA / 《Learning How to Remember》** https://arxiv.org/abs/2601.07470 ：原话「most existing approaches store memory in fixed representations and reuse it at **a single or implicit level of abstraction**, which **limits generalization** and often leads to **negative transfer** when distribution shift」；对策是把记忆抽象当成**可学习技能**（DPO 训练 memory copilot），并把记忆组织成**抽象层级**，按任务相似度**选择性复用**。`[第三方]`
- **《From Storage to Experience: A Survey on the Evolution of LLM Agent Memory Mechanisms》** https://arxiv.org/abs/2605.06716 ：把记忆演化分三阶段 **Storage（轨迹保存）→ Reflection（轨迹精炼）→ Experience（轨迹抽象）**，并指出领域碎片化。`[第三方]`
- 这两条正好对上本项目的「F1 单例泛化 / F5 自证污染」：**抽象层级**与**抽象来源**是同一条轴。

### 3.3 九套系统实际用到的「防僵化」手段清单（可对照本项目的六道闸）

| 手段 | 谁在用（出处） | 与本项目闸的映射 |
|---|---|---|
| 作用域隔离（硬隔离，默认不可见） | Hindsight bank + tags（`any_strict`/`all_strict`）；OpenViking 目录子树 + `memory_policy`；MemOS cube；mem0 三 ID | 闸 1 作用域（F2） |
| 证据计数（proof count / support） | Hindsight observations；MemOS support σ；Zep episode 溯源 | 闸 2 支撑门槛（F1）、闸 5 来源纪律（F5） |
| 证据必须带**原文引用**且可定位 | Hindsight「exact quotes」；Zep「everything traces back to episodes」；OpenViking `memory_diff.json` | 闸 5（本项目的 `quote` 可定位要求，与 Hindsight 同构） |
| 冲突 = 失效标注而非删除 | Zep `invalidated`；Hindsight「refined rather than overwritten」+ 保留版本 | 闸 4 只增不改（F4） |
| **禁止改写既有条目** | mem0 ADD-only（彻底）；Hindsight 也有改写（refine），故不完全等价 | 闸 4（反面参照：A-MEM 的 evolution 是改写） |
| 新鲜度/陈旧降级 | Hindsight mental model freshness（落后就**不再短路检索**）；Zep 有效期窗口 | 闸 3 有效性（F3） |
| 晋升门槛（多证据/多任务） | MemOS（不同 episode 计数 + gain/support）；MemoryOS（heat 阈值，但是热度不是证据） | 闸 2（MemOS 是唯一「跨任务才晋升」的） |
| 去重/近重复复核 | Hindsight 0.97 余弦 + 读全文再决定 merge/keep | 本项目暂无用例——**可作为「重复但不合并」的折中** |
| 审计日志（变更可回溯） | OpenViking `memory_diff.json`（adds/updates/deletes/skipped_operations）；Letta git 历史 | 支撑「每条可被反例推翻、被原件追溯」 |
| **自动回滚（回归即撤）** | SimpleMem EvolveMem `Guard` + rollback | **本项目完全没有对应物** → 最有价值的一条 |
| 上下文预算/占用审计 | Letta `/doctor`（token usage）；Hindsight token budget；MemOS「injection timing, not quantity」 | 闸 6 预算与省略（F6） |
| 拒答式写入（策略/校验拦截） | OpenViking 写权限 + 输出校验 + `skipped_operations` | 闸 5 的「无源不入」变体 |

### 3.4 第 5 节的三个硬结论

1. **「过拟合」在工业界是空白命题**：九套系统都在优化「记得更多、更准」，没有一套把「训练集涨、留出集跌」当验收指标。本项目的 `overfitGap` + 留出会话评测，**在这个赛道上是稀缺设计**，不是重复造轮子。
2. **能抄的是「晋升门槛」而不是「衰减函数」**：唯一真正防「单例泛化」的是 MemOS 的 `minEpisodesForInduction`（**不同 episode 计数**）；MemoryOS 的 heat 是**访问热度**，会把「常被检索」误当「为真」，正是本项目 F1/F4 要防的东西 —— **不要抄 heat**。
3. **回滚闸是缺口**：只有 SimpleMem 有「回归即回滚」，且只作用于检索配置。本项目的六道闸全是**准入闸**（写前拦），缺一道**事后闸**（注入后按 `memoryErrorRate` 自动降级/撤销）。

## 4 · 「会话级 → 长期层」的二次蒸馏：谁真的做了

| 系统 | 有没有中间层 | 怎么做的（官方） |
|---|---|---|
| **OpenViking** | **有，最完整** | `commit()` = 归档（messages.jsonl）+ **单会话摘要 `.abstract.md`/`.overview.md`** + 后台抽取长期记忆 + `memory_diff.json`；摘要与记忆是**两个独立产物**，摘要是 L0/L1，记忆进 `~/memories/*` `[官方]` https://docs.openviking.ai/en/concepts/08-session |
| **MemOS** | **有，但按任务而非会话** | L1 步级 trace →（reward 结算后）L2 跨任务策略 →（足够多高质量 L2 后）L3 世界模型 → Skill；每级都有独立门槛 `[官方]` |
| **MemoryOS** | **有，按对话链** | 短期满 → 中期段（FIFO）→ heat 超阈值 → 长期（画像/用户知识/Agent 知识）`[官方]` |
| **Letta** | **半个** | dreaming 后台复盘最近会话 → 整合成 MemFS 里的教训；没有「单会话压缩产物」对象 `[官方]` |
| **SimpleMem** | **半个（会话内）** | Online Semantic Synthesis 在**写时**把会话内相关单元合成抽象表示 `[官方]` |
| **Hindsight** | **无** | 分层是「事实 → 观察 → 心智模型」，不以会话为单位 `[查不到]` |
| **Zep/Graphiti** | **无** | episode 是原始流，不是压缩产物 `[查不到]` |
| **mem0** | **无** | 只有 `run_id` 这个维度 `[查不到]` |
| **A-MEM** | **无** | 直接笔记化 `[查不到]` |

**给本项目的直接含义**：本项目 `episode.l0 / l1`（≤256 / ≤4000 字符，l0 从 l1 派生）与 OpenViking 的 L0/L1 **几乎同构**，但 OpenViking 的 L0/L1 是**目录级**、本项目的 l0/l1 是**会话级**。真正的差异在**下游**：OpenViking 的摘要是「给人/给 agent 浏览的导航件」，记忆抽取**另起一路**；本项目若让 claim 从 `l1` 里抽，就会踩 F5（自证污染）—— OpenViking 的做法恰好证明了「摘要与记忆分流」是可行且被产品化的。

## 6 · 对本项目的 10 条可执行启示

> 格式：**机制（出处） → 我们怎么用 → 风险**。全部对齐 `方案.md` §6 的六道闸，不引入本项目明令禁止的东西（不做向量检索、不做压缩、不改写既有条目）。

1. **证据计数 + 原文引用（Hindsight observations）**
   → `claim.support[]` 每条带 `{episode, seq, quote}`，`counter` 同理；注入时显示「n 局支撑 / m 条反例」。与闸 2、闸 5 完全同构，可直接落地。
   → **风险**：quote 校验要真能在原件定位，否则闸 5 变成装饰；长会话里 quote 定位成本高，需要在入档时就把 `seq` 存好。

2. **「精炼而非覆盖」的失效语义（Hindsight refine / Zep invalidate-not-delete）**
   → 冲突时只写 `supersededBy` + `supersededAtSeq`，旧条目降级为 `stale`/`disputed`，**永不改 text**。这条我们已经定了（只增不改），外部有两家独立同构，可以在评审时当依据。
   → **风险**：旧条目不清空会导致注入时新旧同现，必须靠状态机在**读侧**过滤，而不是靠删。

3. **多 episode 才可晋升（MemOS `minEpisodesForInduction`）**
   → 把闸 2 的 `support≥2/≥3` 显式定义为「**不同 episode** 计数」，并额外要求「**不同 scopeKey** 不计入同一 claim 的支撑」——这是 MemOS 用 `DISTINCT episodes` 防单例泛化的直接移植。
   → **风险**：门槛常数是拍脑袋；MemOS 也没给出该常数的敏感性分析。必须用留出集校准，否则只是把 F1 换成 F1'。

4. **绝不让「摘要」当抽取源（Zep 的 episode 溯源 + 本项目 F5）**
   → 抽取输入只允许 `棋谱边 + 会话日志原始事件`；`l1` 只作为**展示/导航**，不得作为 claim 的 `support` 来源。OpenViking 把「摘要」与「记忆」做成两条并行产物（`.abstract.md` vs `memories/*`），是这条纪律的产品级旁证。
   → **风险**：如果 l1 里已经含有模型判断，而我们又允许「从 l1 找线索再回原件」，中间仍可能引入偏差；需要在 `support` 里强制写**原件定位**而非摘要定位。

5. **作用域默认不可见 + 只允许显式祖先链（Hindsight bank/tags、OpenViking 子树、MemOS cube）**
   → `scopeKey` 不匹配即不可见；祖先链只允许 `workspace → global` 一跳，且**必须在索引里显式登记**，不能靠路径前缀猜。
   → **风险**：祖先链一旦过宽就退化成 F2；Hindsight 明确警告 `tags_match="any"` 会跨用户泄漏——我们的等价错误是「scopeKey 前缀匹配」。

6. **陈旧度信号要能「短路」注入（Hindsight mental model freshness）**
   → 对 `validity.type != none` 的 claim，注入前做廉价检查；失败 → 只给**指针**（文件/commit + 「已于 X 失效」），不给断言正文。
   → **风险**：检查本身可能误判（NTFS 时间戳超前、文件被 touch）；检查失败要 fail-**降级**而不是 fail-open。

7. **变更审计日志（OpenViking `memory_diff.json`）**
   → `journal/` 记录每次**状态迁移**：`{claimId, from, to, reason: support|counter|validity|manual, evidence[], at}`；`skipped_operations` 对应我们的「被闸拦下的候选」。
   → **风险**：日志会变成第二个真相源；必须规定「journal 只追加、不能反向修 claim」，且 journal 的校验要能重放出同一状态。

8. **上下文占用审计（Letta `/doctor`）**
   → `scripts/cli.mjs doctor` 增三项机械检查：① 同 `scopeKey` 下文本高度相似的 claim 数 ② 注入预算占用分布 ③ 长期未命中（`injections=0` 且 `age > N`）的 claim 清单。
   → **风险**：「长期未命中」是**删除依据的诱惑**——按本项目纪律，它只能生成**报告**，不能自动淘汰；否则就是把「访问频次」偷换成「真值」（MemoryOS 的 heat 就是这个坑）。

9. **回归即回滚（SimpleMem EvolveMem Guard）**
   → 任何「注入策略/排序/门槛」的改动，必须在留出会话上做**配对比较**（有记忆 vs 无记忆），**留出集跌即回滚**，并把这个回滚写成脚本而不是人肉判断。
   → **风险**：留出集只有 86 个会话 / 11 张棋谱，样本小，单次波动可能误触发回滚；需要先定「最小可检测效应」，否则会来回横跳。

10. **注入时机 > 注入数量（MemOS 的 golden rule）**
    → 明确「每步 / 新会话 / 轮次收尾」各自允许注入什么，且**禁止在工具调用中途注入**；这与 `agent/pre-step` 是唯一安全写点的宿主约束天然一致。
    → **风险**：`pre-step` 是 waterfall，与压缩插件同点注入时两个替换互不代管（AGENTS.md §5.6），必须用唯一标记定位自己的消息，否则会互相覆盖。

## 7 · 一句话总结

九套系统把「记得更多、更准、更省 token」做到了工程级（LoCoMo 80–95 分区间、token 降到 1/30、延迟降 90%），但**没有一套把「记忆导致的错误泛化」当作一等问题来设计**：Hindsight 只到「证据 vs 推断」的措辞，MemOS 只到「多 episode 才诱导策略」的门槛，SimpleMem 只到「检索配置回归即回滚」。**「留出会话 + overfitGap + 注入后自动降级」这三件套，在公开产品里是空的** —— 这既是本项目的差异化，也是它必须自己造评测的原因。
