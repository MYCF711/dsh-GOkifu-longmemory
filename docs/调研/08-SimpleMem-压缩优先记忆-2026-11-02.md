# SimpleMem（及 Omni / EvolveMem）：压缩优先的长期记忆（2026-11-02 采集）

- 来源：[github.com/aiming-lab/SimpleMem](https://github.com/aiming-lab/SimpleMem)（README，2026-11-02）；
  论文 [arXiv:2601.02553](https://arxiv.org/abs/2601.02553)（README 徽章链接，正文未读）。
- [外] 核心主张：**语义无损压缩**——以高信息密度存记忆，agent 记得更多、token 更少。
- [外] 三阶段管线（SimpleMem 文本）：
  1. **语义结构化压缩**：把非结构化交互蒸馏成自包含事实单元（**消解指代 + 绝对时间戳**），多视图索引；
  2. **在线语义合成**：同一会话内把相关上下文合并成统一抽象表示，**在建库时做而不是查询时**；
  3. **意图感知检索规划**：推断查询意图，决定检索什么、组装紧凑上下文。
- [外] 自报：LoCoMo 平均 F1 +26.4%，推理期 token 约降 30×。
- [外] Omni-SimpleMem（多模态）：选择性摄入（熵驱动）、渐进检索（**混合 FAISS + BM25**、金字塔 token 预算）、知识图谱增强。
- [外] EvolveMem：把「检索配置」也做成自演化闭环（评估→诊断→提议→护栏→重复），LoCoMo 相对 +25.7%，且跨 benchmark 迁移为正。

## 与我们对照

| SimpleMem | 我们 | 差距 / 判断 |
|---|---|---|
| 绝对时间戳 | `occurredAt` 一等字段 | ✅ 已有 |
| 消解指代（"它/那个"→具体实体） | 无（禁止模型抽取） | 不做：需要模型，越边界 |
| **建库时合成**，不查询时 | D1 归档 + 卷（thread）在主卷里合成 | ✅ 方向一致；我们刚把 `class:*` 做成主卷 |
| 意图感知检索 | 首条消息 → 主题/实体/类信号 | 已有雏形；意图规划未做 |
| 混合 BM25 | 只有主题精确/包含匹配 | **N2 仍未落地**（需倒排 + 精度抽样） |
| 检索配置自演化 | 我们的整点巡检 + 六轴人工判读 | 人驱动的同类闭环；自动化程度低 |

## 可落地候选

- **N9 建库期骨架卡**（合成前置）：归档时对 `class:*` 主卷生成「卷首卡」（标题 + 局数 + 代表错误 + 指针），
  首轮命中直接取用；查询期不再现场拼。预期 A4 下降、A2 不变。
- **N2 混合关键词**：SimpleMem 用 BM25 + 向量；我们只做 BM25（非向量，边界内），仍按 `M7-N2-rejected.md` 三步走。
