# Self-RAG：按需检索 + 反思 token（2026-11-03 采集）

- 来源：[arXiv:2310.11511](https://arxiv.org/abs/2310.11511)（2023-10-17）。
- [外] 批评"无差别检索固定条数"：不管需不需要、相不相关都塞进去，会降低可用性。
- [外] 做法：训练一个模型，用**反思 token**（reflection tokens）自己决定
  **要不要检索**、**检索到的段落相不相关（ISREL）**、**支不支持结论（ISSUP）**、**生成有没有用（ISUSE）**；
  推理时可调这些 token 控制行为。
- [外] 7B/13B 在开放域问答、推理、事实核查上超过 ChatGPT 与检索增强的 Llama2-chat，
  长文本生成的**事实性与引用准确率**显著提升。

## 与我们对照

| Self-RAG | 我们 | 判断 |
|---|---|---|
| 按需检索（模型决定） | 机械判定：命中才注入，不命中**零注入** | ✅ 同一目标，我们不用模型决定 |
| 反思 token（模型自评相关性/支撑性） | **十道闸**（机械判据）+ 作用域闸 | ✅ 同功能，可单测、可复核 |
| 引用准确率 | provenance 必带 episode+seq+日期（A6 = 100%） | ✅ 更硬 |
| 训练/微调 | 零训练、零模型调用 | 有意不同（边界成文法） |
| 固定的检索条数 | 预算 ≤500 tokens / ≤5 条，超了截断并说明 | ✅ 同构 |

## 结论
Self-RAG 与 CRAG 指向同一件事：**"检索该不该发生、结果可不可信"必须被显式判断**。
它们用**训练出来的反思 token**，我们用**机械闸**——后者不能学，但能审计、能单测、能复现。
本文没有给出可落地的新机制；它给了一句可引用的话：

> 检索系统的质量上限，取决于它对"不该检索"和"检索错了"这两件事的处理方式。

我们两条都有：不命中就沉默（拒答优先）、闸不过整卡不注入。
