# GraphRAG：实体图 + 社区摘要的全局问答（2026-11-04 采集）

- 来源：[arXiv:2404.16130](https://arxiv.org/abs/2404.16130)（v2，2025-02-19）。
- [外] 问题：普通 RAG 在「面向整个语料」的全局问题上失效（如"这批数据的主要主题是什么"），
  那本质是 query-focused summarization（QFS），不是检索。
- [外] 做法：**LLM 建图索引**两阶段 —— ① 从文档抽实体知识图；② 为紧密相连的实体群**预生成社区摘要**；
  回答时用每个社区摘要生成局部回答，再做一次汇总（map-reduce）。
- [外] 在百万 token 级语料的全局理解问题上，比常规 RAG 基线在**全面性**与**多样性**上有显著提升。

## 与我们对照

| GraphRAG | 我们 | 判断 |
|---|---|---|
| LLM 抽实体图 | 机械抽主题/边（`why` 可核） | ⚠ 路线相反：他们用模型，我们禁用模型判断 |
| 社区摘要（LLM 预生成） | 线索/卷是**派生视图**，不存模型摘要 | ⚠ 我们不设全局摘要；卷只是索引 |
| 全局问答（"主要主题是什么"） | 不提供：我们只答"这个信号在历史里出现过什么" | ⚠ 定位不同，不是缺陷 |
| 回答靠摘要汇总 | 回答靠**注入事实 + 模型自己推理** | 我们的红线：注入只给事实，不给结论 |

## 三条可复用结论
1. **"摘要必须标明是生成物"**：GraphRAG 的社区摘要显式是派生/可重建数据——与我们"卷是视图、可重算"同构；
2. **全局问题确实需要另一条路**：它不是检索能解的。我们的答案是**不做**（职责边界：记忆不替模型写总结），
   而不是"用相似度硬凑"；
3. **索引要按需重建**：他们重建社区摘要成本高；我们的 `signature-index` / 卷视图都可重算（N9 已落地）。

## 结论
无新机制可落地（LLM 建图/摘要被边界禁止）；但它把"全局问答 ≠ 检索"这件事讲清楚了，
支持我们**不做全局摘要**的取舍，也提醒未来若要做，必须走"派生 + 可重建 + 标明生成物"的路。
