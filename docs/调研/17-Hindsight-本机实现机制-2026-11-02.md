  即**运行中产品的官方说明**，比论文更贴近我们要对标的东西。
- 标注：`[外]` = 该文档原文所述；`[本]` = 我们在本机测到的数字（`evidence/` 里可复算）。

## [外] 它的机制（摘要，按原文）

1. **每仓库一个 memory bank**：`coding-agent::<gitProject>`；worktree 共享主仓库的 bank；
   每轮按工作目录重新解析，`cd` 到别的 bank 区域会"从那一轮起"写进新 bank。
2. **自动摄入**：首次打开时用最近 commit message + 只读代码库调查（survey）播种；
   每次会话开始后台补齐（新 commit、新对话），并**维护 5 张知识页**。
3. **会话合成（reflect）**：默认首条 prompt 触发一次深度记忆合成并注入；
   `autoInject` 可换成 `pages`（知识页命中）/`recall`（观察召回）/`none`。
4. **写回**：会话结束自动把对话 retain 进 bank；不需要用户"保存"。
5. **知识页是固定分类**（各绑定一个 tier tag）：Component map / Core concepts / Conventions and patterns /
   Key decisions and rationale / Initiatives and enhancements——**每页一次 LLM 合成**，按 cron/hourly 刷新。
6. **观察（observations）作用域**：默认整合成每个 bank 一份（`observationScopes: "shared"`），
   避免"同一仓库被两个 agent 各长一套信念"。
7. **失败降级**：reflect 超时/5xx → 退到知识页检索 → 再退到原始 recall；都失败就是普通无记忆回合，
   记 `diag.jsonl`（`reflect_failed` / `inject_recall` 等），**从不打断 agent**。
8. **纠错**：发现记忆错/旧 → `hindsight_ingest_document("Correction: …")`，新事实压过旧记忆。

## 对照结论（为什么这套设计是"可打败的"）

| 维度 | Hindsight | 我们 |
|---|---|---|
| 写入权 | 模型/引擎自动写（consolidation 会重写表述） | **只有聚合器写**，只增不改，原文可回溯 |
| 事实保真 | 合成后的摘要（原文需 `read_chunk` 才见） | claim 文本 + support 逐条 quote，**天生可核** |
| 延迟 | 秒级（LLM reflect） | 毫秒级（机械匹配） |
| 成本 | 每页每次刷新一次 LLM 合成 | 零模型调用 |
| 自动摄入代码/commit | 是（seed + survey） | **否**（无棋谱不入馆，刻意） |
| 知识页 | 5 张固定分类，LLM 写 | 不建知识页（面向模型，不面向人） |
| 纠错 | `Correction:` 文档 | L4 人纠错 → counter + `validTo` + disputed |
| 失败模型 | 降级到无记忆回合 | 同（任何异常返回原 decision + warn） |

**我们不打算照搬的两件**：LLM 合成知识页、代码库自动 survey。
**我们明确更强的三件**：秒级→毫秒级、摘要→逐字可回溯、自动写→只增不改+人纠错。

## 需要注意的一条（他们的提醒，我们也适用）
