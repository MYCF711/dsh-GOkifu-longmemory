# "默认关"的工程价值：负收益特性怎么下线（2026-11-05 采集）

- 来源：两份一手规范（均已读全文，访问日期 **2026-11-05**）：
  [Semantic Versioning 2.0.0](https://semver.org/)（作者 Tom Preston-Werner）、
  [PEP 594 – Removing dead batteries from the standard library](https://peps.python.org/pep-0594/)（Status: Final）。
- **范围声明**：47 篇讲"低频能力该投/期权/删"的**生命周期判断**、50 篇是判据总表、53 篇讲指标归因；
  本篇只写**"测量证明无收益之后怎么处置"**——默认关、下线节奏、以及"证明无收益"与"没测到"的区别。三篇不重复页面。

## 一、SemVer：删功能是"重大变更"，不是"清理"

- [外] **已发布版本的内容不可修改**：规则 3 —— "Once a versioned package has been released, the contents of that
  version **MUST NOT be modified**. Any modifications **MUST be released as a new version**."
- [外] **弃用要先"发一个 minor"，再"发一个 major 删"**：FAQ "How should I handle deprecating functionality?"
  —— "Deprecating existing functionality is a **normal part** of software development and is **often required to make
  forward progress**"；做法两条：(1) 更新文档，(2) "issue a **new minor release with the deprecation in place**"；
  且"**Before you completely remove the functionality in a new major release there should be at least one minor
  release that contains the deprecation** so that users can smoothly transition to the new API."
- [外] **"标记弃用"本身就要求升 minor**：规则 7 —— "Minor version Y **MUST be incremented if any public API
  functionality is marked as deprecated**"；而规则 8 规定**向后不兼容的删除必须升 major**。
- [外] **不可逆决策的代价被写成了版本语义**：FAQ 里那句是重点——"Incompatible changes **should not be introduced
  lightly**… Having to bump major versions to release incompatible changes means **you'll think through the impact
  of your changes, and evaluate the cost/benefit ratio** involved."
  即：**"删"是一个需要付 major 号价钱的不可逆动作**；能"默认关"就不该"删"。

## 二、PEP 594：删的标准是"最不争议 或 最有收益"

- [外] **删除的判据是双向的**："The modules in this PEP have been selected for deprecation because
  **their removal is either least controversial or most beneficial**."——不是"我觉得没用"，而是**争议最小**或**收益最大**。
- [外] **"没被用到"不等于"该删"**：该 PEP 专门有一节 "**Modules to keep**"——"This PEP also **designates some
  modules as not scheduled for removal**. Some modules have been deprecated for several releases or **seem
  unnecessary at first glance**. **However it is beneficial to keep the modules**… mostly for environments where
  installing a package from PyPI is not an option."（例：`optparse` 虽长期弃用但"too widely used to remove"；
  `wave` 因为"能教小孩做声音"而保留。）
  ⇒ **"我们这里测不到收益" ≠ "它没有价值"**：价值可能在别的环境（这正是 option value）。
- [外] **维护成本是删除的第一理由**："Any additional module **increases the maintenance cost** for the Python core
  development team. The team has limited resources, **reduced maintenance cost frees development time** for other
  improvements."；另有一条是"占位效应"——"Modules in the standard library are generally **favored and seen as the
  de facto solution**"，留着未维护的模块会**挡住更好的社区实现**。
- [外] **下线有节奏，不是一次性消失**：弃用时间表——3.11 起发 `DeprecationWarning` → **3.12 是最后含该模块的版本**
  （EOL 2028-10）→ **3.13 从 main 分支移除**。即**至少两个 minor 的观察窗**。
- [外] **"另建仓库养着"被明确否决**：Rejected ideas 里写——"the added workload to create and maintain such a repo
  **officially wasn't justified**, as the source code will continue to be available in the CPython repository for
  people to **vendor as necessary**."（源码留在历史里，需要的人自己 fork —— 这就是"默认关但可重开"的另一种形态。）

## 三、三条处置判据（机械可算）

| # | 判据 | 机械口径 | 判定 |
|---|---|---|---|
| **D1 样本量与区间** | 配对样本量 `n`（逐题配对的对数）与**差值区间的上界** | `n ≥ 100` 且 `diff 的 95% 上界 < 预设最小有意义效应（如 5pt）` ⇒ 可判"**无收益**"；否则只能"**继续观察**" | 不足 ⇒ 不许下结论 |
| **D2 配对差值** | **discordant 对**：`onlyA`（只 A 过）/ `onlyB`（只 B 过） | `Δ = (onlyB − onlyA)/n`；**`onlyA = onlyB = 0` ⇒ Δ = 0 且方向无信息**（McNemar 的 p 值此时无判别力，`p = 1` 只说明"没有不一致对"） | Δ 显著为正才考虑开 |
| **D3 噪声/挤出** | `noiseShare = 多出的行里噪声占比`；`displaced = 被挤掉的真内容行数` | `noiseShare ≥ 50%` **且** `displaced > 0` ⇒ **负收益** | 负收益 ⇒ 必须关 |

**D1 与 D2 的分工**（这是本篇要区分的两件事）：
**"证明无收益" = 区间上界足够小（D1）** ；**"没测到收益" = 样本不足或区间过宽**。
`discordant = 0` **本身不构成证明**——它只让差值恰为 0；**必须配上 D1 的上界**，才能说"收益至多 3pt，而我们不接受"。

## 四、对照本仓（棋院，写作时点实测）

Q18（跨项目召回）复评，**n = 112 逐题配对**：

```
A（默认关）严格 46/112 = 41.07% · A5 泄漏 0
B（开跨项目）严格 46/112 = 41.07% · A5 泄漏 0
配对：both 46 · onlyA 0 · onlyB 0 · neither 66 · Δ=0 · McNemar p=1.0000
B 多出 17 行里 15 行（88%）是噪声；挤掉 12 行（5 行是同域内容）
```

- **D1**：`n = 112 ≥ 100`；`discordant = 0` ⇒ 差值的 95% 上界约 **±3.2pt**（以 112 为分母），**< 5pt 的最小有意义效应** ⇒ 可判"**无收益**"（不是"没测到"）。
- **D2**：`onlyA = onlyB = 0` ⇒ `Δ = 0`，且**方向无信息**（`p = 1.0000` 不得被读作"两版等价"的证明，只能读作"没有不一致对"）。
- **D3**：`noiseShare = 15/17 ≈ 88% ≥ 50%` **且** `displaced = 12 > 0`（其中 5 行同域）⇒ **负收益**。
- **结论：永久关闭（默认关）**。三条判据同时指向"关"，且这是**第二次**得到同一结论——上一轮 n=12，本轮**前提已换过一轮**（排序键、判定口径、信号源都改了），结论仍不变 ⇒ **结论对前提稳健**（PEP 594 的"least controversial"在此成立）。
- **处置形态（不是"删"）**：代码与开关**保留**、默认关、判据写进文档与测试；
  重开条件写死：**出现"跨项目召回"的独立需求证据（≥1 个真实用例 + 配对复评 Δ > 5pt）**才重开。
  依据：SemVer 说"删是 major 级不可逆动作"，PEP 594 说"源码留在历史里，需要的人自己 fork"——
  **默认关 = 把不可逆决策换成可逆决策**，代价只是一个开关。

## 结论

判据三句话：**D1 看区间上界（不是看 p 值）→ D2 看配对差值方向 → D3 看噪声与挤出**。
三者组合的处置只有三档：**继续观察（样本不足）／默认关（无收益或负收益，代码保留）／删（争议最小且维护成本高）**。
Q18 落在第二档，且因为**换过前提仍同结论**，这一档是稳的——
**"默认关"不是没做决定，而是把一个不可逆决定换成了一个可逆决定**。
