# CRAG：Corrective RAG —— 检索质量评估 + 降级动作（2026-11-02 采集）

- 来源：[arXiv:2401.15884](https://arxiv.org/abs/2401.15884)（v3，2024-10-07）。
- [外] 核心：RAG 依赖检索质量，检索错了模型就跟着错。CRAG 用一个**轻量检索评估器**给检索结果打置信度，
  据此触发不同动作：
  1. 置信度高 ⇒ 直接用；
  2. 置信度低 ⇒ 走**大规模网页搜索**补充；
  3. 另配 **decompose-then-recompose**：把检索文本拆开、只留关键信息、滤掉无关部分。
- [外] 即插即用，可挂在多种 RAG 方案上；四个数据集（短/长文本生成）上显著提升鲁棒性。

## 与我们对照

| CRAG | 我们 | 判断 |
|---|---|---|
| 轻量检索评估器（模型/小模型打分） | **十道闸**（机械判据：时间/来源/预算/作用域/祈使句/治理痕迹…） | ✅ 同功能，但我们的"评估器"是**机械规则**，不是模型 |
| 按置信度触发不同动作 | 闸不过 ⇒ **整卡不注入**（降级为空/指针）；预算不足 ⇒ 截断并显式说明 | ✅ 同构 |
| 低置信度时外网补充 | **不做**（边界成文法：不联网、无棋谱不入馆） | 有意不同 |
| decompose-then-recompose | 预算内裁剪（`clipLine`/降级到 60 字）+ 省略计数 | ✅ 同构的机械版 |
| 置信度打分 | 只用**计数**（支撑局数/闸通过数/repeat），禁止模型评分 | ✅ 更严 |

## 结论
CRAG 的价值是**证实"检索必须先被评估"**这条路线；我们的"评估器 = 十道闸"已经在做同一件事，
且是机械的、可单测的。它比我们多的是外网兜底（我们刻意不做），少的是"事实必须可追溯到 episode+seq"。
**没有需要新实现的机制。**

## 可复用的一句话（写进复盘时用）
> 检索质量评估不是可选项；区别只在"用模型打分"还是"用机械闸"。我们选后者，因为打分不可复核、闸可以单测。
