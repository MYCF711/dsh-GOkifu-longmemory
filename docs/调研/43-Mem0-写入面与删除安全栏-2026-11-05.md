# Mem0 的显式写入面：就地覆盖、不可变条目与删除安全栏（2026-11-05 采集）

- 来源：厂商文档两页（均已读原文，访问日期 **2026-11-05**）：
  [Update Memory Operation](https://docs.mem0.ai/core-concepts/memory-operations/update)、
  [Delete Memory Operation](https://docs.mem0.ai/core-concepts/memory-operations/delete)。
  页面清单取自 [docs.mem0.ai/llms.txt](https://docs.mem0.ai/llms.txt)（同批抓取，用于确认这两页在 Core Concepts
  → Memory Operations 节下）。
- **范围声明**：本仓 35 篇写的是 Mem0 **v2→v3 的抽取管线**（ADD-only、单轮抽取、`linked_memory_ids`），
  39/41 写的是 Cognee 与 Memobase 的去重/覆盖；本篇只写 Mem0 **显式的更新/删除 API 面**（update / batch_update /
  delete / batch_delete / delete_all）——这三页此前未写，且与 35 的"抽取只发 ADD"是两件事：
  **抽取侧不覆盖，写入侧仍然提供覆盖原语**。

## 一、更新：就地覆盖 + 不可变 + 三选一校验

- [外] **更新的语义是"替换"**：`update` 用 `memory_id` 定位，`text` 是"**New content that replaces the stored
  memory value**"；`data` 是 `text` 的 deprecated 别名（仍可用、会打 warning）；另有 `metadata`（键值对，随更新一起写）
  与 `timestamp`（"Unix epoch (int/float) or ISO 8601 string to **override the memory's timestamp**"）。
  文档给的流程第三步是"Mem0 **overwrites the stored value and adjusts indexes**"。
- [外] **OSS 的更新是"部分字段可选"**：在 Python / JavaScript OSS SDK 里 `text` 可省——只传 `metadata` 和/或
  `expiration_date` 就只改这两项、保留原内容；但"**At least one of the three must be provided, otherwise the call
  raises**"（三个字段一个都不给 ⇒ 抛错）。`expiration_date` 传 `null` 表示**清除**过期时间。
- [外] **不可变（immutable）条目**："**Immutable**: Flagged memories that **must be deleted and re-added instead of
  updated**"；平台侧返回描述性错误，OSS 侧**直接抛异常**（"Raises exception: delete and re-add"）。
- [外] **批量更新有硬上限**：平台 `batch_update` "Update **up to 1000** memories in one call"；
  OSS 没有对应批量接口，"Script your own loop or bulk job"（OS 层要自己写循环/批处理）。
- [外] **配对反馈**：文档建议 "Pair updates with feedback signals (thumbs up/down) to **self-heal** memories
  automatically"；并指出经 MCP 接入时，"AI agents can update their own memories when users correct information"。

## 二、删除：三级作用域 + 安全栏

- [外] **三种删除入口**（Method comparison 原文）：`delete(memory_id)`（知道具体记录时，需要 ID、不接受 filter）、
  `batch_delete([...])`（有 ID 列表时）、`delete_all(...)`（按 `user_id` / `agent_id` / `run_id` / `metadata` 过滤，
  不需要 ID）。
- [外] **`delete_all` 的破坏性变更**：文档 WARNING 原文——"**`delete_all` previously wiped all project memories
  when called with no filters. It now **raises an error** if no filters are provided.**"
  想做批量删除必须用 `"*"` 通配符**显式**声明；且"**A full project wipe requires all four filters set to `"*"`**
  （`user_id` / `agent_id` / `app_id` / `run_id`）"，只设其中几个只会删那几个实体类型的记忆，不会清空项目。
- [外] **空 ID 也会被拦**："An empty or whitespace-only ID such as `user_id=""` **matches every memory in the project**,
  so the SDKs **raise an error before sending the request**."（`delete_users` / `deleteUsers` 同样校验。）
- [外] **删除的用途被明确写成三条**：满足 GDPR/CCPA 的"用户擦除"、删除陈旧或错误事实、会话过期/保留期到期后的清理；
  并再次强调 immutable 条目"cannot be updated; delete + re-add instead"。
- [外] **删除也是 agent 可调用的**：经 MCP 接入时"AI agents can **delete their own memories** when data becomes
  irrelevant or at user request"。

**没读到 / 不能确认的部分（如实标注）**：① 两页都是**厂商文档**、**无发布日期**，只能记抓取日期 2026-11-05；
② **没有任何"更新/删除后历史是否保留"的说明**——文档只说"overwrites the stored value"，**没说**是否留旧版本快照

## 对照本仓（棋院）

本仓的写入纪律是：**成员永不删 + 读侧折叠 + `mergedInto` 反指针**；而 Mem0 恰好给了这条路线的**反面样本**：
它把"同一条事实被反复写入"的正解，做成了**几个可审计的写原语 + 一堆安全栏**，而不是"更好的合并算法"。

| Mem0 写面 | 棋院 | 判断 |
|---|---|---|
| `update` **就地覆盖**（overwrites the stored value） | 只增不改：新条目 + `supersededBy`，旧条原样保留 | ⛔ **不借**：覆盖后"当时那句原话"永久消失，直接砍掉可回放 |
| `timestamp` 可 **override**（改 `occurredAt`） | 时间戳是一等字段，新旧**只按 `occurredAt`** 判，禁止回写 | ⛔ **不借**：可改时间戳 = 可以伪造"新旧"，整条溯源链失效 |
| **immutable 条目**（不可改，只能删+重加） | 原件永不删、也永不改（episode / 事件） | ✅ **概念同向**：他们把"不可变"做成**可选标志**，我们做成**默认全局**——这是我们更强的一点 |
| **三选一校验**（text/metadata/expiration 全空 ⇒ 抛错） | 我们的写面目前只有归档；将来加"遮蔽/重算"命令时同样要拒空操作 | ✅ **可借**：**任何写原语都必须拒绝"什么都不改"的调用**，否则审计里会出现空事件 |
| `delete_all` **无过滤器即报错**；通配符必须显式，**全项目清空要四个维度全是 `"*"`** | 我们的批量遮蔽/清理若存在，必须要求**显式 scope 全维** | ✅ **强烈可借**：这是防"一条命令清空整库"的标准护栏，形状可直接抄（缺一维就拒） |
| 空 / 空白 ID 会被 SDK **提前拦下**（否则匹配全库） | 我们的 `scopeKey` 若为空，同样会退化成全局 | ✅ **可借**：入参校验要**在发请求前**做，不要指望后端 |
| 批量上限 **1000 条/次** | 归档/遮蔽若批量，应分批 + 幂等重放 | ✅ **可借**：上限 + 幂等（我们已有 append-only 重放，缺的是"每批上限"） |
| **feedback 自愈**（thumbs up/down 触发更新） | L4 人纠错 = 最高优先级证据，只记 correction+counter | ⛔ 不借模型/用户评分自动改记忆；但**可借"纠错要留痕"**（我们的 correction 记录形状是对的） |
| MCP 让 **agent 自己改/删记忆** | `kifu_*` 只读工具面，写入只发生在归档期 | ⛔ 不借：开放写面 = 让模型在推理时改证据，与"注入只给事实"冲突 |
| 删除用途写的是 **GDPR/CCPA 擦除、删错误、过期清理** | 我们只遮蔽可见性，不删原件；"擦除"需求由 scope 隔离 + 只读面承担 | ⚠ 口径不同：他们有合规删除义务，我们用"不存敏感内容 + 作用域隔离"替代 |

**能借的四点（都能落成机械规则）**：

1. **写原语必须拒绝空操作**：任何"改这条记忆"的调用，若三个可改字段（内容/来源/有效期）一个都没变 ⇒ 直接报错，
   不写空事件。
2. **删除/遮蔽的安全栏形状**：无显式 scope ⇒ 报错；通配符要**逐维显式**；空/空白 scope 在**构造请求前**拦截。
   这三条可以直接抄进我们的归档与遮蔽命令。
3. **不可变标志作为"默认值"而非"选项"**：Mem0 让用户显式标记不可变；我们把**全部原件**默认不可变，
   只有派生视图（claim / 合并行）可重算——这条差异可以在契约里写得更硬。
4. **每批上限 + 幂等重放**：批量归档/遮蔽按固定批次切分，重放两次同结果（与"写盘可崩溃恢复"同一条纪律）。

**明确不借的三点（附理由）**：

1. **就地覆盖**：旧值消失即不可回放；我们要保留"当时怎么写的"。
2. **时间戳可改**：`occurredAt` 一旦可写，`supersededBy` 的新旧判定就可被伪造，A6 文字可核直接失效。
3. **agent 自写自删**：推理期改证据 = 把"记忆"变成"草稿"；本仓的写面只允许在归档钩子里。

## 两条可复用结论

1. **写入歧义的正解不是"更强的合并算法"，而是"更窄的写原语 + 更硬的校验"**：Mem0 这两页一半篇幅在讲
   "怎么删得安全"（无过滤器报错、通配符全维、空 ID 拦截、批量上限），说明**写面越宽，护栏成本越高**。
2. **"不可变"是产品级需求**：连一个允许覆盖的系统都要专门提供 immutable 标志。本仓把它做成默认，
   意味着我们**用"不能改"换来了"永远能追"**——这是可以写进对标材料的取舍，而不是实现偷懒。

## 结论

无需改结构（无写面 + 只增不改 + 读侧折叠）；可落地的是**把 Mem0 的护栏形状抄进我们的批量命令**：
空操作报错、无 scope 报错、通配符逐维显式、空 ID 提前拦截、每批上限 + 幂等。
它同时给了一个反向坐标：**写面越灵活，越需要靠校验兜底**；而我们的选择是让校验无处可兜——因为根本没有写面。
