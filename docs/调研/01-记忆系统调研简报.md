## 1 · 九套记忆系统逐一拆解

> 这一节的唯一来源是 `04-memory-systems.md` §2（横向事实表）、§3（逐系统 ①–⑦）、§4（收敛/分叉）、§7（蒸馏表 D1–D10），个别处引 `01` §2.3。
> 判据（`04` §1）：① 内容产自**本次会话**历史；② 只在**压缩生命周期**出现。两条都满足才可能进压缩插件。

### 1.1 Hindsight（vectorize-io，本机已装 v0.10.2）

- **数据结构**：bank → memory unit。三层 `document`（原文）→ `chunk`（切片，`store_document_text` 可关）→ `memory unit`（派生事实）；unit 字段 `id`/`type`（`world`|`experience`|`observation`）/`document_id`/`chunk_id`/`proof_count`/`state`/`consolidation_state`/`tags`/`entities`/`mentioned_at`/`occurred_start`/`occurred_end`；其上还有 entity 图、observation 整合层、mental model / knowledge page。
- **写入策略**：`retain` 用 LLM 抽事实+时间+实体+关系（抽取模式 `concise|verbose|custom|verbatim|chunks`）；observation 由后台 consolidation 生成，作用域按 **tag fnmatch glob**（`tags_match: all|exact`），`max_observations_per_scope` 限制每域条数；人工 `PATCH /memories/{id}` 改 `state`。
- **检索策略**：4 臂并行（vector / BM25 / graph〔entity-temporal-causal〕/ temporal）→ **RRF 融合 → cross-encoder 重排 → 按 token 上限裁剪**；budget 分 low/mid/high，映射函数 `fixed` / `adaptive`；`recall_include_chunks` 可连带返回原文切片。
- **遗忘/整合**：**没有时间衰减**——在 51 字段 bank 模板 + 342,843 B / 77 path 的 openapi 全文里搜 `ttl|decay|half_life|expires_at` **0 命中**。替代物是**配额触发整合** + **可逆失效**（`state`/`invalidation_reason`/`invalidated_at`；"Invalidated memories are excluded from recall, consolidation, and graph maintenance but **kept for audit (reversible)**"）。README：observation 是 "deduplicated beliefs"，"Each observation keeps its supporting evidence with exact quotes and a proof count, and is **refined** rather than overwritten"。
- **数字/机制细节**：v0.10.2；openapi 342,843 B / 77 端点；bank 模板 **51** 字段；TTL 搜索 **0** 命中；三级可寻址端点 3 个（`/memories/{id}/history`、`/v1/default/chunks/{chunk_id}`、`/documents/{id}/chunks`）。
- **进压缩插件判定**：**部分可借**（`04` §3.1-⑦、§7 D1/D2/D5）。借：(a) 三级闭包链的**形状**（派生→切片→原文）；(b) `invalidate` 而非 delete；(c) `proof_count`——"被独立见过几次"是**与时间无关的计数权重**。不借：整条记忆管道（抽取/实体归一/图/observation/bank）、4 臂检索、跨会话。边界张力：`proof_count` 只能借**计数**，不能滑向**模型打分**（`04` §5 末）。

### 1.2 OpenViking（volcengine，**AGPLv3**）

- **数据结构**：虚拟文件系统 `viking://`：`resources/`（文档/代码）+ `user/{id}/{memories,skills,peers}`。**目录级语义侧车**：`.abstract.md`（L0，默认 **256** 字符）+ `.overview.md`（L1，默认 **4000** 字符），文件本体是 L2。
- **写入策略**：`session.commit` 归档会话并把 memory 抽成 markdown（"you can inspect, edit, and merge"）；派生摘要由后台队列生成，**不构成跨 VikingFS/向量库/队列的原子事务**（`09-transaction.md` 明说）。并发写同一目录摘要用 `coalesce_version`：**"only the latest version may write back"**，旧任务写回前丢弃。
- **检索策略**：`HierarchicalRetriever` 每查询跑**一次全局向量检索**，用目录/类型/权限/`level` 作约束——**默认不递归导航目录**（逐字："retrieval **does not navigate directories recursively**"）。`find()`=QUICK；`search()` 有 reranker 时走 THINKING（先意图分析）；结果带 `abstract`（L0）。披露顺序写死：**先 L0 → 再 L1 → 最后 L2**。
- **遗忘/整合**：**未公开**——README + `docs/en/concepts/{03,06,07,09}.md` 四篇里没有 TTL/衰减/淘汰记载；站点 Version management 页返回 SPA，判「未核实」。**「未公开」≠「没有」**。
- **数字/机制细节**：L0=256 / L1=4000 字符；"Truncation prefers complete sentences … can retain the first complete sentence even when that sentence is longer"（整句优先）；L0 **从 L1 派生**（H1 之后、第一个 `##` 之前那段），不是从 L2 直接压；许可证 AGPLv3。
- **进压缩插件判定**：**部分可借**（`04` §3.2-⑦、§7 D3/D4）。借：(a) 分层字符预算 + 整句优先；(b) **"上层从下层派生"的方向纪律**（对应"L4 汇总行必须从边集算出来，不能由模型另写一段"）；(c) `coalesce_version` 版本戳。不借：整个 context database、目录检索、后台抽取、多租户/ACL。
- **一处被复核推翻的通行说法**：任务书里「OpenViking = 目录递归检索」**不成立**（`04` §0.1 末）。

### 1.3 MemOS（MemTensor，arXiv 2507.03724）

- **数据结构**：三种基质 **plaintext / activation（KV-cache 中间态）/ parameter（权重）**；基本单元 **MemCube**："encapsulates both memory content and metadata such as **provenance and versioning**"，可 compose / migrate / fuse；明文层按 **task–concept–fact** 路径组织成层级图。
- **写入策略**：明文层"supports conflict detection, deduplication, versioning, and forgetting policies"；生命周期 `generation → activation → fusion → archiving → expiration`，由 `MemReader` / `MemScheduler` / `MemLifecycle` / `MemOperator` 分工。
- **检索策略**：MemScheduler "selects appropriate memory types based on task intent, and dynamically plans invocation order"——**检索被当成调度问题，不是排序问题**。
- **遗忘/整合**：有 `expiration` 这个**生命周期状态名**，但论文**没给策略、阈值、触发条件** ⇒ 不可照搬（它依赖多层调度的系统语义，单插件没有那个语义）。
- **数字/机制细节**：arXiv 2507.03724；三种基质；生命周期 5 段；`expiration` 无阈值（文中无）。具体 API/阈值【未核实】。
- **进压缩插件判定**：**只借一个形状**（`04` §3.3-⑦）：**MemCube = 内容 + provenance + version 三件套**，可一对一映射成「fold 块 = 摘要 + `{seqStart,seqEnd}` + `foldCount`」。不借：三层基质、调度器、参数层、fusion。

### 1.4 SimpleMem（arXiv 2601.02553）

- **数据结构**：三段管线——semantic structured compression（LLM 当**语义裁判**估"信息增益"决定留不留）→ **online semantic synthesis** → intent-aware retrieval planning（多索引 + 动态检索预算 + ID 去重）。
- **写入策略**：合成发生在**写阶段**："synthesizes related fragments into unified, high-density entries **before they are committed to the database**"。
- **检索策略**：dense + sparse + symbolic 三索引；规划式决定 scope 与 depth；再按 token 预算裁剪。
- **遗忘/整合**：**无显式遗忘机制**；等价物是**写时丢弃低增益内容**。
- **数字/机制细节**：全文按 `provenance|source id|source document|source chunk` 搜 **0 命中**（零回指）；LoCoMo F1 **+26.4%**、token 降至 **1/30**（来自摘要，**不迁移**，`04` §3.4-⑥）。
- **进压缩插件判定**：**基本不可借，且是反面教材**。可借仅一条：检索预算随意图/场景变化（与 00 §3 #5 同族）。明确否：**写时合成 = ρ^k 的另一种形态**（每写一次重写一次表示）；**LLM 语义裁判门控**不可复现，且它砍的是**原文**不是**视图**。
- **⚠ 术语警告**（`04` §3.4-⑦）：它自称 "semantic **lossless** compression"，但逐段看是"改写+合并+丢弃"，"lossless" 只对**下游任务效用**成立，**对原文不成立**——这个词不能进设计文档当依据。

### 1.5 mem0（arXiv 2504.19413 + 现行仓库 v3）

- **数据结构**：文本记忆 + 向量库；可选图记忆（实体-关系三元组）。
- **写入策略（两个时点，差别本身就是结论）**：2025 论文 extract→update，**LLM 自选四操作** `ADD`/`UPDATE`/`DELETE`（`M ← M \ {m_i}`，真删）/`NOOP`；2026 现行 README（v3）：**"Single-pass ADD-only extraction — one LLM call, no UPDATE/DELETE. Memories accumulate; nothing is overwritten."** 另加 entity linking、multi-signal retrieval、temporal reasoning。
- **检索策略**：v3 三信号并行融合（semantic + BM25 + entity）。
- **遗忘/整合**：旧版 = DELETE（真删）；新版 = 不删；**无 TTL**。
- **数字/机制细节**：四操作伪码见论文；v3 无 UPDATE/DELETE；可寻址**弱**（README 未提指向源消息的 id）。`01` §2.3 记：LOCOMO 上比 OpenAI 方案 LLM-as-Judge **+26%**，图变体仅 **+2%**，p95 延迟 **-91%**、token 成本 **-90%+**。
- **进压缩插件判定**：**只借它的路线变化**（`04` §3.5-⑦）：一个大规模部署的记忆产品，从"LLM 判定 + 破坏性 DELETE"退回"只增不改"，是「**覆盖会丢信息**」最强的外部证据，正好支持"遮蔽不删、覆盖只标注"。不借：LLM 判定冲突、向量检索、跨会话。`01` §2.3 补一条硬边界：**覆盖语义只能用在"同一对象的属性"上，不能用在"尝试历史"上**。

### 1.6 Letta / MemGPT（arXiv 2310.08560 + 现行 Letta 文档）

- **数据结构**：main context（system instructions + working context + FIFO queue）↔ external context（`recall storage` = 消息库，`archival storage` = 任意长文本）。现行 **MemFS**：记忆是**一个 git 仓库**，按路径寻址（label → `persona.md`）。
- **写入策略**：模型通过 **function call 自编辑**记忆；队列管理器三段阈值 **warn 70% / flush 100% / evict 50%**；队列第 0 项是"已被驱逐消息的**递归摘要**"（"a recursive summary of messages that have been evicted from the queue"）；检索用**分页**防溢出。
- **检索策略**：函数调用 + 分页；MemFS 下**根目录文件每轮进 system prompt**，子目录带自己的 `MEMORY.md` 索引、**不进上下文**，agent 顺索引去读（"directory and file names act as **signposts** … This keeps the active context lean while preserving deeper reference material."）；**默认不装向量/语义索引**。
- **遗忘/整合**：FIFO 驱逐 + 队首一条递归摘要；**无 TTL**。
- **数字/机制细节**：arXiv 2310.08560；70%/100%/50%；git commit 即版本（可 diff/rollback）；`dreaming` / sleep-time 后台整合内部策略【未核实】。
- **进压缩插件判定**：**一借一否，而且是最需要点名的一处**（`04` §3.6-⑦）。借：**"索引 + 指针"式披露**——根索引只列名字、正文按需读，是"省略行必须带去哪查"最干净的工业实现（**省略行 = 指针行**）。**不借（红线）**：MemGPT 的核心主张就是"让模型自己决定何时换入换出"，**同时撞两条线**——教模型"何时 restore"（行为指导→AGENTS/persona）+ 自建记忆工具接管工具层。次不借：`dreaming` / sleep-time。

### 1.7 Zep / Graphiti（arXiv 2501.13956）

- **数据结构**：三层子图 **episode**（原始消息/JSON，"non-lossy data store"）/ semantic entity / community（map-reduce 式摘要）；边与 episode 之间**双向索引**。
- **写入策略**：episode 摄入 → 抽实体与事实边 → 与语义相关旧边比对 → **冲突则 invalidate，不删除**（"old facts are invalidated — not deleted. Query what's true now, or what was true at any point in time."）。四条时间戳：`t_valid`/`t_invalid`（事件时间轴 T）与 `t'_created`/`t'_expired`（摄入时间轴 T′）。
- **检索策略**：cosine + Okapi BM25 + BFS 三路 → 重排；README 明说检索 "without reliance on LLM summarization"。
- **遗忘/整合**：无 TTL；失效保留历史、可查任意时间点。
- **数字/机制细节**：**双时间轴 4 个时间戳**；"**Every derived fact traces back to the episodes** (raw data) that produced it. Full lineage from derived fact to source."
- **进压缩插件判定**：**借一个退化版，不借建图**（`04` §3.7-⑦）。借：双时间轴的退化版——会话里"事件时间"天然就是 `seq`，一条边被新事实取代时记 `supersededAtSeq`，同时得到"何时为真"和"何时失效"，**不需要第二套时钟**。不借：图构建、实体解析、community 的 map-reduce 摘要（那就是递归摘要，ρ^k）。

### 1.8 A-MEM（arXiv 2502.12110，NeurIPS 2025）

- **数据结构**：Zettelkasten 式：每条新记忆生成一张**结构化笔记**（上下文描述、关键词、tags、向量），并在历史库里找相似者建链。
- **写入策略**：两个动作——`link generation`（建链）+ **`memory evolution`**："new memories, when incorporated, can trigger **updates to the contextual representations and attributes of existing memories**"。
- **检索策略**：链接网络 + 相似度（链接是可检索面）。
- **遗忘/整合**：**无**。
- **数字/机制细节**：`provenance` 全文 **0 命中**；"演化"**直接改写旧笔记**；六个基座模型上优于 SOTA（`01` §2.3，来自摘要）。
- **进压缩插件判定**：**不可借，纯反面教材**（`04` §3.8-⑦）。`memory evolution` 正是 `03` §6 第 4 行"**记忆是可塑的 → 摘要可以覆盖原文**"：它把"后来的理解"写回"当时的事实"，且**没有原件指针可退回**。可借为零的第二个理由：它唯一值得借的"标签作为检索面"，而压缩**不做检索**（判据②直接出局）。`01` §2.3 给的折中判据：**只许加标注，不许改内容**（`superseded_by` 而非重写）。

### 1.9 MemoryOS（arXiv 2506.06326）

- **数据结构**：三级 **STM**（对话页定长 FIFO 队列）/ **MTM**（按话题分段，段内分页）/ **LPM**（用户画像 + agent traits，**定长队列 100**）。
- **写入策略**：STM→MTM 走 FIFO；MTM→LPM 按 heat 做**段删除 / 段升级**两个操作。
- **检索策略**：两级——语义相关性先选段，再取段内页。
- **遗忘/整合（全组唯一有公式的）**：`Heat = α·N_visit + β·L_interaction + γ·R_recency`，`R_recency = exp(−Δt/μ)`，`μ = 1e7` 秒（≈**115.7 天**）；`N_visit` = 段被检索次数，`L_interaction` = 段内页数；迁移后 `L_interaction` 归零使 heat 下降。α/β/γ **具体取值未读到**（只说"决定相对重要性"）。
- **数字/机制细节**：arXiv 2506.06326；μ=1e7 s；LPM 定长队列 **100**；版本化/可寻址**无**（页即原文，事实级无回指）。
- **进压缩插件判定**：**不借公式，形状本仓已有**（`04` §3.9-⑦）。heat 三分量全不可借：`N_visit` 需要在线统计"检索次数"，而压缩**没有"检索"这个动作**；`R_recency` 是时间衰减（`03` §6-1 已否）。唯一可借是**形状级**的"定长队列 + 迁移"，而 tier-2（checkpoint 满 N 条合并最老两条）**已经是这个形状**，无需再借。

### 1.10 横向收敛（`04` §4，全部【核实·原文】）

- **收敛 5 条**：① 派生层与原件层分离，且派生必须能指回原件（Hindsight / Graphiti / OpenViking / Letta / MemOS **五家一致**）；② 失效用"标注"不用"删除/改写"（Hindsight `state=invalidated`、Graphiti "invalidated — not deleted"、mem0 v3 取消 DELETE）；③ 检索 = 多臂 + 融合 + 按预算裁剪；④ 分层披露是共同形态（L0→L1→L2 / 索引→文件），**先给判断依据，再给内容**；⑤ **"可回溯"是工程需求不是论文卖点**——三个学术系统（SimpleMem / A-MEM / MemoryOS）**全部**不做事实级回指，五个工业系统**全部**做。
- **分叉 3 条**：① 遗忘——只有 MemoryOS 给时间衰减公式，Hindsight 用配额、Graphiti/Letta 用驱逐或不删、OpenViking 未公开 ⇒ **时间衰减不是主流，是孤例**；② 冲突判定——LLM 判定 vs 确定性失效，前者**不可复现且失败时无声**；③ 合并时机——写时合成 / 后台整合 / **不合并**，GOkifu 属第三类 + 增量 fold，**任何"为省 token 退回写时合并"的改动都是在拆地基**。
- **`04` §2 的一行读法**：**做压缩的（SimpleMem/A-MEM/MemoryOS）几乎都不留回指；做记忆的（Hindsight/Graphiti/Letta/OpenViking）都以回指为前提。** 这不是巧合——优化的指标不同。**压缩优化"同样的历史丢得最少"，所以只能站后一列。**

## 2 · 被判定「属于记忆系统、不属于压缩插件」的东西（本次新项目最关键的输入）

> 这是「长期记忆系统」项目的**正面清单来源**：凡被压缩插件判为越界/不可借的，正是记忆系统该接的活。反过来，被压缩插件判为"可借"的四样（§6）是**记账方式**，记忆系统可以直接复用，不需要重新发明。
> 分组按"为什么出局"分，依据列给出处。

- **一条横向证据值得新项目直接继承**：可回溯性在工业界是默认、在学术界是空白（§1.10 收敛⑤）。所以"长期记忆系统"若只做密度与准确率、不做回指，就是站到了学术系统那一列——而那正是压缩插件刻意避开的列。

## 3 · 压缩的职责边界成文法要点（`docs/压缩的职责边界.md`）

### 3.1 两条判据（§1 原文）

> **"一段内容属于「压缩」，当且仅当它同时满足两条：① 它产自本次会话的历史（不是产品自带的知识、不是通用规则、不是工具契约）；② 它只在压缩生命周期里出现（决策压什么 / 执行压缩 / 呈现压缩产物），不常驻、不解释世界。"**
>
> **"两条都满足才算本职；缺一条就等于替别的机制干活。"**

判据的来处（§0）：主人的原话「分清楚哪些是压缩 compact 的任务，哪些不是，不要把 AGENTS、tools、系统提示词等其他地方涵盖的功能越权覆盖。只做好本职工作，把本职工作做到最好。」

### 3.2 越权红线（§2「❌ 不属于压缩」七行 + 灰色地带）

七类机制与它们的红线（原文照录要点）：

| 机制 | 压缩绝不能做的事（原文） |
|---|---|
| AGENTS.md / 硬规则 | "不许把'你应当先备份再改'这类通用规则写进热清单或摘要模板；不许因为'压缩后模型可能忘记规则'就自己再复述一遍规则" |
| persona / 系统提示词 | "不许改 persona 的措辞、不许在 system 段落里追加'压缩提示'、**不许教模型'何时该 restore'（那是行为指导）**" |
| tools 定义与治理 | "不许改工具描述/参数、**不许自建'decompress 工具'去接管工具层**、不许做 `permission: allow\|ask\|deny` 这类治理开关" |
| 跨会话记忆 / 知识库 | "不许把本次棋谱写进跨会话库、不许做'从历史会话检索'、不许把 Hindsight/向量库接进来当压缩" |
| 上下文工程 | "不许决定'该读哪个文件'、不许预先裁剪工具结果（那是 `tool-result-pruner` 的事）、不许改请求的消息组织" |
| 提示压缩 | "不许把它混进会话历史压缩（两者生命周期完全不同：一个不改变历史，一个是持久化改写）" |
| UI / 展示 | "不许在压缩路径里做展示逻辑；页面只读压缩产物" |

灰色地带四条裁决（§2）：每步注入热清单 ✅（"前提是内容**全部来自棋谱**…一旦掺入通用建议就越界"）；摘要指令 "You are the fold engine…" ✅（"只喂给摘要模型，不注入主 agent"）；"Never promote UNVERIFIED to fact" ✅（"保真规则，不是 agent 行为指导"）；教模型"何时该 restore" ❌（"压缩只能**提供事实**（'seq 10-643 已折叠，可用 X 还原'），不能教'你应该还原'"）；压缩后自动重放规则 ❌。

**提交前五问**（§5，有一条答不上就不要写）：① 它产自本次会话历史吗？② 它只在压缩生命周期里出现吗？③ 它改变了模型"该做什么"吗？（是 ⇒ AGENTS/persona）④ 它改了工具契约或权限吗？（是 ⇒ 越权）⑤ 它跨会话了吗？（是 ⇒ 记忆/知识库）。

### 3.3 机器审计怎么做（§5.1，2026-11-01 起可执行）

```bash
node scripts/boundary-audit.mjs        # 0 条才算过；--json 机读
```

- 做法：**"只扫字符串字面量、先剥注释"**——把"最容易越界的两类东西"变成检查。
- **行为指导类**（error）：`下一步：` / `不要重试` / `you should` / `continue or abandon` 等出现在**模型可见字面量**里。
- **工具治理类**（error）：`permission: allow|ask|deny` / `approval:` / `sandbox_permissions`。
- **唯一豁免**：`src/rooms/facts-prompt.mjs` 的 `behavior-guidance`——"那是**只喂摘要模型**的指令模板，约束压缩行为、不注入主 agent"，豁免必须写进脚本 `ALLOW` 并注明理由。
- 效果实证：**"它的第一次运行就抓到一条真实残留：`renderFacts` 的 `STALE_UNSETTLED … (continue or abandon)`"**，上一轮清 OPTIONS 时漏在事实块里——"**这就是人工审计会漏的证据**"。

### 3.4 三个必须长期盯住的风险点（§3）

1. **热清单膨胀**——"约束：热清单只放**已发生的事实**与**用户/系统已声明的约束**，不放'下一步应该'"。
2. **摘要指令膨胀**——"摘要模型只做**降维与保真**，不做规划"。
3. **"还原"能力**——"如果实现 restore，只能提供**寻址事实**（哪个 seq 区间、怎么取），不能教模型何时用"。

边界复审的触发条件（§8，不是定期，是有事才审）：任何新增注入模型上下文的文本；任何"为了让模型更好理解"而改写的措辞；任何来自 doctor/验收清单的提示语被搬进热清单的时候。

## 4 · 重注入契约七项（`docs/压缩的重注入契约.md` §1）

判据（开头）："这些东西之所以'不靠摘要'，是因为**摘要可能丢、可能被模型改写、可能在降级时被裁掉**。凡是有'丢了就不可恢复'性质的，必须在每一步**重新灌进**上下文。"

| # | 项目 | 一句话含义 | 谁负责重灌 | 机器判据 |
|---|---|---|---|---|
| ① | **根目标** | 用户最初要什么（首条 user 消息，逐字） | `ledger.mjs` 的 `ROOT USER (verbatim)` | `ledger-boundary` #4；`handoff-check` ① |
| ② | **约束** | 不能做/必须做，**逐字**，来自所有 user 消息 | `CONSTRAINTS (verbatim)` | 同上 |
| ③ | **失败边** | 试过且失败 + 原因原文 + 证据 `seq`，**任何降级档位都不砍 seq** | `LEARNED (N failed attempts)` | #4 + A |
| ④ | **未落地的选项** | candidate / live-unsettled，**L2+ 至少留计数行**（沉默=断言"没有别的路"） | `OPTIONS (not yet landed)` | #4 + D |
| ⑤ | **未验证声明** | 跑了但没有外部验证信号，不能当事实 | `UNVERIFIED (ran, but no external signal)` | #4 |
| ⑥ | **当前路径 / 工作位置** | 现在做到哪，防重复已完成的工作 | `# WORKING:` / `# path:` 行 | #4 |
| ⑦ | **出处** | 每条边自带 `seq` / edge id，**全档保留** | 行内 `(seq a-b)` | #4 + A + I |

为什么是这七项（§2 原文）：①②"丢了会**改变任务本身**（'必须'和'最好'是两个任务）"；③⑤"丢了会**重复踩坑 / 把猜测当事实**"；④"丢了会让模型以为'只有当前这一条路'（提取诱发遗忘）——**沉默本身就是断言**"；⑥"丢了会**不知道自己在哪**，从而重复已完成的工作"；⑦"丢了就**无法回查**——一段没有出处的历史，等于不可验证的传闻"。

**不在这张表里**（§3）：工具定义/用法、AGENTS 规则本身、persona/语气、跨会话记忆/知识库、"下一步该做什么"。

**墓碑测试**（§4）：`test/ledger-boundary.test.mjs` **#4**——构造同时含七项的图，逐项断言出现在 `renderLedger().text` 里；断言用**内容**而非标题措辞（改标题不误红，删信息一定红）。§5 又补了 `scripts/handoff-check.mjs`（只读、跑 live 图、九项判定，有 FAIL ⇒ exit 1），因为它"只证明夹具七项齐全；生产的图形态差得远"。

## 5 · AGI 记忆架构对四个关键判定的结论（`05-agi-memory-architectures.md` / `01` / `03`）

### 5.1 「重要性」——三种来源，压缩只能站"算出来"

- 分类（`05` 开篇）：① **学出来**（NTM/DNC/Compressive Transformer/世界模型：需梯度 + **未来的损失**）；② **算出来**（结构、因果、结算状态：压缩时就能算）；③ **猜出来**（让模型说哪条重要：**不可复现**）。
- **"我们没有梯度、不能训练、只能操纵文本 ⇒ 只能站 ②"**，且"站 ② 不是退而求其次，是这批架构的失败替我们选出来的唯一可行位置"。
- **判定不采纳**："绝不接受第四种：模型说它重要"（`05` §3.2）。反例机制：Generative Agents 的 importance 打分"服务的是 believable，不是保真"，且"会系统性高估'叙事上重要'的（戏剧性失败），低估'判别上重要'的（一条排除了 3 个候选的枯燥失败）"（`05` §6-8）。
- **可移植的正例**：Compressive Transformer 压缩函数谱系里唯一廉价强者是 **most-used**（"过去被读得最多的"）⇒ 符号版 = **`reentryCount`（被后续路径再到达的次数）+ `retryCount`（同 intent 被重试次数）**，`05` §7 G-3 称其为"唯一新增信号、零模型调用、可单测"。

### 5.2 「时间衰减」——排序函数误用为存留函数

- 核心判据（`05` §5.4）：**"在检索里，衰减只影响排序：错了顶多多取一条，代价有界。在压缩里，衰减影响存留：错了是永久看不见，代价无界。⇒ 同一个公式不能因为'在检索里好用'就搬到压缩里。这是判据层面的不对称，不是调参问题。"**
- 合法用途只有一个：**"时间在压缩里只有一个合法用途：陈旧标注（`[stale 42m]`），不是删除。"**
- 反例与硬边界：① 人类 Ebbinghaus 曲线——材料是**无意义音节**、被试**N=1（他自己）**、作者自评"no other value than that of a **shorthand statement** … found **but once**"（`03` §3.1，实测 1 小时掉一半、1 天剩约三分之一、1 个月剩约五分之一）；② **本仓 27.8%（268/964）悬空残留**已是既有损坏，"再加自动过期是灾难"（`00` §4.1、`03` §6-1）；③ 长尾反例——"会话里最相关的往往是**最早的约束**（根目标），必须永久最高权重——直接与衰减冲突"（`05` §6-3）。
- 灰色地带的硬判据（`01` §6.2）：**"把这条权重设成 0，热清单的条目集合不应改变，只应改变顺序。"**

### 5.3 「可微记忆」——没赢；承重的不是可微性

- 结论句（`05` §1.5-4、§0）：**"承重的不是可微性，是「原文还在 + 能寻址」。"**
- 数字反例（[外]）：**Memorizing Transformers** 用**非可微**的 kNN 记忆，"steadily improves … up to **262K tokens**"，C4/arXiv/PG-19/GitHub/Isabelle 一致提升；**RETRO** 用 2T token 库 + 冻结 BERT 检索器，在 Pile 上以 **25× 更少参数**达到 GPT-3 / Jurassic-1 级。
- 另一条失败证据（`05` §1.5-1/2/3）：可微记忆"要求模型与记忆一起训练"（读头是权重的一部分）；"**接口在权重里，不可审计**——没有文本契约 ⇒ 不能 diff、不能回放、不能换模型"；"证据只在玩具任务上"（NTM 摘要自写 "**Preliminary** results … copying, sorting, and associative recall"）。
- 于是**"图结构记忆"不是怪招**（`05` §1.2）："DNC 里唯一真正承载信息的那一部分（temporal link matrix），被拿出来做成了显式的、可读的、可审计的结构。**可微没赢，链接赢了。**"
- 三条只该借的思想（`05` §1.6）：**时序链接、地址（`seq`）、软擦除（erase+add ≠ 覆盖）**；"别指望'记忆模块'自己学会重要——它只会优化你给它的损失；而我们的损失（下一步的验证结果）在压缩时还没发生"。

### 5.4 「原文可寻址」——page-in 不是 recall；原件是可检索性的基础

- **唯一合法的检索形态**（`05` §5.5、`01` §6.4）："合法的检索形态是 **page-in（按需回填原件）**，不是'召回知识'。不需要向量库，只需要 `seq` 寻址 + 一条取回路径。"**机制借，入口不借**：热清单给可寻址指针，"怎么把那段历史取回来"由宿主已有能力完成。
- **为什么摘要不能替代原件**（`05` §5.5、§6-6 原文）："它们的收益建立在**'原始表示还在'**（kNN 取的是 past keys / values，不是摘要）。⇒ 支持'保留原件、只遮蔽可见性'：**原件是可检索性的基础，摘要不是。原件丢了，任何检索都只能检索到摘要的错误。**"
- **为什么检索不能替代压缩**（`05` §6-6）："检索解决'取得到'，不解决'知道该取'。模型不知道有一段被折叠过时，它不会去检索（`03` §5.1：**模型没有'取不到'的信号**）。"
- **回填的成本证据**（`01` §4.5，[外]）：transparent-compact 因为带查找通道，"在 Qwen 的承诺探针上**每轮未命中缓存的 prompt token 从 21,389 涨到 57,300（约 2.7 倍）**"⇒ "page-in 的价值必须算**净账**"；"当前'一步 351 tokens'这个数字的前提是**不回填**"。回填四必要条件（`01` §4.3）：稳定的可寻址 id / 至少两种索引 / 每次回填有预算 + 游标 / 回填结果带来源——压缩**只有①④**，②③"不归压缩"。
- **可寻址失效的现实表现**（`02` §6-A）：Claude Code #26771——粘贴约 8,000 字符 DOM，压缩后"摘要在、内容没了"，摘要只写"User provided 8,200 characters of DOM markup"；用户诉求**不是"别压"而是"摘要里给可寻址的引用"**。

### 5.5 附带两条对设计有直接约束的结论

- **MDL 两段码 ⇒ 产物自己的"使用说明"也算成本**（`05` §2.1-1、`05` §2.2）："一份需要 50 token 前言解释自己格式的热清单，比看起来大 50 token"；且"MDL 惩罚模型复杂度，**不惩罚'读者要重建的假设'**"——把 5 条失败边压成"试了几种方案都失败"，字节更短但不可恢复。
- **因果配对是唯一无法重建的东西**（`05` §4.2 末、`00` §1.2-5）："文件可以再读，命令可以再跑，但'哪次修改让报错消失'只存在于历史里。" ⇒ 压缩真正的失效模式是"**压缩把'已经付过代价拿到的信息'降级成了'下一个模型的推测'**"（`02` §6 末）。

## 6 · 可被新项目直接复用的「记账方式」（抄清楚定义与字段）

> 来源：`04` §7 D1–D5（蒸馏表，含函数级落地形态）、`00` §8.1/§9/§11、`05` §7 G-1/G-2/G-3/G-5、`01` §2.6、`02` §8.1。
> 这四样（D1–D4）的共同点（`04` §7 总账）：**"都不是'记忆'，而是'让一个降维产物不失真、可退回'的记账方式"**；"**都不需要跨会话、都不需要检索、都不改变模型该做什么**"。

### 6.1 闭包指针（D1）——派生件必须带闭包，合并时取**并集**

- **定义**（`04` §7 D1）：派生件带闭包指针，合并时 `nodeIds/parents = union(子闭包)`。
- **字段设计（关键，且是"不要写进 `foldMarks`"的明确告诫）**：
  > "**不要写进 `foldMarks`**（它按 `FOLD_MARKS_KEEP=20` 截断，正好在最需要闭包的老 checkpoint 上丢信息）。新增**不受截断**的 `g.foldIndex[checkpointId] = {seqFrom, seqTo, nodeIds:[…], parents:[…]}`，append-only。"
- **写入时机**："`engine.mjs` 写 checkpoint 时同步落 `foldIndex`；`#tier2IfNeededUnsafe()` 合并最老两条时 **`nodeIds/parents = union(子闭包)`**，而不是只记合并后的新区间。"
- **渲染形态**：`ledger.mjs` 省略行渲染成 `… +N (见 graph.json#ck-12, seq 88–412)`；另一形态（`01` §4.5）：`[folded: 12 events, 3 failures → nodes n41-n53]`（个位数 token）。
- **失败模式（为什么要它）**：① 截断（`FOLD_MARKS_KEEP=20`）会让最老的块恰好失去回指；② 合并若只记"合并后的新区间"，就丢掉"哪些原始边被合进来"；③ 更强的断言形式是**集合相等**——"合并后 `seq` 集合必须**等于**合并前各边 `seq` 的并集（集合相等，比 `provenanceCoverage` 的'行带 seq'更强）"（`01` §5.6 probe #4、§3.3）。
- **状态**：候选 #12，"⏳ 未做（大）"（`00` §11）。

### 6.2 失效标注（D2）——只标注、不删不改写

- **定义**（`04` §7 D2）：失效只标注、不删不改写（Hindsight `state=invalidated` 可逆；Graphiti invalidated-not-deleted；mem0 v3 弃用 DELETE）。
- **字段设计**：`old.supersededBy = new.id` **+ `supersededAtSeq`**（后者即 `04` §3.7-⑦ 的"双时间轴退化版"：用会话 `seq` 当事件时间，**不需要第二套时钟**）。
- **渲染**：`renderFailureLine()` 在 tags 后追加 `[superseded by e12]`，**仍然渲染，只是标注**；对应 `01` §2.3 的 `FAILED (superseded by e42): ...`。
- **现状是破坏性的（失败模式记录）**：`kifu-model.mjs` 的 `mergeNodeInto()`（`:147`）"把 `from` 节点的入/出边全部重定向到 `into`，再 `delete g.nodes[fromId]`"。改法："置换命中时**不删节点、不改边端点**"（`04` §7 D1/D2）。
- **相关的两个已有实现**：`C17` 失败边被同一 action 的更晚成功边解决 ⇒ 标 `↑later-ok:<边id>`（`00` §10）；`C18` 失败边重试计数 `↻k`（只标同 action 组**最近一条**；每条都标 +12 tok → 只标最近一条 **+1 tok**）。
- **反面教材**：A-MEM 的 `memory evolution` = 把后来的理解写回当时的事实，且无原件指针（§1.8）。

### 6.3 分档预算（D3）——显式化，不许散在数组里

- **定义**（`04` §7 D3）：分层预算 + 边界截断 + **上层从下层派生**（OpenViking L0 256 / L1 4000、整句优先；Hindsight 按 token 上限裁剪）。
- **字段/函数设计**：`ledger.mjs` 新增 **`ledgerBudgetTiers()`** 显式列出 L0–L5 每档字符预算——"现在散在 `intentLen/reasonLen` 数组里"（实测就是硬编码 `intentLen = [70,50,34,22]`、`reasonLen = [90,60,36,25]`，`04` §0.1 复核过）。
- **两个配套机制**：`clipMiddle()` 加"**句/行边界优先**"分支（对应 OpenViking "Truncation prefers complete sentences … can retain the first complete sentence even when that sentence is longer"）；L4 汇总行的计数**从边集算**（不能由模型另写一段），并把 `provenanceCoverageOf()` 的断言**按档位**记录。
- **降级原则（本仓已有、有外证）**：`renderLedger` 六档 L0–L5 取"第一个装得下"的档；文件头写死"**能逐条列出的绝不合并**"。GraphRAG 的外证（`01` §3.3）："社区摘要装不进上下文时，不是删条目，而是用更短的子社区摘要**逐级替换**更长的元素摘要，直到装得下"——这是"降级表示"而不是"丢弃内容"。
- **真实缺陷（G-1，`05` §7.1）**：现在是**整份清单同档降级**（`for (level = 0; level <= 5; level += 1)` 取第一个 `tokens <= maxTokens` 的候选）⇒ "预算紧时先牺牲的恰好是约束与出处"。修法是**分项预算（floor）**：根目标 + 约束永远 L0 逐字、失败边允许降、`OPTIONS` 至少留计数 + 最近一条、路径可降。**风险最大（动渲染主干）**。
  - ⚠ **但 G-1 的依据已被 live 数据推翻一半**（`00` §11 #16，commit `bed5366`）："根目标占 2–89%、约束 0–26%，它们本来没被压没；主要矛盾是**失败边的表示效率**" ⇒ 优先级下调，改做「sections 观测 + 表达压缩」，**不抬下限**。`07` §4.3 同步判"给热清单加分项下限 ❌ 暂不"。
- **配合的观测字段**：`sections`（分项占比，失败边 < 40% 说明"失败记忆可能被别的段挤掉了"；根目标 > 80% 说明该会话没有失败可记）；`provenanceCoverage`（**必须 = 1**，边行带 `(seq …)` 或 `(sa-b)` 的比例）+ `provenanceMin`/`provenanceLow`。

### 6.4 版本戳（D4）——防旧写回覆盖新写回

- **定义**（`04` §7 D4）：版本戳防旧产物覆盖新产物（OpenViking `coalesce_version`："only the latest version may write back"；Letta git commit）。
- **字段设计**：`engine.mjs` 在 checkpoint/flush 前写 **`g.lastFoldVersion = {foldCount, atSeq, route}`**；tier-2 与常规 fold 的写回在 `#flush()` 前**比对版本，旧版本丢弃**。
- **与现有机制的区别（关键）**："现有 `_tier2InFlight`（`src/engine.mjs:176`）**只防重入，不防旧写回**"。
- **状态与判定**：候选 #18，"⏳ 未做（小）"；`00` §11 给的降级理由："当前写入是'内存图 → debounce 落盘'单进程，无跨进程写回 ⇒ **先记为低收益**"。
- **失败模式**：并发/异步写回（tier-2 合并 vs 常规 fold）交错时，晚到的旧结果覆盖新结果——OpenViking 的处理是"旧任务在写回前丢弃"。

### 6.5 配额与计数（D5）——用配额触发整合，用计数而非打分做权重

- **定义**（`04` §7 D5）：用配额触发整合（Hindsight `max_observations_per_scope`），用**计数**而非时间做权重（`proof_count`）；反例 = MemoryOS heat。
- **落地形态**："`fold-planner.mjs`：把'checkpoint 满 N 条'写成显式配额常量并进 doctor 观测（现为 `tier2After`）；`renderFailureLine()` 可加 `×k` 表示该失败被重复观测的次数（**仅当 k 可机械统计**，不得由模型打分）。"
- **必须写死的边界**（`04` §5 末）："`proof_count` 是**事实计数**（可机械统计，来自图结构），不是**模型评分**。我们若借，只能借'计数'，不能借'打分'。"

### 8.4 `05` §6 的 11 条「站不住的说法」（架构/理论侧，与 §8.3 不重复）

`6-1` 记忆越像大脑越好（"抄了形态没继承收益"）· `6-2` 压缩就是丢掉不重要的（"'不重要'在压缩时不可知…丢'不重要'的**没有收益**"）· `6-3` 用时间衰减决定保留 · `6-4` 窗口够大就不需要压缩 · `6-5` 压缩率越高越智能 · `6-6` 记忆即检索、有 RAG 就不用压缩 · `6-7` 可微记忆只是算力不够 · `6-8` 让模型判断哪条重要 · `6-9` 反思/巩固/摘要链提升质量 · `6-10` MDL 说最短最好所以删细节 · `6-11` 更强的模型会让压缩问题消失（"能力越强越会**流畅地填补**缺失（confident blunders），使缺失更难被发现"）。

### 8.5 明确"已被下调 / 未核实 / 未对齐"的三条（最容易被后人当成仍有效或可引用）

1. **候选 #16 分项预算 floor**：原判定"收益最大但动渲染主干"，后**被 live 数据推翻**——"根目标占 2–89%、约束 0–26%，它们本来没被压没；主要矛盾是**失败边的表示效率**"（`00` §11）。
2. **`04` §3.1 的一条表述**：`01` §1.3 里"不同成分的丢弃代价差**两个数量级**"的说法**本轮未核实到**，能核实的是同长度下 **4.7 倍**（`01` §5.2、§7.3-1）；"τ-bench 上 LLMLingua-2 无增益"亦**未抓到原文**，可核实的是 2608.01056 对 **LLMLingua**（非 2）在 **ACC 控制上下文**（非 τ-bench）上的 10.0% / 0%（`01` §5.4、§7.3-2）。**结论（借 budget controller）不变，理由要改。**
3. **口径未对齐项**：热清单 **351 tokens**（M-00 bench）与 `AGENTS.md` §17 的 **323 tokens** 在仓库里"**没有对齐，也没有各自的定义式**"（`01` §0）；`05` §7 声明"不引用 351/323，只用 `hotLedgerMaxTokens` 默认 500"。新项目若要引用，先补"哪段文本 / 哪个 tokenizer / 哪次 bench"。
