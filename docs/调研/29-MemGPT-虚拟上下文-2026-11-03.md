# MemGPT：把 LLM 当操作系统（分层记忆 + 中断）（2026-11-03 采集）

- 来源：[arXiv:2310.08560](https://arxiv.org/abs/2310.08560)（v2，2024-02-12）。
- [外] 核心概念 **virtual context management**：借鉴操作系统的分层内存（快/慢两级），
  通过在快慢存储间搬运数据，制造"上下文比窗口大"的假象。
- [外] 机制：主上下文（窗口内）↔ 外部存储（窗口外）；**中断**管理模型与用户之间的控制流；
  模型可以**主动编辑自己的记忆**（追加/替换/检索）。
- [外] 评测域：超长文档分析、多会话聊天（记住、反思、随时间演化）。

## 与我们对照

| MemGPT | 我们 | 判断 |
|---|---|---|
| 目标是"扩展上下文窗口" | 目标是"不重复踩坑"（记忆≠上下文工程） | ⚠ 定位不同：上下文压缩是 `dsh-GOkifu-compact` 的本职 |
| 分层：主上下文 + 外部存储 | 分层：完整日志（永不删）+ claim/边（可注入） | ✅ 同构 |
| 模型可编辑自己的记忆 | **禁止模型写记忆**：只有归档器机械抽取、裁决聚合器落账 | ⚠ 边界红线，方向相反 |
| 中断驱动控制流 | 我们挂在 `agent/pre-step` 这个**宿主给的**步边界 | ✅ 同构（且不自造控制流） |
| 多会话聊天中"反思" | 我们的 claim 是日志事实，不做模型反思 | ⚠ 见调研 26（Reflexion）的取舍 |

## 两条可复用结论
1. **分层是省 token 的关键**：MemGPT 把"窗口外的大库"与"窗口内的工作集"分开；我们对应的是
   "日志/棋谱永不删，注入只挑与当前信号相关的少量事实"，A6 溯源 100% 但 token p50 ~248 就是这个结构的效果。
2. **中断点必须是宿主给的**：MemGPT 自己造中断，我们只在宿主暴露的 `agent/pre-step` 上工作——
   这避免了"插件自己抢控制流"的整类风险（也是边界成文法写的红线）。

## 结论
无新机制可落地（模型自编辑记忆被禁止）；但确认了两点结构性选择是对的：**分层存储**与**只用宿主钩子**。
