# LangMem：热路径 vs 后台记忆管理（2026-11-02 采集）

- 来源：[github.com/langchain-ai/langmem](https://github.com/langchain-ai/langmem)（README，2026-11-02）。
- [外] 定位：让 agent「learn and adapt from interactions over time」，提供三种能力：
  1. **Core memory API**（可在任意存储上用）；
  2. **Memory tools（热路径）**：agent 在对话中主动调用 `manage_memory` / `search_memory` 记录与检索；
  3. **背景记忆管理**：后台自动抽取、**巩固（consolidate）与更新** agent 知识；
  4. 可选的 **prompt refinement**：通过提示词优化 agent 行为；与 LangGraph 的 Long-term Memory Store 原生集成。
- [外] 例子用 `InMemoryStore` + 1536 维 embedding 索引；生产建议 Postgres store。

## 与我们对照

| LangMem | 我们 | 判断 |
|---|---|---|
| 热路径记忆工具（agent 主动写） | **禁止**：只有聚合器落账，模型不能写记忆 | 产品立场不同（避免自证污染） |
| 后台抽取/巩固/更新 | `turn-stopping` 触发归档（D1）+ 卷/claim 派生 | ✅ 同构；我们只做机械抽取 |
| prompt refinement（改进提示词） | **越界**：不改系统提示词 | 明确不做 |
| 结构化存储 + 命名空间 | sidecar JSON + `scopeKey` 作用域 | ✅ 同构（无向量） |
| embedding 检索 | **禁止**（边界成文法） | 明确不做 |

## 可借鉴

- **「后台巩固」的时序**：LangMem 强调巩固发生在对话之外、且合并相关记忆——我们的 D1 归档 + 类级主卷已经是这个形状；
  可补的是「**巩固结果要能被回放**」（我们的 claim 有 support，已满足）。
- **热路径只读**：LangMem 让 agent 主动写；我们反过来只允许 agent **读**（注入），写全在后台。
  这个不对称是有意的，写进 `docs/记忆的职责边界.md` 时可用作对照。
