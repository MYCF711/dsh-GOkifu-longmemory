# Sleep-time Compute（Letta 团队，2026-11-02 采集）

- 来源：[arXiv:2504.13171](https://arxiv.org/abs/2504.13171)（2025-04-17，cs.AI）；代码 `letta-ai/sleep-time-compute`。
- [外] 核心：模型在**查询到来之前**离线「思考」上下文，预先算出有用量；把成本从 test-time 挪到离线。
- [外] 数据（作者自报）：
  - 达到同等准确率所需 test-time 计算量降低 **~5×**（Stateful GSM-Symbolic / Stateful AIME）；
  - 加大睡眠计算还能再涨 **13% / 18%** 准确率；
  - 同一上下文的相关多查询摊薄后，**平均每查询成本降 2.5×**；
  - 效果与「用户查询的可预测性」强相关；附一个真实 agentic SWE 案例。
- [外] 边界：不是新模型能力，而是**调度**——离线预计算 + 在线取用。

## 与我们已有的机制对照

| 论文机制 | 我们的对应物 | 差距 |
|---|---|---|
| 离线预计算 | D1 `agent/turn-stopping` 定时归档 + 插件加载预热 `walkCache` | 我们只预计算**索引**，没预计算**卡片** |
| 查询可预测性 | 我们的信号来自用户首条消息（主题/实体） | 可预测性中等；同类会话重复率高 |
| 多查询摊薄 | 每次 walk 现场算 | 未缓存「同一主题 × 同一作用域」的卡片 |

## 可落地（按边界过滤后）

- **N5 睡眠期预计算卡片（card cache）**：归档后为「高热主题 × 作用域」预生成卡片骨架（不含日期渲染），
  首轮命中直接取用；冷门主题仍走现场 walk。预期 A4 p95 再降，且不改变 A1/A2 语义（同输入同输出，需 digest 校验）。
- **N6 可预测性代理指标**：统计「首条用户消息的主题 key」在历史里的 df；df 高 ⇒ 值得预计算。
  这是机械量，不引入模型评分。
- 不做：把 LLM 放进睡眠期（成本/边界不允许）。
