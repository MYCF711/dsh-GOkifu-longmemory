# Zep：面向 agent 记忆的时序知识图（2026-11-03 采集）

- 来源：[arXiv:2501.13956](https://arxiv.org/abs/2501.13956)（2025-01-20，12 页）。
- [外] 核心组件 **Graphiti**：时序感知的知识图引擎，同时整合**非结构化对话**与**结构化业务数据**，并保留历史关系。
- [外] 指出现有 RAG 只做"静态文档检索"，而企业场景需要**动态知识整合**。
- [外] 在 MemGPT 团队主推的 **DMR** 基准上 **94.8% vs 93.4%**（超过 MemGPT）。
- [外] 在更难的 **LongMemEval** 上：准确率最高提升 **18.5%**，同时响应延迟**降低 90%**（相对基线实现）。

## 与我们对照

| Zep / Graphiti | 我们 | 判断 |
|---|---|---|
| 双时态（valid_at / invalid_at）维护历史关系 | `occurredAt / recordedAt / validFrom / validTo` | ✅ 同构，且我们多了 `validityOk` 探针 |
| 实体+边由 LLM 抽取 | 由机械抽取（topic/link/claim） | ⚠ 我们更笨但可回放 |
| 动态整合（对话 + 业务数据） | 单一来源：棋谱（会话日志+棋谱边） | 刻意收窄（边界成文法：无棋谱不入馆） |
| DMR / LongMemEval 基准 | 六轴 + 冻结卷 + 安慰剂 | 不可直接比：他们的基准要跑模型问答 |
| 延迟降低 90% | 真实会话注入 p50 15ms（Hindsight 4,715ms） | 量级一致：毫秒 vs 秒 |

## 两条可复用结论
1. **时序是记忆的一等属性**：Zep 的最大卖点是"保留历史关系而不是覆盖"，这正是我们 `validFrom/validTo` + `still 只增不改` 的选择；
2. **基准要选能反映真实场景的**：他们指出 DMR 太简单，转用 LongMemEval（跨会话合成、时序推理）。我们的对应物是"真实会话回放 + 冻结卷"，也在往"真实场景"靠。

## 结论
无新机制（Graphiti 的机制已在 `docs/调研/15` 消化）；本文提供了**外部基准证据**：
时序知识图在 LongMemEval 上带来最高 18.5% 提升、延迟降 90% —— 支撑我们继续把时间字段当一等公民。
