# Cognee：把会话蒸馏进知识图谱（2026-11-02 采集）

- 来源：[github.com/topoteretes/cognee](https://github.com/topoteretes/cognee)（README，2026-11-02）；
  论文 [arXiv:2505.24478](https://arxiv.org/abs/2505.24478)（Markovic et al., 2025，正文未读）。
- [外] 一句话：把文档、代码、会话变成**自托管知识图谱**，供 agent 检索与复用。
- [外] 四个操作（README 表格）：
  - `remember`：写入永久记忆；给 session ID 时写会话级记忆；
  - `recall`：自动路由或指定检索策略，取上下文/答案；
  - `improve`：**用反馈丰富记忆**，把会话知识**桥接**进图谱；
  - `forget`：删除指定条目或数据集。
- [外] 「文本 → 实体与关系；代码 → 符号与依赖图；**会话蒸馏**把被接受的教训固化进永久记忆」。
- [外] 自报 BEAM：100K tokens 0.79、10M tokens 0.67（两设置语料/模型/检索选择不同，README 自己提醒不可直接横比）。

## 与我们对照

| Cognee | 我们 | 差距 / 判断 |
|---|---|---|
| 会话蒸馏 → 永久记忆 | 归档 `episode → claim` + `support` 逐条溯源 | ✅ 已有，且我们只做机械抽取 |
| `improve`（反馈丰富记忆） | L4 人纠错（最高优先级证据，只记 correction+counter） | ✅ 同构；我们**没有**模型自我 improve |
| `forget` | `state: invalidated` + 只遮蔽可见性、原件不删 | ✅ 更保守（我们不真删） |
| 代码 → 符号/依赖图 | topic 抽取 repo/dependency/file/error + 相关边 | ✅ 部分同构 |
| 图 + 向量 + 全文混合检索 | 主题 exact/包含 + 类级错误 + 同错/同文件边 | ❌ 缺关键词/向量通道（N2 未做） |
| 单 Postgres 跑全套 | 纯 JSON sidecar + 内存索引 | 我们是单机零依赖，**不引入 Postgres** |

## 可落地候选

- **N10 「improve」的机械版**：人纠错（L4）后，把该 claim 的 `counter` 证据**回填**到同类 claim 的
  `preconditions`/`state`（只改状态与指针，不改原文）；这是 Cognee `improve` 在无模型条件下的可行子集。
- **N11 「forget」语义检查**：`forget` 在我们这里只能是 `invalidated`；可在 `cli` 加 `audit --invalid`
  列出"被遮蔽但仍可检索"的条目，确认没有泄漏到注入。
