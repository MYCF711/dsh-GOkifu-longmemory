## 一、leakage 的定义与代价：分数虚高，上线崩

- [外] **定义（原文）**："Data leakage occurs when **information that would not be available at prediction time**
  is used when building the model. This results in **overly optimistic performance estimates** … and thus
  **poorer performance when the model is used on actually novel data**, for example during production."
- [外] **铁律**："Test data should never be used to make choices about the model. **The general rule is to never call
  `fit` on the test data**."；"Always **split the data into train and test subsets first**, particularly before any
  preprocessing steps."
  ⇒ 判据不是"用了没用全部数据"，而是**"这个信息在预测时刻存在吗"**。
- [外] **毁灭性量化例子**（原文实测）：200 条样本 × **10000 个纯随机特征**、目标随机（期望准确率 ≈ **0.5**）。
  用**全部数据**做特征选择（`SelectKBest(k=25).fit_transform(X, y)`）再划分训练/测试 ⇒ 准确率 **0.76**；
  先划分、只用训练集做选择 ⇒ **0.5**。
  ⇒ **凭空多出 26 个点的准确率，全部来自"提前看到了测试集"**，而模型本身没变强。

## 二、"未来函数"的三种常见伪装

| 伪装 | 形态 | sklearn 的对应原文 | 本仓同款 |
|---|---|---|---|
| **M1 全局归一化/全局统计** | 用**全量**均值、方差、IDF、阈值、分位数做特征 | "if you have a normalization step where you divide by the average value, the average should be the average of the **train subset**, **not** the average of all the data" | 用**全库** df/IDF 给单题打分 |
| **M2 事后统计** | 用在**决策之后**才产生的字段（命中次数、跑过的文件、失败次数） | "information that would not be available at prediction time" | 把"该局实际碰过的文件"当检索信号（T249/T263） |
| **M3 用整局/全量做选择** | 先在全量上选特征/选信号，再切分评估 | 随机特征也能 **0.76** 的那个例子 | 先看完整局再决定"哪些主题算相关" |

**共同点**：三种伪装都让**评估时的输入**比**上线时的输入**多一点点——
而"多一点点"在随机数据上就能造出 20+ 个点（原文：0.5 → 0.76）。

## 三、"注入时刻可得"的机械判据

| # | 判据 | 可执行检查 | 判红条件 |
|---|---|---|---|
| **A1 时刻对齐** | 每个特征的 `availableAtSeq`（来源事件的最大 seq）必须 **≤ 注入点 seq** | 给每个特征标 `availableAtSeq`，与 `injectionSeq` 比较 | `availableAtSeq > injectionSeq` ⇒ **该特征不可用** |
| **A2 因果闭合** | 特征只能由 `seq < t` 的事件计算；任何 `over all …` 的聚合必须带显式 `asOf` 参数 | 静态扫特征路径里的聚合函数（`max/avg/count over all events/edges/claims`） | 无 `asOf` 的全局聚合 ⇒ **标红** |
| **A3 截断自证（决定性）** | 把事件流**截断到注入时刻**再跑，分数**必须不变** | 提供 `--as-of <seq>`，同一批题跑两遍（全量 / 截断） | 两次分数**不同** ⇒ **存在未来函数** |
| **A4 快照可复算** | 给一个人工写死的"注入时刻快照"，从它重算特征必须等于系统给的值 | 冻结一份 `snapshot@seq` 的 JSON，作为回归夹具 | 重算不等 ⇒ 特征依赖了快照外的东西 |

**A3 是唯一能一刀切的判据**：因为"信息是否可得"是**时间属性**，最直接的检验就是**把时间截断**。
若截断后分数掉了，那部分分数就是**泄漏出来的**，不是能力。

## 四、可执行的检查思路（机械发现考卷里混进事后信息）

1. **给每个特征打时间戳**：`availableAtSeq` 与 `availableAtEvent`（哪个事件让这个值第一次可算）。
   没有时间戳的特征，**默认视为不可用**（46 篇的纪律：未知不许吸收成通过）。
2. **静态扫描聚合**：特征路径上出现"对全集求值"的表达式（尤其 `df`、`IDF`、`count(all)`、`normalize by mean(all)`）⇒ 要求带 `asOf`。
3. **截断重跑进 CI（A3）**：`node … eval --as-of <seq>` 与全量跑结果必须**逐题相同**；
   不同则输出**差值最大的题**（那就是泄漏源）。
4. **单调性检查**：把日志尾部截掉 N 个事件，同一时刻的特征值必须**不变**；
   若变化 ⇒ 该特征用到了尾部信息（这是 A2 的运行时版本）。
5. **三路对照**：A=基线、B=只加"注入时刻可得"的信号、C=加全量信号。
   **C−B 就是泄漏量**，真实收益只看 **B−A**。

## 五、对照本仓（棋院，写作时点实测）

- T249/T263 把"**该局实际碰过的文件**"加进检索信号，主判据从 **34% 涨到 77%**（+43pp）。
- 但那是**该局会话执行完之后**才知道的信息；真实注入点在 `pre-step`（第一个 step 之前），
  那时系统**只知道用户说了什么**。
- T264 三路对照（A/B/C）证明：**C − B = +53.19pp 全部是作弊带来的虚高**，**真实冷启动只有 34.21%**。
- 更硬的一条：**原话里只有 20.18% 的题含实体**（文件路径/错误码），其余是「处理一下」「修一下」——
  **冷启动时根本拿不到更多线索**，这不是模型弱，是**信息不在**。

**映射到 sklearn 那个例子**：我们的 **77%** 就是那个 **0.76**（随机特征也能拿到的分数），
**34.21%** 才是接近 chance 的**真实水平**；"该局碰过的文件"正是 M2 型未来函数——
它同时满足 A1 判红（`availableAtSeq` 远大于 `injectionSeq`）与 A3 判红（截断到注入时刻后分数掉回 34%）。

## 结论

一句话判据：**一个信号只有在 `availableAtSeq ≤ injectionSeq` 时才算数**；不能证明这一点的，默认不可用。
三种伪装（全局归一化 / 事后统计 / 全量选特征）都能让随机数据凭空多出 20+ 个点——
所以**评估必须做 A3：把时间截断到决策时刻，分数必须不变**。
我们的 77% 是那个 0.76，**34.21% 才是真的**；而 20.18% 的实体率说明：
**冷启动的天花板由"用户话里有多少信息"决定，不由模型决定**。
