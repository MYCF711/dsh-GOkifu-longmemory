# MemOS：把记忆当系统资源（2026-11-02 采集）

- 来源：[arXiv:2507.03724](https://arxiv.org/abs/2507.03724)（v4，2025-12-03；36 页）。
- [外] 主张：LLM 缺**显式记忆管理层**；RAG 只是无状态外挂，没有生命周期控制。
- [外] 机制：
  1. **MemCube** 为基本单元：内容 + 元数据（**provenance、versioning**）。
  2. MemCube 可 **compose / migrate / fuse**，在不同记忆类型间迁移（明文 / 激活 / 参数级）。
  3. 统一**表示、调度、演化**；把记忆当作可管理资源（存储与检索成本可控）。
  4. 目标：controllability / plasticity / evolvability。
- [外] 本页未读全文，仅摘要级；不引用其具体数字。

## 与我们对照

| MemOS | 我们 | 差距 |
|---|---|---|
| MemCube 带 provenance + version | `episode/claim` 有 `occurredAt/recordedAt/support/validity`、`supersedes` | **没有显式 version 字段**（靠 supersedes 链隐式表达） |
| compose / fuse | 只有 `supersedes` / `corroborates` | 缺「多条 claim 合成一条更粗结论」的机械操作 |
| migrate（类型迁移） | 无 | 与我们边界无关（不做参数级/激活级） |
| 生命周期 | `state: observed/candidate/stale/invalidated` | 已有，够用 |

## 可借鉴（边界内）

- **N7 claim 显式 version**：`version:int` + `supersedes` 双写，渲染时可显示 `v2`；迁移成本低，利于审计。
- **N8 合成操作（fuse）**：同类 claim ≥3 局支撑且无反例时，生成一条**更粗粒度**的 claim（`derives` 边指向原条目），
  原条目保留。关键：合成只做文本拼接与计数，不调模型（否则越过「禁止从摘要再抽取」）。

## 不采用

- 参数级/激活级记忆迁移（需要训练管线，与本项目无关）。
- 无 provenance 的记忆融合（我们会坚持 support 逐条可回溯）。
