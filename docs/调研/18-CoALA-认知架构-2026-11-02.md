# CoALA：语言 agent 的认知架构（2026-11-02 采集）

- 来源：[arXiv:2309.02427](https://arxiv.org/abs/2309.02427)（v3，TMLR camera-ready，2024-03-15）。
- [外] 主张：当前的 language agent 缺一个**系统框架**。CoALA 给出三件：
  1. **模块化记忆组件**；
  2. **结构化动作空间**（对内操作记忆、对外作用于环境）；
  3. **广义决策过程**（选择动作）。
- [外] 用 CoALA 回顾并组织了大量近期工作，并前瞻性地指出方向。本页只读摘要，不引用其具体分类细节。

## 与我们对照（按摘要级概念，不臆造类型名）

| CoALA 要素 | 我们 | 谁负责 |
|---|---|---|
| 模块化记忆组件 | `episode`（局）+ `claim`（事实/反模式/偏好）+ `joseki`（定式）+ `topics/links`（关系） | 本仓 |
| 其中「工作记忆」（当前会话上下文） | **不在本仓** | 压缩插件 + 宿主上下文 |
| 内部动作：检索 | `walk`（顺藤摸瓜，钩子里触发） | 本仓 |
| 内部动作：学习/写入 | 归档时机械抽取（不是模型自学习） | 本仓 |
| 外部动作（工具/环境） | **不做** | 宿主工具 |
| 决策过程 | 宿主决定何时调用；我们只响应 `agent/pre-step` | 宿主 |

**关键点**：CoALA 把"工作记忆"也算记忆。我们的边界成文法把它划给压缩插件——
所以我们的 `方案.md` 必须永远写清"本仓只覆盖长期记忆层"，否则会被读成"记忆系统缺一块"。

## 可借鉴（仅一条，且不改代码）
- **动作空间要显式**：我们的内部动作只有"检索"和"归档（学习）"两件，且写入权在聚合器；
  可在 `docs/记忆的职责边界.md` 增一节「本仓的动作空间」，把这两件事与"不做的动作（工具调用/改写上下文）"并列写死。

## 结论
CoALA 是一张"定位图"而不是新机制：它印证我们的分层（episodic/semantic/procedural 都有），
也解释了为什么必须把工作记忆明确交给压缩插件——这正是边界成文法存在的理由。
