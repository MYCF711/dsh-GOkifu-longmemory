## 一、三值逻辑的真值表：UNKNOWN 会被"吸收"

- [外] **SQL 是三值逻辑**：原文 "SQL uses a **three-valued logic** system with true, false, and `null`,
  which represents '**unknown**'."
- [外] **AND/OR 的吸收规则**（同页真值表，逐行原文）：

  | a | b | a AND b | a OR b |
  |---|---|---|---|
  | TRUE | **NULL** | **NULL** | **TRUE** |
  | FALSE | **NULL** | **FALSE** | **NULL** |
  | NULL | NULL | NULL | NULL |

  即：**`FALSE AND unknown = FALSE`、`TRUE OR unknown = TRUE`** —— unknown 被另一个操作数**吸收**，
  结论已定就再也看不到"这里其实缺证据"；而 `NOT NULL = NULL`，否定也救不回未知。
- [外] **比较运算遇到 unknown 就产出 unknown**：原文 "Ordinary comparison operators yield null (signifying
  'unknown'), not true or false, **when either input is null**. For example, `7 = NULL` yields null,
  as does `7 <> NULL`." 且**不许写 `= NULL`**："`NULL` is not 'equal to' `NULL`… the null value represents an
  unknown value, and it is not known whether two unknown values are equal."
- [外] **需要"把 null 当成一个普通值"时，用显式的 null-safe 谓词**：`IS DISTINCT FROM` /
  `IS NOT DISTINCT FROM` —— "effectively act as though null were a normal data value, rather than 'unknown'"；
  例：`NULL IS DISTINCT FROM NULL` → **f**（而不是 NULL），`1 IS DISTINCT FROM NULL` → **t**（而不是 NULL）。
- [外] **要强行得到 true/false，必须用 `IS TRUE/IS FALSE/IS UNKNOWN` 家族**：文档明说
  "These will **always return true or false, never a null value**, even when the operand is null."
  例：`NULL::boolean IS TRUE` → **f**、`NULL::boolean IS UNKNOWN` → **t**、`NULL::boolean IS NOT TRUE` → **t**
  （即"'真'未被证实"涵盖 false 与 unknown 两种）。**注意 `IS NOT TRUE` ≠ `IS FALSE`**：
  前者把 unknown 也归入"不真"，后者对 unknown 返回 **f**。
- [外] **行值（row）上的 `IS NULL` / `IS NOT NULL` 不是互补的**（同页 "row-valued" 段）：
  含 null 与非 null 字段的行，两个测试**都返回 false**——同一个对象在两条互补断言下同时"不通过也不失败"。
  文档给的替代写法是 `row IS DISTINCT FROM NULL` / `IS NOT DISTINCT FROM NULL`。
- [外] **`WHERE` 只保留 TRUE**：三值里 UNKNOWN 与 FALSE 在过滤时同命（都不满足），
  所以"没有报错"与"确认为真"在 `WHERE` 这个形状里**不可区分**——这是 unknown 被静默丢弃的入口。

## 对照本仓（棋院）

audit-12 揭出的三条刚好是"未知的三种命运"：

| 闸 | 现象 | 原来的处理 | 等价于 SQL 的哪个形状 |
|---|---|---|---|
| 闸 2 | 合并节点的**成员取不到** | 只计数，按记录自身 state **放行** | `FALSE AND unknown = FALSE` —— 被吸收成"通过" |
| 闸 4 | `mergedInto` 指向的**节点不存在** | 只记 unresolved，**不报错** | `x = NULL` 恒为 unknown，再被 `WHERE` 丢掉 |
| 闸 3 | 探针**读不到** | 判 `unverified` | `IS UNKNOWN` —— **唯一处理对了的那条** |

**机械判据（三者不许混）**：

| # | 断言性质 | 证据缺失来源 | 判定 | 依据 |
|---|---|---|---|---|
| A | **结构性不变量**（成员必须可达 / 反指针必须落地） | 库内缺失、悬空 | **FAIL** | 我们查的是**自己的库**，取不到就是数据坏了，不是"外部不可达"；对应 `IS NOT TRUE` 里 unknown 也算"未证实" |
| B | 结构性不变量 | **外部**不可达（文件/网络/探针） | **unverified**（不判绿、不进通过数、单独计列） | 对应 `IS UNKNOWN`：可观测地"未知"，而不是"通过"或"失败" |
| C | 非必须断言（可选字段/可选证据） | 任意 | **PASS，但必须显式 `allow-missing` + why** | 默认不放行；省略必须有**记录**，不能靠沉默 |

**四条实现纪律（可直接指导 T199）**：

1. **禁止吸收**：判定链里 `INVARIANT AND unknown` 必须得 **FAIL**，不能像 SQL 那样 `FALSE AND unknown = FALSE`。
   实现上就是：汇总"通过"只接受**明确为 PASS** 的项（`IS TRUE` 口径），而不是"非 FAIL 即通过"。
2. **三态必须落盘**：每个闸输出 `pass | fail | unverified`（不是 boolean），且汇总时**分母分列**
   （pass/fail 一起算，unverified 单列），否则 unknown 一混进分母就成了"通过率"的一部分。
3. **悬空引用要用 null-safe 判定**：`mergedInto` 的检查不能用"找不到就算不相等"（= SQL 的 `= NULL`），
   必须显式区分"目标存在且匹配""目标存在但不匹配""**目标不存在**"三种，第三种是 **FAIL**。
   这正是 `IS DISTINCT FROM` 存在的理由：把 null 当普通值比较，而不是让它坍缩成 unknown。
4. **不要用互补断言假装完备**：`IS NULL` 与 `IS NOT NULL` 在复合对象上可以同时为 false。
   我们的"成员取得到"与"成员取不到"两条检查如果都基于同一份不完整索引，就会出现**两边都不报**——
   所以结构性检查要**从原始存储直接取**，而不是从派生视图自证。

**能借的**：`IS UNKNOWN` 家族（"总能给出 true/false"的显式三态）→ 我们的闸也该提供"这条到底是 pass、
fail、还是没测到"的显式答案；以及 `IS DISTINCT FROM` 的 null-safe 比较 → 悬空引用的判定。
**不借的**：`WHERE` 式的"只留 TRUE"聚合（它天生把 unknown 与 false 合并，正是我们踩的坑）；
以及"`= NULL` 恒 unknown"的隐式语义（我们要求**显式**三态，不允许默认值兜底）。

## 两条可复用结论

1. **三值逻辑的危险不在"多了一个值"，而在"这个值会被吸收"**：SQL 里 `FALSE AND unknown = FALSE`
   是对的（结论已定），但在校验系统里**同一个形状会让你在缺证据时也判通过**。
   所以校验必须自己定义吸收规则：**未知向上传播为 FAIL 或单列，绝不被吸收为 PASS**。
2. **"没报错"不是"确认过"**：`WHERE` 把 UNKNOWN 和 FALSE 一起过滤，于是"没有违反"看起来像"验证通过"。
   要分开只能靠**显式三态输出 + 分开的分母**——这和我们 44 篇"核身份不核数量"是同一族纪律的两面。

## 结论

无需改机制（只读 + 三态输出本来就该有）；需要落地的是四件事：
**禁止吸收（unknown ⇒ FAIL 或单列）**、**三态落盘 + 分母分列**、**悬空引用用 null-safe 判定**、
**结构性检查从原始存储取而不是派生视图自证**。
audit-12 的那三条，恰好就是 SQL 真值表上的三行：一行被吸收、一行坍缩成 unknown 后被丢弃、一行做对了。
