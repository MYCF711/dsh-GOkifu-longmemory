# MemoRAG：全局记忆 + 线索式检索（2026-11-03 采集）

- 来源：[arXiv:2409.05591](https://arxiv.org/abs/2409.05591)（v3，2025-04-09；TheWebConf 2025）。
- [外] 指出传统 RAG 的两个隐含前提在长文本任务里不成立：**查询是显式写出来的**、**知识是结构良好的**。
- [外] 双系统架构：
  1. **轻量长程系统**：为长文本建一个**全局记忆**；任务一来先产出**草稿答案**，草稿给检索工具提供"去哪儿找"的线索；
  2. **昂贵表达系统**：依据检索到的内容生成最终答案。
- [外] 记忆模块用 **KV 压缩**实现，并用"生成质量的反馈"（RLGF）强化记忆与线索能力。

## 与我们对照

| MemoRAG | 我们 | 判断 |
|---|---|---|
| 全局记忆 | `index.md` 一行（局数 + scope + "未列出≠不存在"） | ✅ 形态相似，但我们的是**计数指针**，不是语义记忆 |
| 草稿答案 → 检索线索 | 没有草稿；线索直接取自**当前消息**的报错原文/主题 | ⚠ 差异：我们不做"先猜再找" |
| KV 压缩记忆 | 不做（压缩是另一个插件的本职） | 边界外 |
| RLGF 反馈强化 | 不做模型训练；只用机械闸 | 有意不同 |
| 双系统 | 单系统（步边界一次走完） | 有意简化 |

## 可借鉴的一点（候选 N6，非实现）
"先产草稿、再据此检索"本质是**查询改写**。我们不用模型，但可以做一个**机械版**：
把当前消息里抽到的错误签名 + 命中主题拼成一条"扩展查询"（不改原文），用于 walk 的起跳。
- 风险：等于放大误命中（A2b 严格可能掉）；且 0.44 的"给 claim 文本加关键词"实验已证明改文本无效，
  改**查询**是另一条路，但同样需要先做离线对照。
- 当前不做：冻结集上尚无证据；先记入候选。

## 结论
MemoRAG 印证"全局记忆应当参与检索决策"，而不是只当背景。我们的 `index.md` 目前只做"存在性提示"，
没有参与 walk 起跳——这是**结构上可对照的差距**，但补它要动检索层，必须有 A2b 前后对照，记 N6。
