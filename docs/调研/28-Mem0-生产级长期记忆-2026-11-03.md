# Mem0：生产级长期记忆（抽取 / 整合 / 检索）（2026-11-03 采集）

- 来源：[arXiv:2504.19413](https://arxiv.org/abs/2504.19413)（2025-04-28）。
- [外] 架构：从对话中**动态抽取 → 整合（consolidate）→ 检索**显著信息；另提供**图记忆**变体捕捉关系结构。
- [外] 评测基准 **LOCOMO**，四类问题：single-hop / temporal / multi-hop / open-domain。
- [外] 结果：相对 OpenAI 记忆方案，LLM-as-a-Judge **提升 26%**；图记忆再高约 **2%**；
  相比"全上下文"方案，**p95 延迟低 91%、token 成本省 90%+**。

## 与我们对照

| Mem0 | 我们 | 判断 |
|---|---|---|
| 抽取：LLM 从对话里抽事实 | 机械抽取（失败边/信号/主题） | ⚠ 路线相反；我们可回放、不花模型调用 |
| 整合：ADD / UPDATE / DELETE | **只增不改**：新条目 + `supersededBy`，旧条保留 | ⚠ 他们允许删改；我们的红线是原件永不删 |
| 图记忆捕获关系 | link（shared-topic / same-error / same-file） | ✅ 同构，且每条边带 `why` |
| 检索：相似度 + 时间衰减 | 关键词+类别+作用域闸 + 有效期遮蔽 | 不同：我们不用向量、不做衰减 |
| LOCOMO 四类问题 | A2b 冻结卷（19 条）+ LOO + holdout | 我们的评测更小但更可控（可复算） |
| p95 延迟 −91%、token −90% | 真实注入 p50 22.4ms（Hindsight 4,715ms）、tokens p50 ~248 | ✅ 同方向，量级不同（他们对比全上下文） |

## 两条可复用结论
1. **"整合"是长期记忆的价值核心**：单纯堆检索会退化；Mem0 的 UPDATE/DELETE 与我们的 `supersededBy` 是同一问题的两种解法
   （他们删改以省空间，我们保留以保可回放）——差异源于边界，不是能力。
2. **评测维度要能对上真实使用**：LOCOMO 的 temporal/multi-hop 对应我们的"有效期 + 藤上两跳"，建议 A2b 下一版按这四类分桶重算（已有 `evidence/a2b-set.json` 可扩展）。

## 结论
无新机制可落地（LLM 抽取被边界禁止）；但给了两条外部证据：
**结构化记忆比全上下文更省更快**（−91% 延迟 / −90% token），以及**图记忆的增益有限（约 +2%）**——
后者支持我们"先把失败教训做对，再谈关系网"的优先级。
