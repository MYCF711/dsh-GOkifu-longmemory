## 对照本仓（棋院）

这篇论文对我们最有价值的地方，是它把"**读过旧版本**"这件事单独拎出来量了：
**旧事实不是噪声，是反向证据**。棋院的 `supersededBy` / `validTo` / `state: stale` 只做了
"新旧并存 + 日期标注"，这在读侧还不够——只要注入把旧条正文一起递上去，模型就可能被它带偏。

| 论文发现 | 对棋院意味着 | 判断 |
|---|---|---|
| 最新事实已检索到，仍答错（45% → 32%） | "命中了"和"用上了"是两件事：我们的注入按"命中即注入"不够 | ⚠ 需补：注入的是**结论**不是**证据堆** |
| 等大小下，过时竞争陈述比无关证据更有害（100% → 44.6%） | 旧 claim 的**正文**不该和新 claim 一起进上下文；旧条的指针可以留 | ✅ 可借：**遮蔽优先于并列** |
| 预算越大越差（64 → 512 tokens） | 支持"少而准"：注入条数与字符预算要卡死，宁少勿多 | ✅ 同向（现为 ≤K 条、每步有上限） |
| 32K 复现同向（69% vs 58%） | 不是 6K 特例，规模放大不解决冲突 | ✅ 支持不在语料规模上加码 |
| 50/50 有害翻转全部是 stale | 伤害可机械归因：只来自"过时版本被看见" | ✅ 可做**机械检查**，不需要模型判分 |

**能借的两点（都能做成机械规则，不进模型判断）**：

1. **注入侧"遮蔽优先于并列"**：对被 `supersededBy` / `validTo` 覆盖的条目，注入只给
   `指针 + 一句话 + 覆盖日期`，**不给正文**；正文只给最新那条。这正好是现成字段（`state` / `supersedes`），
   不需要新数据，也不需要模型参与。
2. **评测加一组"新旧同题"用例**：同一 question 给两条互相矛盾的 claim（一条 `validTo` 已过），
   断言渲染结果里**只出现新条正文**、旧条以指针出现、且日期可核。这是唯一能**机械**证明
   "我们的去重/遮蔽策略没有把模型带进旧事实"的办法；用他们的话说，就是把 retrieval 分数与
   utilization 分数拆开。

**明确不借的三点（附理由）**：

1. **提示词工程 / 采样策略修复**：论文本身在冻结提示词下做对照，说明"换个 prompt"不是它的解法；
   而且任何 prompt 级修复都要在本仓**调模型**，与"无模型判断、无向量、零模型调用"的边界冲突。
2. **把"记忆预算"交给检索器自适应**：他们量的是 BM25 预算；我们若要复现这种扫描，得先有
   可复算的检索器与真实语料消费者——现在做只会得到一个没人消费的假指标。
3. **拿它当"产品效果"证据**：alphaXiv 摘要在二手层面指出这是**合成基准、非部署 agent**；
   所以我们只把它当**机制证据**（"旧条有害"这个方向可信），不当效果承诺。

## 两条可复用结论

1. **记忆系统的失败模式有两个**：找不到（recall）与**看见了旧版本**（stale interference）。
   后者更隐蔽——因为检索指标看起来是满分。我们的"只增不改"必然让旧条长期存在，
   所以**遮蔽必须发生在注入前**，而不是指望模型自己按日期判断。
2. **可解释性也是正确性**：他们能把 50 次有害翻转**逐条归因到 stale**；我们同理应能回答
   "这次答错是因为注入了哪条旧记忆"——`supersededBy` 链 + `occurredAt` 恰好够做这件事。

## 结论

无新机制可落地（其修复路径在提示/采样，被边界挡掉）；但它给了我们**一个必须补的工程缺口**：
把"新旧并存"从**并列展示**改成**遮蔽 + 指针**，并用一组机械用例证明旧条不再进正文。
它同时是本仓"只增不改"取舍的**外部代价说明**：不写时覆盖 = 旧条永远在库里，
所以读侧遮蔽不是可选项，而是这条取舍的配套成本。
