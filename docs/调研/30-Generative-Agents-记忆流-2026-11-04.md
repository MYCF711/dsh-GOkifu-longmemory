# Generative Agents：记忆流 + 反思 + 检索三元（2026-11-04 采集）

- 来源：[arXiv:2304.03442](https://arxiv.org/abs/2304.03442)（v2，2023-08-06）。
- [外] 记忆架构：**完整经历记录**（memory stream）用自然语言存储，随时间**反思**（reflection）合成为更高层记忆，
  再**动态检索**；三者（observation / planning / reflection）经消融验证都对行为可信度有贡献。
- [外] 检索打分通常按 **recency（时间近）/ importance（重要）/ relevance（相关）** 组合（该文与后续实现常见口径）。
- [外] 场景：25 个 agent 的小镇沙盒；从"一个 agent 想办情人节派对"扩展出邀请、约会、按时到场等涌现行为。

## 与我们对照

| Generative Agents | 我们 | 判断 |
|---|---|---|
| memory stream：完整经历全存 | 会话日志 + 棋谱边**永不删** | ✅ 同构（原件永不删） |
| reflection：模型把经历合成更高层记忆 | **禁止模型写记忆**；只有机械抽取/裁决聚合落账 | ⚠ 方向相反（边界红线） |
| 检索 = recency + importance + relevance | relevance（主题/错误类）+ 作用域闸 + 有效期；**不做时间衰减** | ⚠ 我们**故意不用 recency 权重** |
| importance 由模型打分 | 计数（支撑局数/反例数），不用模型评分 | ⚠ 红线一致：计数不是打分 |

## 两条可复用结论
1. **"完整记录 + 少量动态检索"是对的骨架**：他们也是全存 + 检索，不是"摘要替换原文"；
   这与我们"日志/棋谱永不删 + 注入只挑少量事实"一致。
2. **recency 权重是双刃**：它让 agent 更像人，但会让"旧但仍然有效的教训"沉底。
   我们六轴里的 A2b 就依赖"旧签名也要召回"，所以**不引入 recency**——这是有意识的分歧，不是没想到。

## 结论
无新机制可落地（反思与重要性打分都属模型判断，被边界禁止）；但确认了两点：**全存 + 检索**的骨架、
以及**不引入 recency** 的取舍理由，值得写进对标文档免得以后被"看起来更先进"的方案带跑。
