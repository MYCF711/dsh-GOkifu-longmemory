# 记忆不是免费午餐：经验复用的负迁移、检索多样性塌缩与稳定性-可塑性权衡（2026-11-08 采集）

- 来源：[arXiv:2604.27003](https://arxiv.org/abs/2604.27003)（**When Continual Learning Moves to Memory: A Study of Experience Reuse in LLM Agents**；
  作者 **Qisheng Hu / Quanyu Long / Wenya Wang**（**Nanyang Technological University**）；
  v1 **2026-04-29**；正文 [HTML](https://arxiv.org/html/2604.27003) 已读 §1–§6、Limitations、附录 D（检索多样性塌缩），访问日期 **2026-11-08**）。
- **范围声明**：`docs/调研/00` 的 01–93 已覆盖 Mem0/Letta/Zep 的系统篇、MemUse 的使用点评测（#92）、Zep Agent Skills 的过程性记忆（#93）等。
  本篇是**第一篇"经验复用 × 负迁移"的受控实证**：它不提出新记忆系统，而是把「记忆表示（raw vs insight）× 记忆组织（粒度、检索频率）」拆成两轴，用**持续学习指标**（前向/后向迁移）量「记忆到底帮忙还是帮倒忙」。
  与 #92（怎么量"被用上"）、#93（过程怎么编译）互补：本篇回答「**哪些经验该留、哪些经验会害人**」。
- **一句话结论**：[外] 外部记忆**没有**消掉稳定性-可塑性两难，只是把冲突从**参数更新**挪到了**检索竞争**：原始轨迹（raw）跨任务时产生**负迁移**（ALFWorld A→B：`ΔRR=+4.6` 但 `ΔNL=−26.1`——简单题保住、难题被带崩），抽象洞见（insight）把迁移翻正；**细粒度存储不是普遍更好**（同质记忆会「检索多样性塌缩」：88.5% 查询挤到同一条，检索覆盖率跌到 5.4%，同任务内 −17pp）；**前向最强的配置后向忘得最多**（BabyAI A→B：Cond-Ind 前向 +15.0% 但 BWT −10%）。

## 一、它问的问题

- [外] **记忆增强的 agent 看起来绕过了持续学习的稳定性-可塑性两难**：不更新参数、只往外部记忆里追加经验。论文的主张是：**这个两难没有消失，只是换了位置**——在有限上下文窗口里，新旧经验在**检索**时竞争同一条进入决策的通道。
- [外] 于是经验复用有两个可分离的设计轴：
  - **表示（value）**：一条记忆保留**原始、实例相关的过程细节**，还是**抽象、可迁移的洞见**（Study 1）；
  - **组织（key）**：**存储粒度**（一条记忆 = 整个任务包，还是一条洞见？）× **检索粒度**（每个任务实例检索一次，还是执行中反复检索？）（Study 2）。
- [外] 现有工作常把「同任务内更好」当成「更好」；论文专门测**跨任务**：同一份记忆，换个任务族还成立吗？

## 二、方法：用持续学习指标两两对比

- [外] **序列 A → B**：先在任务族 A 上累积经验，再在任务族 B 上跑；同时跑 `∅ → B`（无记忆基线）和反向序列 `B → A` 作对照。
- [外] **前向迁移 FWT**（对后一个任务）：`FWT(A→B) = Acc_B(∅→A→B) − Acc_B(∅→B)`；**FWT < 0 = 负迁移**。
- [外] **后向迁移 BWT**（对前一个任务）：`BWT(A→B) = Acc_A(∅→A→B) − Acc_A(∅→A)`；**BWT < 0 = 遗忘**。
- [外] **两种失败模式必须拆开**（本仓最该抄的口径）：用无记忆基线把测试集分成**基线成功子集（简单题）**与**基线失败子集（难题）**，再算：
  - `ΔRR`（Retention Rate 变化）< 0 ⇒ **有害复用**（跨任务记忆把本来会做的题弄坏）；
  - `ΔNL`（New Learning 变化）< 0 ⇒ **无效复用**（跨任务记忆帮不上难题，甚至更糟）。
  > 平均成功率会把这两件事平均掉；拆开才能说清「负迁移到底伤在哪」。
- [外] **环境**：ALFWorld（A=`pick_and_place` 基线 95%，B=`pick_clean_place` 54%）与 BabyAI（A=`action_obj_door` 70%，B=`find_obj` 49%）；每对任务一个代表序列、**每个条件跑两次**、单一稀疏检索骨干。
- [外] **记忆条件**：Study 1 = Raw（原始轨迹）vs Insight（抽象洞见）；Study 2 = 存储粒度 Agg / Cond-Ind，检索频率 Ind / Cond-Step。

## 三、Study 1（表示）：抽象更安全，负迁移集中在难题

- [外] **Raw 在两个环境的 A→B 都产生负 FWT，Insight 把它翻正**。作者的解释：A 相对容易、B 更难，raw 轨迹带着「看起来相关但缺了额外结构」的过程——ALFWorld 里 A 的轨迹是 `take → go → place`，B 还需要一步 `clean`；raw 会推着 agent 做一个**局部合理、全局不对**的动作。
- [外] **负迁移不均匀**：ALFWorld A→B 下 Raw 的 `ΔRR=+4.6`（简单题基本保住）但 `ΔNL=−26.1`（难题被带崩）——**能做的题怎么做都行，不会做的题最依赖检索到的指引，也最容易被害**。Insight 大幅减小这个不对称。
- [外] **同任务优势不能预测跨任务收益**：ALFWorld 的 Task B 上 Raw 同任务内大幅领先（细节轨迹在同分布内信息量大），一旦跨任务复用优势消失、Insight 略胜；BabyAI 上更直接——Raw 下降、Insight 上升，出现交叉。**「同分布内最好的表示」不一定是跨任务部署的最好选择**。
- [外] **抽象还能减少遗忘**：BabyAI 的 `B→A` 上 Insight 得到正 BWT（+3.5），Raw 造成遗忘（−4.0）；ALFWorld 两者都只有中等遗忘（Raw −5.5 / Insight −3.5）。作者的解释是「Insight 记的是任务无关原则，混进池子是在**丰富**而不是**污染**」。

## 四、Study 2（组织）：细粒度不是普遍更好，会出现「检索多样性塌缩」

- [外] **存储粒度（Agg vs Ind）**：BabyAI A→B 里 Cond-Ind **+15.0%**（Agg +9.0%；`ΔRR=+19.4`、`ΔNL=+10.8`）——A 有三个不同子任务类型，拆成独立条目后每条有不同检索键，能对上 B 的查询；但 **B→A 反转**：Cond-Ind **−1.0%**、Agg **+7.5%**——B 的洞见高度同质（都是「find [object]」式的网格搜索），拆开只制造一堆**几乎一样**的条目。
  ALFWorld 则相反：A→B 下 Agg **+6.5**、Ind **−2.0**（只有 Agg 的两个诊断都为正：`ΔRR=+9.3`、`ΔNL=+3.3`）——ALFWorld 依赖**连贯的多步策略**，拆开就破坏了结构。
- [外] **检索频率（Ind vs Step）**：BabyAI B→A 里 Step **+7.5%**（Ind −1.0%）——A 有「先导航、再交互」的明显阶段，执行中重查有帮助；但 A→B 反转（Step **−2.5%**、Ind **+15.0%**）——B 全程是均匀的网格搜索，重查只会拿回冗余内容。ALFWorld 跨任务差异小（±1.5pp），但**同任务内 Step 明显更高**（Task B 79.5% vs scratch 55.0%）——**同任务收益同样不迁移**。
- [外] **稳定性-可塑性**：BabyAI A→B 里 **Cond-Ind 前向最强（+15.0%）→ 后向最差（BWT −10%）**；机制不是参数覆盖而是**记忆稀释**——B 训练后池子被大量同质的网格搜索洞见占据，再回到 A 时，查询检索到的是这些新条目，**旧记忆没被删掉，只是越来越难被取到**（附录 F）。Cond-Agg 靠聚合保持池子紧凑，Cond-Step 靠分步检索在稀释的池子里仍能翻出不同条目。
- [外] **检索多样性塌缩（附录 D 的量化）**：Cond-Ind 在**同质源记忆**上键多样性 >0.91，但 **88.5% 的查询挤到同一个 top-1 条目**，**检索覆盖率跌到 5.4%**（Cond-Agg 下上下文多样性 0.41 vs Cond-Ind 0.38），同任务内 **−17pp**。作者的原话：**塌缩在存储侧不可见**（键多样性一直很高），**只在检索时显形**——所以「池子里有多少条」「键多样不多样」都不足以预测检索效果。

## 五、局限（作者自陈）

- [外] **受控优先于覆盖**：每个环境只取**一对**代表任务、**单一**稀疏检索骨干、**每条件两次运行**；作者明说不是穷尽，是为了把迁移/遗忘/检索效应隔离出来。
- [外] 结论的普适性需要更多任务对、更多检索器、更大规模重复；**没有跨模型/跨 agent 框架的复现**。

## 七、对照本仓（棋院）

| 论文 | 棋院现状 | 判断 |
|---|---|---|
| **负迁移拆两种失败模式**（ΔRR 有害复用 / ΔNL 无效复用） | 我们的硬约束是「负迁移 ≤5%」，但 T9/T29 的 ablation 只报「A 臂踩坑 vs B 臂踩坑」一个数；**没有把「把会做的弄坏」与「难题没帮上」拆开** | ✅ **可直接抄口径**：≤5% 应定义为**有害复用**（基线成功子集上的 ΔRR<0），并单列**无效复用**（难题子集 ΔNL<0）；两者不能平均 |
| **同任务优势 ≠ 跨任务收益** | T9 的合成坑是**同任务**重复；T26/T29 的对照也在同一题面 | ⚠ **警告**：同任务 ablation 只能证机制，**不能**推出真库跨局收益；跨任务要另设任务对（不同坑族） |
| **raw vs insight：抽象更抗负迁移** | 我们的恢复事实是**原始轨迹**（「失败 → 后来同一命令成功」+ 日期/seq），T34 的 exact/same-file/same-tool 也是**字面匹配** | ✅ **可借**：给恢复事实加**洞见层**（失败原因类别 + 正确做法的抽象），用 raw/insight 两档跑迁移对照；这也可能抬覆盖率（字面匹配之外还能按类别命中） |
| **细粒度不是普遍更好；同质记忆会塌缩** | 我们的 claim 是**逐条**存（一条记忆一个 claim），指针档/聚合档刚起步（T3/T31） | ✅ **可借**：对**同质 claim**（同一错误签名的多个变体、同一文件的多条恢复）先聚合再注入；用「检索覆盖率」而不是「池子大小」验收 |
| **检索多样性塌缩：存储侧看不见，检索时显形** | 我们只有注入次数（`injections`），**没有「池子里多少条被检索过」** | ✅ **可借**：加 **retrieval coverage**（被检索过的 claim / 可检索 claim），塌缩时降级为聚合；这是「哪些记忆该退役」的机械判据（长期 0 检索 + 同质变体多 ⇒ 退役/合并） |
| **记忆稀释：旧记忆没删但取不到** | 我们的冷却/衰减（#90/#91）是「没人用 ⇒ 权重降」；但**没有测「被新记忆挤掉」** | ✅ **可借**：「取不到」与「没用」是两件事；退役判据要能区分「被稀释」与「真没用」 |
| **稳定性-可塑性：前向最强 ⇒ 后向最差** | 我们的 `supersedes` 是「新覆盖旧」，旧条仍可读 | ⚠ **提醒**：任何「鼓励多存新经验」的改动都要同时看 BWT（旧坑会不会因为池子稀释重新踩） |

## 八、能借的三点（都能做成机械规则）

1. **负迁移口径拆两档**：`harmfulReuse = ΔRR < 0`（基线成功子集被弄坏）、`ineffectiveReuse = ΔNL < 0`（基线失败子集没帮上/更糟）。验收表同时报两个数，**≤5% 只对 harmfulReuse 生效**；ineffectiveReuse 单列趋势。
2. **检索覆盖率（retrieval coverage）**：`被检索过的 claim / 可检索 claim`（按窗口）。覆盖率骤降 + 同质变体占比升高 ⇒ 触发**聚合或退役候选**（只标记，不自动删——本仓「原件永不删」）。
3. **恢复事实的「洞见层」**：在现有 raw 事实（命令 + 退出码 + 日期 + seq）之上，机械派生一条**类别级**陈述（例如「该文件写入前必须先读」这类坑类 id + 共享机制），用 `mechanism`/坑类 id 做检索键，raw 作证据。这样既保留原件，又能在字面不匹配时命中（对标论文的 Insight 表示）。

## 九、明确不借的三点（附理由）

1. **不借「细粒度一定更好」**：论文自己证明同质记忆下 Cond-Ind 会塌缩（−17pp）；我们的 claim 大多是同质变体，盲目拆条会更糟。
2. **不借「同任务 ablation 当跨任务证据」**：这是本仓最容易犯的错——T9 的 12 对同题只能证机制；跨局收益要另设任务对与序列。
3. **不借「用池子大小/键多样性当健康度」**：论文明确说这些**存储侧指标看不见塌缩**；我们要用**检索侧**的覆盖率与多样性。

## 十、对本项目的可执行建议（对应三个痛点）

1. **记忆退役判据（下一步 T37）**：退役候选 = `长期 0 检索` **或**（`同质变体 ≥N` 且 `检索覆盖率 < 阈值`）**或** `preconditions 已失效`（T35 已有）。退役动作**只做可见性降级**（复用 T3 指针档 / T8 冷却），**不删原件**；每次退役写一条 ledger（`claimId, 旧状态, 新状态, 理由, 时间, 证据`）。
   > 同期还有一篇**框架**（[arXiv:2608.18177](https://arxiv.org/abs/2608.18177)，Reversible Forgetting，我读了全文框架与算法）给的是**三态状态机**：`active / dormant / retired` + 滞回（`τ↓<τ↑`、连续 `L↓` 次低分才休眠、连续 `L↑` 次高分 + **阴影模式**收益 `>ε` 才唤醒）+ 退役要**策略/人审批**。它**没有实验**，但状态机形状可以照搬：休眠可唤醒、退役要审批、每次转换进 ledger。
2. **负迁移 ≤5% 怎么测**：按 §八-1 拆两档；`harmfulReuse` 用**基线成功子集**（T26/T29 里 B 臂做对的题）算，`ineffectiveReuse` 用**基线失败子集**算；同时报 **FWT/BWT**（跨局序列的前向/后向）。当前 T9 只有单一「踩坑率」，建议加这两列再发结论。
3. **恢复事实覆盖率低（2.37%）**：先做 §八-3 的**洞见层**（类别级检索键 + raw 作证据），再量覆盖率；预期收益来自「字面不匹配但同坑类」的那些 claim——这与 T12 的坑类桥同源，但作用在**恢复事实**上而不是相关性判据上。量的时候用**检索覆盖率**（池子里多少条真被取到）而不是「索引里有多少条」。
