# 难负例（hard negatives）：随机负例测不出判据的真实误判率

> **范围**：只写"**负例怎么选**"这一面 —— 随机负例 / 难负例（BM25 负例）/ 金标准负例的差别，以及本仓该怎么造难负例。
> 不重复 `80-判据校准`（先建标注集）、`56-考卷污染`（选择偏差）、`79-不相关时沉默`（什么时候该拒绝）。
> 访问日期：**2026-11-07**。

## 为什么写这篇

昨天我造标注集时，先造了 190 对**正例富集**的对（从"卡上的行"抽），
发现"误判率测不出来"后，又补了 20 对**跨 scope 的负例**。

**但那 20 对负例几乎没用**："来自另一个项目"的 claim，**一眼就不相关**，
判据在它们身上**不会犯错** ⇒ **误判率永远是 0，但那是假的**。

这篇把 **DPR 的负例分类**搬过来，说明**什么样的负例才真正考验判据**。

## 一、一手文献

### [外 1] 负例的选择"常被忽视，却可能是决定性的"
Karpukhin et al.《Dense Passage Retrieval for Open-Domain Question Answering》（DPR，EMNLP 2020）：
> "For retrieval problems, it is often the case that positive examples are available explicitly,
> while negative examples need to be selected from an extremely large pool.
> **In practice, how to select negative examples is often overlooked but could be decisive
> for learning a high-quality encoder.**"
>
> — https://arxiv.org/html/2004.04906v3 §3.2 *Positive and negative passages* （访问 2026-11-07）

### [外 2] 三种负例：**随机 / BM25 / 金标准**
同文：
> "We consider three different types of negatives:
> (1) **Random**: any random passage from the corpus;
> (2) **BM25**: top passages returned by BM25 which **don't contain the answer but match most question tokens**;
> (3) **Gold**: positive passages paired with other questions which appear in the training set."

**关键差别**：
- **Random（随机负例）**：与问题**没有重合**，**太容易** —— 判据不会犯错；
- **BM25（难负例）**：**匹配了问题的大部分 token，但不是答案** —— **表面重合、实际无关**，**这才是考验**；
- **Gold（金标准负例）**：**别的问题的正确答案**（真实但不对口）。

### [外 3] DPR 的最佳组合里**必须含 BM25 负例**
同文 §3.2：
> "Our best model uses gold passages from the same mini-batch and **one BM25 negative passage**."

⇒ **只用随机/金标准负例不够** —— 必须加入"**有表面重合但不对**"的难负例。

## 二、对照本仓：我那 20 对负例是 **Random negatives**

| 我造的负例 | 属于哪一类 | 能不能考验判据 |
|---|---|---|
| "来自**另一个 scope** 的 claim" | **Random negatives** | ❌ **太容易**：一眼就不相关，判据不会犯错 |
| "与信号**有词重合但内容无关**的 claim"（如 pair 5） | **BM25 negatives（难负例）** | ✅ **才能测出真实误判率** |

**pair 5 就是一个天然的难负例**：
- 信号：`这个网页我登录了…看下我有多少token额度`
- claim：`Error: glob search failed (exit 2): rg: /d/.../ai-coding-free…`
- `bigramRaw = 2`（**有词重合**），但**内容完全无关**。
- ⇒ **判据误判为"相关"** —— 这正是我要测的误判。

## 三、机械方法：怎么造难负例

**不要**从"别的 scope"里**随机**挑（那是 Random negatives）。

**要**从"**与信号有表面重合**"的对里挑：
```
难负例 = { (信号, claim) : bigramRaw ≥ 2（有词重合）
                            且 人工判为 **不相关** }
```

**具体做法（可复算）**：
1. 对每条信号，**先按现有判据（bigramRaw ≥ 2）召回一批 claim**（这些都有表面重合）；
2. **人工判**：哪些**其实不相关**；
3. 那些"**有重合但人工判不相关**"的对，**就是难负例**。

**判据会在它们身上犯错** —— 那才是误判率的真实来源。

## 四、一个我必须承认的错误

我昨天补的 20 对"跨 scope 负例"，**属于 Random negatives**：
- 它们与信号**没有表面重合** ⇒ 判据**本来就不会**把它们判为相关；
- 所以**误判率 = 0** 是**必然的、无信息量的**。

**如果我当时拿那 20 对去证"误判率 = 0，判据很准"，那就是自己骗自己。**

**正确的负例必须"长得像正例"** —— 有表面重合，但不是答案。

## 七、一句话

**随机负例只能证明"判据不会在显而易见的地方犯错"；难负例才能证明"判据在容易混淆的地方也不犯错"。**
