# Mem0 论文：抽取 / 巩固 / 检索 + 图记忆（2026-11-02 采集）

- 来源：[arXiv:2504.19413](https://arxiv.org/abs/2504.19413)（v1，2025-04-28）。
- [外] 三件套：**动态抽取（extract）→ 巩固（consolidate）→ 检索（retrieve）** 会话中的显著信息；
  另有**图记忆变体**（graph-based memory）用于表达会话元素之间的关系结构。
- [外] 评测（LoCoMo，六个基线类别：既有记忆增强系统 / 不同 chunk 与 k 的 RAG / 全上下文 / 开源记忆方案 /
  专有模型系统 / 专用记忆平台）：
  - 四类问题（single-hop、temporal、multi-hop、open-domain）上一致优于现有记忆系统；
  - 相较 OpenAI 的 LLM-as-a-Judge **相对提升 26%**；
  - **图记忆比基础配置再高约 2%**；
  - 相较全上下文：**p95 延迟低 91%**、**token 成本省 90%+**。
- [外] 本页只读摘要，因此不引用其具体参数/实现细节。

## 与我们逐条对照

| Mem0 | 我们 | 判断 |
|---|---|---|
| extract | 归档（R00–R03 机械抽取，禁止模型摘要） | ✅ 同构；我们更严（只从原始事件/棋谱边抽） |
| consolidate | D2 同类错误合并 + D3 跨局重复优先 + 类级章节自愈 | ✅ 同构（机械） |
| retrieve | `walk` 顺藤摸瓜（≤2 跳、带 why、预算 500） | ✅ 同构 |
| 图记忆（+2%） | topics/links/threads + same-error/same-file 边 | ✅ **我们本来就是图**；这条对我们不是"可选项"而是默认 |
| token 省 90%+ / p95 低 91% | 注入 p50 ≈2ms、tokens p50 248（预算 500） | ✅ 同量级目标 |
| 向量/embedding | **不做**（边界成文法） | 有意不同 |

## 可借鉴（本轮唯一候选）

- **「巩固」的显式化**：Mem0 把 consolidate 当作与 extract 并列的一步。我们的 consolidate 分散在
  `claim.mjs`（D2/D3）与 `ensureClassClaims`。可在 `docs/数据契约.md` 给「巩固」写一节，明确：
  输入 = 单条 claim，输出 = 类级章节（只增不改、幂等），副作用 = 无。
  **只是文档收口，不改代码。**

## 结论
Mem0 论文基本印证我们已走的路（抽取/巩固/检索/图）；它比我们多的是 embedding 与 LLM 抽取，
比我们少的是"只增不改 + 机械计数 + 十道闸"。没有需要立刻实现的新机制。
