# 负迁移的测量盲区：A1 只测了"过期"，没测"相关但反向"

> **范围**：只写"**负迁移（给了反而错）怎么测**"这一面 —— 本仓硬约束 A1 的现有口径、它没覆盖的形态、以及补上来的机械方法。
> 不重复 `80-判据校准`（阈值怎么定）、`81-难负例`（负例怎么选）、`79-不相关时沉默`（什么时候该拒绝）。
> 访问日期：**2026-11-07**。

## 为什么写这篇

本仓的硬约束是 **A1 负迁移 ≤5%**，当前读数 **0%**。

但我刚发现一种负迁移 —— **"相关但方向相反"的记忆**（用户要 A，记忆说"应该做非 A"），
**它不会被 A1 的现有判据抓住**，因为它**不是"过期"**。

⇒ **A1 的"0%"只说明"没有过期记忆被注入"，不说明"没有误导性记忆被注入"。**

## 一、本仓的既有口径（[本]）

`docs/对标-Hindsight.md`：
> **A1 负迁移 ≤5% = 硬上限**（只否决，不参与"赢"的计算）。

`docs/拷问记录.md` **S16**：
> A1 主值取**闸门后**的 **stale 率**（真正到达模型的那部分）。

⇒ **A1 的分子是"过期（stale）记忆"**。

## 二、这个口径漏掉了什么

| 负迁移的形态 | 现有 A1 能否测到 | 原因 |
|---|---|---|
| **过期记忆**（条件已变，给了会错） | ✅ 能（stale 判据） | 有 `validTo` / `preconditions` 可判 |
| **不相关记忆**（内容与信号无关） | ⚠️ 部分（`bigramRaw` 判据） | 那是"噪声"，不完全是"负迁移" |
| **相关但反向**（用户要 A，记忆说做非 A） | ❌ **测不到** | **它不过期、也内容相关** —— 现有判据对它无效 |

**pair 26 / pair 33 就是例子**：
- 用户"502 应该路由到别的供应商" vs 记忆"**不能是502**"；
- 用户"报错能不能关掉" vs 记忆"能不能让通知**更频繁**"。

**这些记忆不过期、也相关，但**照着做会错**。它们**就是负迁移**，却**不在 A1 里**。

## 三、机械测量方法（自拟，标注为自拟）

### 判据：把"方向"作为一列加进标注集
在 `evidence/label-set.json` 的每一对上加 **`polarity`**：
```
same     = claim 的建议方向与信号**一致**（用户要 A，claim 也指向 A）
opposite = claim 的建议方向与信号**相反**（用户要 A，claim 指向非 A）
unclear  = 看不出方向（纯事实陈述，没有建议）
```

### 指标：**反向记忆率**
```
反向记忆率 = 卡上 polarity = 'opposite' 的行数 / 卡上总行数
```
**这才是"给了反而错"的直接度量** —— 而 A1 的 stale 率测不到它。

### 与 A1 的关系
**不是替换 A1，而是补一轴**：
- `A1.stale`（现有）：过期记忆率；
- `A1.opposite`（**建议新增**）：**反向记忆率**。
**两个都应该 ≤5%**（硬上限的语义就是"不许误导"）。

## 四、为什么这条不能用"模型打分"做

`AGENTS.md` §2.3：**禁止模型评分参与晋升、排序、存留**。

**"方向相反"的判定必须是机械量**：
- **否定词表**（"不要/能不能关掉/别/太多"）与**促进词表**（"应该/建议/更频繁/增加/打开"）的**机械对照**；
- **`counter[]`（反例）**：方向相反的 claim 应进 `counter` 而非 `support`（本仓数据契约里**已经有这个位置**）；
- **`polarity` 标注**：人工标一次，之后可机械统计。

**判不了的就标 `unclear`**，**不许为了出数硬判**。

## 五、我必须承认的局限

- 本节的"反向记忆率"**还没有实现** —— 标注集里**还没有 `polarity` 这一列**；
- **"否定词表"是近似的**：中文的"能不能关掉"与"更频繁"只是**一种**反向形态，
  **不能覆盖所有"方向相反"**（比如"应该重写" vs "不要重写"更隐蔽）；
