# RAPTOR：递归摘要树（2026-11-02 采集）

- 来源：[arXiv:2401.18059](https://arxiv.org/abs/2401.18059)（2024-01-31）。
- [外] 做法：把文本块**递归地 embedding → 聚类 → 摘要**，自底向上建一棵"不同抽象层次"的树；
  检索时从这棵树的不同层级取信息，覆盖长文档整体语境。
- [外] 自报：多步推理类问答显著优于传统 RAG；与 GPT-4 配合，在 **QuALITY** 基准上
  绝对准确率提升 **20%**。

## 与我们对照

| RAPTOR | 我们 | 判断 |
|---|---|---|
| 多层抽象树 | 两层：claim/棋谱（层 0）→ 卷 + `headline`（层 1）；类级章节相当于"跨卷共性的层 1.5" | ✅ 同构但更浅 |
| 聚类 | 按**主题/错误类**机械聚类（`topics`/`class:*`） | ✅ 机械替代 embedding 聚类 |
| 摘要 | **不做模型摘要**；卷首行是机械拼接 | ❌ 刻意不同（边界成文法：不调模型写摘要、不从摘要再抽取） |
| embedding 检索 | 不做（token/词面 + 图） | ❌ 刻意不同 |
| 从多层取信息 | `walk` 有 depth 概念，但**没有"先取卷级再取条目"的降级路径** | ⚠ 可借鉴点 |

## 唯一候选（N4，需证据）
**卷级降级**：当某个主题命中的**条目级 claim 预算不够**（或全部被闸拦）时，改为输出该卷的
`headline`（机械拼接，已实现）作为一层"指针"，让模型知道"这一类有 N 局、去 `cli volumes` 看"。
- 性质：纯机械、零模型；不新增字段（headline 已有）。
- 风险：会占用 500 token 预算、可能挤掉真正的 claim ⇒ 必须用 **A2b 严格 + token 增量** 对照，
  任一下降就回退。
- 当前不做：A2b 84.2%、预算尚未紧张，收益无法证明。

## 结论
RAPTOR 印证"多层抽象有助于整体理解"；我们的树是**机械的两层**，且明确拒绝模型摘要。
它没有提供可立即落地且可验证的机制；「卷级降级」记为 N4 候选。
