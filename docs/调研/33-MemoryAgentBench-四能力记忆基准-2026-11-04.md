# MemoryAgentBench：把"记忆"拆成四项能力的增量多轮基准（2026-11-04 采集）

- 来源：[arXiv:2507.05257](https://arxiv.org/abs/2507.05257)（Yuanzhe Hu, Yu Wang, Julian McAuley；v1 2025-07-07，v4 2026-06-28；HTML v1/v2/v3/v4 均读过，访问日期 **2026-11-04**）。
- [外] 定位：现有基准要么上下文长度有限、要么面向"整本书问答"这类**静态长上下文**，都无法反映记忆 agent
  "**增量**累积信息"的多轮本质；本文据此提出 MemoryAgentBench。
- [外] 四项核心能力（v4 摘要原文）：**accurate retrieval / test-time learning / long-range understanding /
  selective forgetting**；作者称**没有任何现有基准同时覆盖这四项**。
- [外] **v1 与 v4 的第四项不是同一个词**：v1 的目录与正文写的是 **Conflict Resolution (CR)**
  （[v1 HTML](https://arxiv.org/html/2507.05257v1)，访问 2026-11-04），v4 摘要改写为 **Selective Forgetting (SF)**
  （[v4 摘要](https://arxiv.org/abs/2507.05257v4)，访问 2026-11-04）。判据仍是同一类题：面对矛盾证据时
  **修订 / 覆盖 / 删除**旧信息。
- [外] v1 对 CR 的定义（正文原句）：记忆需要"revise, overwrite, or remove previously stored information when
  faced with contradictory evidence"；并明确指出它与 AR 的张力——"AR requires preservation, while CR requires
  overwriting prior facts"。
- [外] 两个新数据集（其余为改造既有长上下文数据）：**EventQA**（AR，自动流水线从叙事文本生成，避免人工标注）
  与 **FactConsolidation**（CR/SF，用 MQUAKE 反事实编辑对构造 **Single-Hop / Multi-Hop** 两版；
  提示里明确让 agent **优先采用后出现的信息**；三档上下文长度 32K / 64K / 262K）。
- [外] 规模（v1 Table 1）：AR 含 RULER-QA（200 题 / 309k 上下文）、RULER-NIAH-MQ（100 / 448k）、
  ∞Bench-QA（100 / 183k）、LongMemEval(S\*)（300 / 355k）、EventQA（500 / 534k）；
  TTL 含 BANKING-77、CLINC-150、NLU、TREC-Coarse/Fine 五个分类集（各 100 题，约 103k）与 Movie-Rec
  （Redial，200 / **1.44M**）；LRU 含 ∞Bench-Sum（100 / 172k）与 DetectiveQA（100 / 235k）；
  CR 含 FactConsolidation-SH（100 / 262k）与 -MH（100）。
- [外] 被测对象分三类：**Long-Context Agents**、**RAG Agents**、**Agentic Memory Agents**；
  未指定基座时，RAG 与商业记忆 agent 统一用 GPT-4o-mini 做基座。
- [外] 结论（v4 摘要）：现有方法**没有一种同时掌握四项能力**。
- [外] 数字样例（v2 Table 2 首行 GPT-4o 长上下文基线，**该次抓取在表尾被截断，只读到前几列**）：
  AR 的 SH-QA 72.0 / MH-QA 51.0 / LME(S\*) 32.0 / EventQA 77.2；TTL 的 MCC 87.6 / **Recommendation 12.3**；
  LRU 的 Summ. 32.2 / DetQA 77.5（[v2 HTML](https://arxiv.org/html/2507.05257v2)，访问 2026-11-04）。
  → 可读出的信号：**"会检索"不代表"会从示例/推荐流里现学"**，TTL 的推荐子项是最低的一列。

## 对照本仓（棋院）

| MemoryAgentBench | 棋院 | 判断 |
|---|---|---|
| 四能力里 AR（准确检索）与 LRU（长程理解） | 我们做的是**跨会话**的事后检索 + 藤上两跳，机械、可复算 | ✅ 同向；我们的差距在"长程"被拆成"索引 + 跳转"而非长上下文 |
| **SF/CR：写时修订、覆盖、删除** | **只增不改**：新 claim + `supersededBy` + `validTo`，旧条原样保留 | ⚠ **口径不同**：我们在**读时**做覆盖（旧条遮蔽、新条可见），不在**写时**改原件 |
| FactConsolidation（反事实编辑对，后出现者优先） | 注入按 `occurredAt` 判新旧；反例走 `counter` 计数 | ✅ 精神一致：后来的事实压过前面的事实——但我们保留前面那条作为证据 |
| "没有一种方法四项全掌握" | 产品定调是先做对失败教训，不追求全能记忆 | ✅ 支持收敛，不必为评测分数扩能力面 |
| 1.44M tokens 的长上下文 stuffing | 不做：注入 ≤K 条、每步 ≤500 token | ✅ 明确不借（那是压缩/上下文的活，不是记忆的活） |

**能借鉴的两点**：

1. **评测分桶**：把冻结卷按 AR / 冲突型（SF）分开算，才看得出"只增不改"在问答上的**真实代价**；
   现在我们的分数是混在一起的，等于把两种能力搅成一锅，出问题也定位不到。
2. **矛盾对可以纯机械构造**：他们用 MQUAKE 反事实编辑成对造题；我们同样可以机械造"同一 claim、
   两条 `occurredAt` 相反"的注入用例，断言渲染给出的是后发生的那条、且旧条仍能以指针形式溯源。

**明确不借的三点（附理由）**：

1. **写时覆盖 / 删除旧记忆**：与「只增不改、原件永不删」直接冲突，且会当场打掉可回溯性——
   SF 分数可能变好，但"当时是怎么想的"就再也答不出来；这属于拿审计能力换分数。
2. **把 TTL 当记忆层能力**：从示例里现学标签/偏好属于**模型侧**能力（工作记忆 / 提示工程），
   不属记忆生命周期；硬塞进来只会让边界模糊。
3. **把长上下文吃满当解法**：1.44M 上下文的成本与我们的"按需注入、未命中就沉默"相反。

## 两条可复用结论

1. **"记忆"不是一个分数**：AR / TTL / LRU / SF 四项在同一系统上此消彼长（论文自己的结论是无人全掌握），
   所以任何"我的记忆更强"的宣称，必须先说清**考的是哪一项**——这与我们"指标口径写清分子/分母"的纪律同源。
2. **能力冲突要在设计时说清解法**：他们用"覆盖旧记忆"解决冲突；我们用"读时遮蔽 + 原件保留"。
   两者都能让最新事实胜出，区别只在**是否可回放**——这正是我们要在审计里守住的那条线。

## 结论

无新机制可落地（其核心卖点是"能改写"，与只增不改冲突）；但它是目前最完整的**四能力评测骨架**，
对我们有两处直接用途：**把冻结卷分桶重算**，以及**用机械方式造 SF 类矛盾对**来量化"不写时覆盖"的代价。
它同时反证了一件事：**冲突处理是记忆系统的必答题**——只是我们的答案写在校验与遮蔽层，不在写入层。
