# 同一输入必须同一输出：幂等与可复现（2026-11-06 采集）

- 来源：两份一手文档（均已读全文，访问日期 **2026-11-06**）：
  [Apache Flink 2.3 · Stateful Stream Processing](https://nightlies.apache.org/flink/flink-docs-stable/docs/concepts/stateful-stream-processing/)、
  [reproducible-builds.org](https://reproducible-builds.org/)。
- **范围声明**：48 篇讲派生数据成本、57 篇讲校验三层次、60 篇讲时间戳语义、63 篇讲子代理归并；
  本篇只写**"同一输入必须同一输出"**——幂等的可验证形式、不幂等的来源、以及重放的前提。四篇不重复页面。

## 一、可复现的定义：连"顺序"与"当前时间"都要管

- [外] **定义**："**Reproducible builds** are a set of software development practices that create an
  **independently-verifiable path from source to binary code**." ⇒ 关键词是 **independently**（别人也能复算）。
- [外] **第一步：让系统完全确定**——"transforming a given source must **always create the same result**.
  For example, **the current date and time must not be recorded** and **output always has to be written in the same
  order**." ⇒ **这两句正好点名了我们最常见的两个不幂等来源**（`Date.now()` 与遍历顺序）。
- [外] **第二步：环境要么记录、要么预定义**——"the **build environment** should either be **recorded or
  pre-defined**"；第三步是"give users a way to **recreate** … and **validate** that the output matches the original".
- [外] **为什么值得**："provide certainty that software is **genuine** and has **not been tampered with**"；
  "**detect unauthorized changes** … early" ⇒ 幂等不只是"省事"，它是**篡改检测的前提**。

## 二、重放的前提：源必须能回卷

- [外] **容错 = 重放 + 快照**："Flink implements fault tolerance using a combination of **stream replay** and
  **checkpointing**"；"resumed from a checkpoint while maintaining consistency **_(exactly-once processing
  semantics)_** by restoring the state of the operators and **replaying the records** from the point of the checkpoint."
- [外] **前提写得很硬**："For this mechanism to realize its full guarantees, the data stream source … **needs to be
  able to rewind the stream to a defined recent point**."（Kafka 有这个能力。）
  ⇒ **没有可回卷的源，就没有 exactly-once**——"重放两次同结果"这句话**首先要求"能重放"**。
- [外] **checkpoint 间隔是权衡**："The checkpoint interval is a means of **trading off the overhead of fault
  tolerance** … with the **recovery time**（the number of records that need to be replayed）."
- [外] **重启不污染旧状态**："Any records that are processed as part of the restarted parallel dataflow are
  guaranteed to **not have affected the previously checkpointed state**." ⇒ 重放必须**幂等**，否则重放会二次写入。

## 三、"不幂等"的六种来源（对得上文档的原话）

| # | 来源 | 症状 | 文档依据 |
|---|---|---|---|
| **1 用当前时间** | 记录 `Date.now()` / `createdAt` | 两次输出差一个时间戳 | "**the current date and time must not be recorded**" |
| **2 遍历顺序不定** | `Object.keys`/目录遍历/`Set` 迭代 | 字段顺序变、diff 全红 | "**output always has to be written in the same order**" |
| **3 并发/异步完成顺序** | `Promise.all` 后按完成序写 | 偶发乱序 | 同上（顺序即确定性） |
| **4 依赖外部状态** | 读全局配置、环境变量、系统时间、网络 | 换机器就不同 | "**build environment** … recorded or pre-defined" |
| **5 去重键选错** | 用路径/时间当身份 | 换个目录就重复插入 | 63 篇：键应是 `(parent, sub, seq)` |
| **6 浮点/随机** | `Math.random()`、`toFixed` 边界 | 偶发 1 位差异 | 确定性要求（"same result"）|

**共同的解**：把**时间、顺序、环境、身份**四样显式化——时间来自**事件**（60 篇）、顺序来自**显式排序键**、
环境写进**契约**、身份用**可复算的键**。

## 四、"幂等"怎么机械验证（四步）

| 步 | 动作 | 判定 |
|---|---|---|
| **I1 双跑** | 同一输入跑两次，**逐字节比较**输出（不只比语义） | 不同 ⇒ 不幂等 |
| **I2 重放** | 在已有结果上**再跑一次**（增量/全量），比较 | 有新增/变动 ⇒ 不幂等 |
| **I3 换环境** | 换一个 `TZ`、换一次目录、换个 `cwd` 再跑 | 变了 ⇒ 依赖环境 |
| **I4 崩溃点** | 在写盘中途 `kill`，重启后重跑 | 出现重复条目 ⇒ 缺幂等键 |

**"逐字节相同"而不是"语义相同"**：reproducible-builds 要的是 hash 相同；
语义相同会放过"字段顺序变了"这类问题，而字段顺序**会改变 diff 与 hash**（002 篇的教训：manifest 只认 sha256）。

## 五、对照本仓（棋院）

- **§2.3 的"append-only + 帧校验 + 幂等（重放两次同结果）"**与 Flink 的"replay + checkpoint"是同一件事；
  **陷阱 15**（活跃会话不幂等属预期）正是 Flink 那条"源必须能回卷到**一个确定的点**"——
  活跃会话的"点"还在动，所以它的不幂等是**定义使然**，不是缺陷。
- **T293/T294 的归并按 `(subEpisode, seq)` 去重，第二次 0 变更** ⇒ 满足 I2；**T300 的"连续 N 次同结果"** ⇒ 满足 I1 的弱化版。
- **本仓真实的六个风险点**：① `recordedAt = Date.now()`（**必然**不幂等，除非只当"入馆时间"且不参与比较）；
  ② 目录遍历顺序（`fs.readdirSync` 未排序）；③ `Map`/`Set` 迭代顺序；④ 依赖 `$DSH_HOME` 与系统时区；
  ⑤ 去重键曾用**路径字符串**（63 篇已修）；⑥ 日志/报告的 `generatedAt` 时间戳。
- **建议的机械检查**：`scripts/idempotent-check.mjs`——同一 store 跑两次 `archive`，**比 manifest 的 sha256 全表**；
  再 `TZ=UTC` 跑一次对比。任一不同即红（与 T300 的"可复算"合并成一条门）。

## 结论

判据三句话：**确定性要把"时间/顺序/环境/身份"四样都显式化**（reproducible-builds：日期不记录、顺序固定、环境记录）；
**幂等要逐字节验证**（I1 双跑 + I2 重放 + I3 换环境 + I4 崩溃点）；
**重放的前提是"源能回卷到确定的点"**（Flink），否则 exactly-once 只是口号。
最后一句：**幂等不是性能优化，它是"篡改检测"与"可审计"的前提**——两次跑出不同结果，就没人能证明哪次是对的。
