# 记忆的职责边界：棋院只做记忆，不越权

> 2026-11-02 · 与压缩仓的 `docs/压缩的职责边界.md` 同构：判据、红线、审计、接口。
> **改代码前先读它；新增任何注入内容 / 任何写入记忆的动作前，先过第 1 节判据。**
> 父级原则（主人原话，2026-11-01）：「分清楚哪些是压缩 compact 的任务，哪些不是，不要把 AGENTS、tools、系统提示词等其他地方涵盖的功能越权覆盖。只做好本职工作，把本职工作做到最好。」
> 本项目把这句原则平移：**记忆系统只做记忆，不接管压缩、工具、系统提示词、AGENTS、上下文工程。**

---

## 1 一句话判据

> **一段内容属于「记忆」，当且仅当它同时满足两条：**
> **① 它不产自本次会话**——产自其它会话的历史，或多会话共同支撑的结论；
> **② 它只在记忆生命周期里出现**——写入记忆 / 检索记忆 / 呈现记忆产物；不常驻、不解释世界、不教模型行动。

两条都满足才算本职；缺一条就等于替别的机制干活。

### 1.1 与压缩判据的镜像关系

| | 压缩（GOkifu-compact） | 记忆（本项目） |
|---|---|---|
| 判据 ① | 产自**本次**会话的历史 | **不**产自本次会话的历史 |
| 判据 ② | 只在**压缩**生命周期出现 | 只在**记忆**生命周期出现 |
| 典型产物 | 棋谱摘要、热清单 | episode 节点、claim、记忆卡 |
| 共享的底线 | 只陈述事实；不写"下一步"；不写许可 | 同左 |

两条判据互为补集：**同一段内容不可能同时属于压缩和记忆**。若某内容两边都想要，说明它其实产自本会话 → 归压缩，记忆只读它、不复制它。

## 2 职责清单（按机制分，越权 = 红线）

### ✅ 属于记忆（棋院的本职）

| 职责 | 具体内容 | 落点（规划） |
|---|---|---|
| **入档** | 会话结束 → episode 节点：闭包、L0/L1、信号计数、**双时间戳**（`occurredAt`/`recordedAt`） | `src/rooms/archive.mjs`（M2） |
| **建边** | 局与局的关系：same-scope / corroborates / contradicts / derives | `src/rooms/meta-graph.mjs`（M2） |
| **抽取** | 从**原始事件/棋谱边**机械抽取失败、约束、成功路径（不抽摘要） | `src/rooms/extract.mjs`（M2） |
| **晋升与失效** | 支撑门槛、反例状态机、validity 检查、superseded 标注 | `src/rooms/promote.mjs`（M2/M4） |
| **定式（joseki）** | 从多局提炼/更新定式，每招指回源头 | `src/rooms/joseki.mjs`（M2/M4，待 Q5） |
| **建网（相关边）** | 从棋谱/节点机械抽取主题，建多粒度相关边（节点↔主题、棋谱↔棋谱、节点↔节点）；每条边带 `why` | `src/rooms/topics.mjs` + `links.mjs`（M2，待 Q4） |
| **成线（线索/棋书）** | 沿主题把棋谱聚成可读线索（多对多、可合卷）；删卷不删谱 | `src/rooms/thread.mjs`（M2） |
| **建馆（棋书馆）** | 关系网 + 索引（`index.md` 树）：只组织与索引，不生成内容；索引可重算 | `src/rooms/library.mjs`（M2） |
| **跳转（顺藤摸瓜）** | 命中主题才跳；深度 ≤2；只给指针+证据路径；不命中零注入 | `src/rooms/walk.mjs`（M3） |
| **疑难裁决（多成员）** | 机械判不了的（边界晋升/强反例/更新提议）派 N 个独立成员各判一次，机械聚合成 `adjudication`；判不了保持 disputed | `src/rooms/adjudicate.mjs`（M4） |
| **折叠** | 配额触发合卷；闭包取并集；L0 派生；卷是视图不删谱 | `src/rooms/meta-fold.mjs`（M4） |
| **呈现** | 记忆卡（≤500 tokens）、记忆树（index/claims/episodes） | `src/rooms/render.mjs` + `hot-inject` 对等物（M3） |
| **可回溯** | 每条记忆 → episode → seq → 原件；记忆树文件 | 全链路 |
| **可观测** | 注入量、命中、错误率、overfitGap、stale 数 | `scripts/doctor.mjs`（M3+） |
| **成本** | 注入预算、写入模型调用次数 | 同上 |

### ❌ 不属于记忆（碰了就是越权）

| 机制 | 它负责什么 | 记忆绝不能做的事（反例） |
|---|---|---|
| **压缩（GOkifu-compact）** | 本会话历史降维、热清单、fold、重注入 | 不许压缩、不许改写压缩产物、不许把本会话历史当记忆源、不许接管 `agent/pre-step` 的压缩替换、不许改 `graph.json` |
| **AGENTS.md / 硬规则** | 用户与项目的恒定行为规则 | 不许把"你应当先备份"这类规则存成记忆条目、不许因"模型可能忘"而复述规则、不许在记忆卡里写"先做 X 再做 Y" |
| **persona / 系统提示词** | 身份、语气、能力边界 | 不许改 persona、不许在 system 段追加"记忆提示"、不许教模型"何时该查记忆/何时该 restore" |
| **tools 定义与治理** | schema、权限、approval、sandbox | 不许新增记忆检索工具、不许改工具描述/参数、不许做 `permission: allow|ask|deny` |
| **上下文工程** | 本次请求选哪些上下文 | 不许决定"该读哪个文件"、不许裁工具结果、不许改消息组织 |
| **提示压缩** | 推理前压输入文本 | 不许混入记忆 |
| **UI / 展示** | 设置页、图表、记忆浏览页 | 展示逻辑不进读/写路径；页面只读记忆产物 |
| **参数层 / 激活层** | 权重与 KV 中间态 | 不做 |

### ⚠ 灰色地带与裁决

| 场景 | 裁决 | 理由 |
|---|---|---|
| 每步注入记忆卡 | ✅ 属于记忆 | 记忆产物的可见性；**前提是内容全部来自其它会话 + 事实陈述**，掺入通用建议即越界 |
| 注入里给"记忆树路径" | ✅ 属于记忆 | 可寻址性的事实（"这些文件存在"），不是行为指导 |
| 注入里写"相关时请 read 记忆树" | ❌ 越界 | 祈使句 = 行为指导 → AGENTS/persona。合法形态：「记忆树在 X（未列出≠不存在）」 |
| 生成 claim 时让模型做同义归并 | ✅ 属于记忆（受限） | 只要不新增事实、不合并不同证据的意思、quote 与 seq 可校验 |
| 让模型判断"两条记忆是否矛盾" | ⚠ 高风险，v0 禁止 | 矛盾判定会滑向"模型猜重要性"；v0 只做机械判据（同 scope + 同 subject + 文本互斥规则），判不了的记 disputed 并留两边证据 |
| 记忆树用普通文件而非新工具 | ✅ 属于记忆 | 复用宿主 `read/grep`；不接管工具层 |
| 记忆里存"用户在 repo X 的偏好" | ✅ 属于记忆 | 但 scopeKey 必须绑定；跨域注入即 F2 |
| 记忆里存"这个工具怎么用" | ❌ 越界 | 程序性知识归工具定义/系统提示词；记忆只记"这次/历次发生了什么" |
| 从压缩摘要里再抽取记忆 | ❌ 越界 + 有害 | 自证污染（F5）：摘要已是模型生成物，二次抽取误差累积（ρ^k） |
| 直接读外部文档/抓网页/扫仓库入馆 | ❌ 违反"唯一入口 = 棋谱"（Q6） | 外部内容必须由 agent 在会话里读过、落进棋谱后才能入馆；否则它就是 RAG，不是记忆 |
| 给记忆条目补"入档时间"当发生时间 | ❌ 时序混淆（F10） | 新旧按 `occurredAt` 判；`recordedAt` 只用于审计"我们何时知道" |
| 用模型判断"某条成功定式适不适用于当前局面" | ❌ v0 禁止（待 Q8 细化判据） | 会把 F7 定式滥用变成不可复现的模型猜测；合法形态是 `preconditions` 机械核（文件/命令/工具/作用域/相位），核不过就只给指针不给做法 |
| 把"成功路径片段（`kind=pattern`）"写进记忆 | ✅ 属于记忆 | 但必须带 `preconditions` 与 support 引文；没有适用条件的成功经验 = 过拟合种子 |
| 定式（joseki）：多源公认的最佳序列 + 每招溯源 | ✅ 属于记忆 | 必须 ≥2 局独立支撑、无反例、preconditions 可核；更新用 version+supersedes，不删旧版 |
| 定式体检：比对对手会话与定式，产出"第 k 步偏离 + 源头指针" | ✅ 属于记忆（只给事实） | **不产出"该打哪里/该换供应商"的行动指令**——那是 AGENTS/persona 的职责 |
| 多成员独立解析（疑难裁决） | ✅ 属于记忆（内部裁决机制） | 成员只交结构化票 + 证据；**不得直接写记忆**；不得让成员互看输出；不得变成"裁判模型"拍板 |
| 人指出错误 → 纠错反思 | ✅ 属于记忆（最高优先级证据） | 只记 counter/修正/失效；**不搞常规人工审批**；不因纠错而改写原文 |

### 2.1 为什么这不算"越压缩的红线"（必须显式声明）

压缩仓的 `docs/压缩的职责边界.md` §2 写着压缩"不许把本次棋谱写进跨会话库、不许做从历史会话检索"——**那是压缩不做记忆，不是记忆不许存在**。

它的文档自己写明了复活条件：`docs/架构-房间契约.md`（已否决方案 #10）"per-session 状态换成全局索引"的复活条件 = **需要跨会话统计**（如全局失败边排行）；同表 #1 拆多包的复活条件 = **第三方要单独复用 R00/R06**。本项目同时命中这两条 ⇒ 属"按上游既有判据条件已成立"的新机制。**声明位置**：本文件 + `方案.md` §3.4。

## 3 与兄弟机制的接口（只读，不改写）

| 来源 | 记忆怎么用它 | 绝不能做 |
|---|---|---|
| 压缩的 `graph.json`（基线 + delta） | episode 的主要来源：节点/边/失败边/约束/foldMarks | 改它、修它、依赖它的内部实现细节（格式变了就降级为只读日志模式） |
| 会话日志（`session.v4.jsonl.zstd`） | 原件来源：原始事件、seq、cwd、delegationDepth；**多帧 zstd** | 写它、追加自定义事件（fail-closed） |
| AGENTS / 系统提示词 | 识别"哪些是恒定规则"从而**不**存成记忆（防重复） | 复述、改写、扩展规则 |
| 工具调用记录 | 证据来源：工具/参数/结果/错误原文 | 改工具 schema、裁结果 |
| 用户消息 | 偏好的证据来源（逐字） | 改写用户原话 |
| 宿主 `agent/pre-step` | 注入点（与压缩并列、各自标记） | 抢压缩的替换点、改压缩注入的消息 |
| 宿主 `agent/status` / `turn-stopping` | 入档时机 | 阻塞回合、在 append 广播里 append |

## 4 边界自检（写任何记忆行为前，五问；有一条答不上就不要写）

1. **它产自其它会话（或跨会话共同支撑）吗？** 否 ⇒ 不是记忆（本会话历史 → 压缩）。
2. **它只在记忆生命周期里出现吗？** 常驻规则/身份/工具契约/上下文选择 ⇒ 越界。
3. **它改变了模型"该做什么"吗？** 是 ⇒ 属于 AGENTS/persona（记忆只给事实）。
4. **它改了工具契约或权限吗？** 是 ⇒ 越权。
5. **它有 provenance（episode + seq/节点/边）吗？** 否 ⇒ 不许入档、不许注入。

## 5 机器审计（M3 起可执行；先写契约再写脚本）

仿压缩仓 `scripts/boundary-audit.mjs`：只扫**模型可见字符串字面量**（先剥注释），命中即 error：

| 类别 | 模式（示例） | 判定 |
|---|---|---|
| **行为指导** | `下一步：` / `你应该` / `不要重试` / `you should` / `please read` | error |
| **行动许可** | `you may` / `continue or abandon` / `可以继续` | error |
| **工具治理** | `permission: allow|ask|deny` / `approval:` / `sandbox_permissions` | error |
| **系统提示词痕迹** | `system prompt` / `persona` / `You are `（在注入模板里） | error |
| **规则复述** | 记忆卡里出现 AGENTS 原文片段（跨文件比对） | error |
| **无源条目** | 渲染行缺 `(ep-…, seq …)` | error（provenance 覆盖率 ≠1） |
| **摘要再抽取** | 抽取器读取 `<compacted-summary>` / `<chess-fold>` / 摘要文本作为输入 | error |

**唯一豁免**：抽取提示里"只许做同义归并、不许新增事实"这类**喂给抽取模型的指令**（不注入主 agent），豁免必须写在脚本 `ALLOW` 里并注明理由。

**复审触发条件**（不是定期，是有事才审）：
- 任何新增注入到模型上下文的文本；
- 任何"为了让模型更好理解"而改写的措辞；
- 任何来自 doctor / 验收清单的提示语被搬进记忆卡的时候；
- 任何新增 claim 字段（新字段可能改变语义）。

## 6 与调研的关系

`docs/` 与本项目相关的调研（压缩仓 `docs/research/`）只用来回答一个问题：
> **同样的历史，怎样在跨会话时被安全地复用、又怎样被证伪。**

凡调研结论指向"让模型判断/打分/自编辑/时间衰减/向量召回"，一律不采纳（无论产品多火）；凡指向"更可核、更可回溯、更省、更可失效"，才进入候选。筛选与理由见 `方案.md` §10 与 `docs/调研/01-记忆系统调研简报.md` §8。
