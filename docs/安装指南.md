# 棋院（dsh-kifuin）安装指南

> **状态**：插件入口已实现（`src/plugin.mjs`），**默认关闭**（`enabled:false, shadow:true`）。
> **安装只能由主人执行**：运行中不改 `profiles/*/cordis.patch.yml`、不重启 DSH（本机铁律）。

## 0 · 前置检查（agent 可代跑）

```bash
node scripts/check.mjs          # 必须 PASS
node --test                     # 必须全绿
node scripts/archive.mjs        # 建库：<DSH_HOME>/memory-context（必须先有库）
node scripts/cli.mjs verify     # 必须 OK
```

库不存在时插件只 warn、不注入——**不会弄坏会话**，但也看不到效果。

## 1 · 影子模式（建议先跑 1–2 天）

在设置 UI 的插件配置里（或你惯用的 profile 配置通道）加：

```json
{
  "enabled": false,
  "shadow": true,
  "storeRoot": "<DSH_HOME>/memory-context",
  "shadowDir": "<repo>/evidence/shadow",
  "budgetTokens": 500,
  "limit": 5,
  "oncePerSession": true
}
```

- `shadow:true` ⇒ **永远返回原 decision**，只把"本来会注入什么"追加到 `evidence/shadow/shadow.jsonl`（每行 `injected:false`）。
- `shadowDir` 不允许落在 `$DSH_HOME` 内（硬守卫，拒绝时 0 字节写入）。

**验证影子在工作**：

```bash
tail -n 3 evidence/shadow/shadow.jsonl     # 每行应是完整 JSON，injected:false
```

## 2 · 看影子数据（agent 可代跑）

```bash
node scripts/eval.mjs --h1 --store "<DSH_HOME>/memory-context" --workspace . --evidence evidence/M5-h1.md
node scripts/m5-report.mjs --store "<DSH_HOME>/memory-context" --workspace . --evidence evidence/M5-six-axis.md
```

看三件事：命中率（多少会话本来会注入）、token（p50/p95）、以及 A1/A6 是否达标。

## 3 · 真注入（只在影子数据达标后）

```json
{ "enabled": true, "shadow": false, "...": "其余同上" }
```

- 行为：**每会话首轮**注入一次；卡片 = 固定一行 INDEX（~35 tokens）+ 命中时展开（≤5 条、≤500 tokens）。
- 任何异常（库缺失/构建抛错/闸门不过/消息造不出）⇒ `ctx.logger.warn` + **原 decision**，不阻塞会话。
- 不写会话事件、不改会话日志；注入内容不进日志（只能从影子台账复盘）。

**启用后第一件事**：开一个新会话，确认 messages 顺序（与压缩插件同点注入，两边都在"最后一条 claimed 之后"插入）。

## 4 · 回滚

把 `enabled` 改回 `false` 即可（无需重启也能生效的配置通道按你的设置 UI 来；需要重启的改动按铁律由你执行）。

## 5 · 已知限制（不要当故障）

| 现象 | 原因 |
|---|---|
| 大部分会话零注入 | 语料属于别的工作区/主题不命中——**沉默是默认**（S9/S8） |
| 有命中但卡里只有指针 | claim 原文未通过闸 5（quote/seq）或闸 3（validity） |
| 定式永远 0 | 真实命令签名跨局不重复（`evidence/M5-joseki.md`，Q17 待裁定） |
| 影子文件里 `injected:false` | 影子模式定义如此 |
