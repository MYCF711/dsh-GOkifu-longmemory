# Latent Toggles · 默认关功能的清单与重开条件审计

> 依据：知识库 85（Feature Toggles）—— **toggle 有持有成本，每个"默认关"的功能都必须写清重开条件，否则变成没人敢删的库存。**
> 本文件是**唯一权威的 latent code 清单**：每加一个默认关的功能，必须在这里登记。
> 最近更新：2026-11-07

## 用法

- **加**一个默认关的功能 ⇒ 在这里加一行（开关名 / 位置 / 为什么关 / 重开条件 / 复核日期）；
- **复核** ⇒ 每轮巡检看一眼"重开条件是否已满足"；**满足就打开并删除该行**；
- **永远不满足 ⇒ 删掉那段代码**（latent code 不是资产，是**库存成本**）。

## 复核结论（2026-11-07）

**三个开关的重开条件目前都未满足。**

- `messageSignals`：最近一次复算仍是**净亏** ⇒ **保持关**；
- `abstainIrrelevant`：判据校准**远未完成**（可判率 3.7%）⇒ **保持关**；
- **Q18**：配对无差异且噪声 88% ⇒ **已裁定维持关闸**（不是"待开"，是"**已否决**"）。

## 一条纪律

**"默认关"不等于"以后一定会开"。**
- `messageSignals` / `abstainIrrelevant` 是**期权**（保留代码，等证据）；
- **Q18 是"已否决"**（证据已经说"不开"）—— **它不该再被当成"待开的功能"反复提起**。

**如果某个开关的重开条件在多次复核后仍不满足，应该删掉那段代码，而不是让它一直躺着。**
（这正是知识库 85 的"toggle 是库存成本，要主动去库存"。）
